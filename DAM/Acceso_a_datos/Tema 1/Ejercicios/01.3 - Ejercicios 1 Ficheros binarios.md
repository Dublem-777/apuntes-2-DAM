## Ejercicio 1: Agenda telefónica en un fichero binario

> [!question] Enunciado
> Realiza una agenda telefónica que almacene los siguientes datos en un fichero binario. A continuación, lee el fichero y muestra el contenido por consola:
>
> - Nombre del contacto
> - Teléfono
> - Dirección
> - Código postal (número entero)
> - Fecha de nacimiento
> - Si le debo dinero (booleano)
> - Cuánto le debo (número decimal)

### Clases y métodos introducidos

- `DataOutputStream` + `FileOutputStream`: escriben cada dato con su tipo (`writeUTF`, `writeInt`, `writeBoolean`, `writeDouble`).
- `DataInputStream` + `FileInputStream`: leen los datos con los métodos `read…` equivalentes.
- `EOFException`: indica que se ha llegado al final del fichero.

> **Términos explicados:** [[01 - Ficheros#9.2 DataInputStream y DataOutputStream|`DataInputStream` y `DataOutputStream`]] · [[01 - Ficheros#9.1 FileInputStream y FileOutputStream|`FileInputStream` y `FileOutputStream`]]

> [!tip] Pista
> Los datos se leen **en el mismo orden** en que se escribieron. La fecha de nacimiento no es un tipo primitivo: se puede guardar como cadena con `writeUTF`.

#### Ejemplo simple de funcionamiento
```java
try (DataOutputStream writer = new DataOutputStream(new FileOutputStream("datos.dat"))) {
    writer.writeUTF("Ana");   // cadena: 2 bytes de longitud + sus bytes
    writer.writeInt(11201);   // 4 bytes
}
try (DataInputStream reader = new DataInputStream(new FileInputStream("datos.dat"))) {
    String name = reader.readUTF(); // mismo orden...
    int postalCode = reader.readInt(); // ...y mismo tipo
}
```

### Conceptos clave

- Un fichero binario **no guarda marcas de tipo**: solo bytes. Quien lee tiene que saber qué se escribió y en qué orden.
- Cada tipo ocupa lo suyo: `int` 4 bytes, `double` 8, `boolean` 1. `writeUTF` escribe 2 bytes con la longitud y después la cadena en UTF-8 modificado.
- `FileOutputStream` crea el fichero si no existe, pero **no crea la carpeta**: por eso se llama antes a `Files.createDirectories`.
- No hay un `-1` que marque el final: se lee en un `while (true)` hasta que salta `EOFException`.
- `EOFException` y `FileNotFoundException` son hijas de `IOException`: sus `catch` van **antes** que el de `IOException` o el código no compila.

### Código (`Contact.java`)

```java
package ficherosBinarios.ejercicio1;

// Un contacto de la agenda telefónica
public class Contact {
    private final String name;
    private final String phone;
    private final String address;
    private final int postalCode;
    private final String birthDate;   // dd/MM/yyyy: no es un tipo primitivo, se guarda como cadena
    private final boolean moneyOwed;  // si le debo dinero
    private final double amountOwed;  // cuánto le debo

    public Contact(String name, String phone, String address, int postalCode,
                   String birthDate, boolean moneyOwed, double amountOwed) {
        this.name = name;
        this.phone = phone;
        this.address = address;
        this.postalCode = postalCode;
        this.birthDate = birthDate;
        this.moneyOwed = moneyOwed;
        this.amountOwed = amountOwed;
    }

    public String getName() {
        return name;
    }

    public String getPhone() {
        return phone;
    }

    public String getAddress() {
        return address;
    }

    public int getPostalCode() {
        return postalCode;
    }

    public String getBirthDate() {
        return birthDate;
    }

    public boolean isMoneyOwed() {
        return moneyOwed;
    }

    public double getAmountOwed() {
        return amountOwed;
    }

    @Override
    public String toString() {
        return String.format("%s%n\tTeléfono: %s%n\tDirección: %s%n\tCódigo postal: %d%n"
                        + "\tFecha de nacimiento: %s%n\t¿Le debo dinero?: %s%n\tCantidad: %.2f €",
                name, phone, address, postalCode, birthDate, moneyOwed ? "Si" : "No", amountOwed);
    }
}
```

### Código (`Ejercicio1.java`)

```java
package ficherosBinarios.ejercicio1;

import java.io.*;
import java.nio.file.*;
import java.util.ArrayList;
import java.util.List;

public class Ejercicio1 {

    private final Path file = Paths.get("files", "agenda.dat");

    public void show() {
        List<Contact> contacts = generateContacts();
        write(contacts); // Escribe los contactos en el fichero binario
        read();          // Lee el fichero y muestra los contactos por consola
    }

    private List<Contact> generateContacts() {
        List<Contact> contacts = new ArrayList<>();
        contacts.add(new Contact("Ana López", "600111222", "C/ Real 12, Algeciras",
                11201, "14/03/1998", true, 25.50));
        contacts.add(new Contact("Luis Pérez", "611333444", "Av. Virgen del Carmen 3, Algeciras",
                11202, "02/11/2001", false, 0));
        contacts.add(new Contact("Marta Ruiz", "622555666", "C/ Ancha 7, La Línea",
                11300, "30/07/1995", true, 120.75));
        return contacts;
    }

    private void write(List<Contact> contacts) {
        try {
            // FileOutputStream crea el fichero, pero no la carpeta "files"
            Files.createDirectories(file.getParent());
        } catch (IOException e) {
            System.err.printf("No se pudo crear la carpeta: %s%n", e.getMessage());
            return;
        }

        try (DataOutputStream writer = new DataOutputStream(new FileOutputStream(file.toFile()))) {
            for (Contact contact : contacts) {
                // Cada dato se escribe con el método de su tipo
                writer.writeUTF(contact.getName());
                writer.writeUTF(contact.getPhone());
                writer.writeUTF(contact.getAddress());
                writer.writeInt(contact.getPostalCode());
                writer.writeUTF(contact.getBirthDate());
                writer.writeBoolean(contact.isMoneyOwed());
                writer.writeDouble(contact.getAmountOwed());
            }
        } catch (IOException e) {
            System.err.printf("Error de entrada/salida: %s%n", e.getMessage());
        }
    }

    private void read() {
        try (DataInputStream reader = new DataInputStream(new FileInputStream(file.toFile()))) {
            System.out.println("Contenido de la agenda:");
            while (true) {
                // Se lee en el mismo orden y con el mismo tipo con el que se escribió
                String name = reader.readUTF();
                String phone = reader.readUTF();
                String address = reader.readUTF();
                int postalCode = reader.readInt();
                String birthDate = reader.readUTF();
                boolean moneyOwed = reader.readBoolean();
                double amountOwed = reader.readDouble();
                System.out.println(new Contact(name, phone, address, postalCode,
                        birthDate, moneyOwed, amountOwed));
            }
        } catch (EOFException e) {
            // En un fichero binario no hay -1: el final se detecta con esta excepción
            System.out.println("Lectura del fichero finalizada");
        } catch (FileNotFoundException e) {
            System.err.printf("El fichero no existe: %s%n", e.getMessage());
        } catch (IOException e) {
            System.err.printf("Error de entrada/salida: %s%n", e.getMessage());
        }
    }

    public static void main(String[] args) {
        new Ejercicio1().show();
    }
}
```

### Explicación paso a paso

1. **`Contact` agrupa los 7 datos del enunciado.** Los atributos son `final` porque un contacto no cambia después de crearse. Los *getters* dan acceso a cada dato para escribirlo, y `toString` lo muestra con el mismo formato que los ejemplos de la teoría (`\t` para sangrar).
2. **La ruta es un atributo de la instancia** (`files/agenda.dat`), así `write` y `read` usan el mismo fichero sin tener que pasárselo.
3. **`show` reparte el trabajo** en tres pasos, como `DataBinaryFile` en la teoría: generar los contactos, escribirlos y leerlos.
4. **`write` crea primero la carpeta.** Si `files/` no existe, `FileOutputStream` lanza `FileNotFoundException`. `Files.createDirectories` no falla si la carpeta ya existe.
5. **Cada dato se escribe con el `write…` de su tipo.** `DataOutputStream` "envuelve" al `FileOutputStream`: el de fuera sabe convertir tipos a bytes y el de dentro sabe escribir bytes en el disco. El `try-with-resources` cierra los dos al terminar.
6. **`read` lee en el mismo orden**: `readUTF` ×3, `readInt`, `readUTF`, `readBoolean`, `readDouble`. Si se cambiara el orden (por ejemplo, `readInt` antes que la dirección), Java interpretaría bytes de una cadena como si fueran un número y saldrían datos absurdos o una excepción.
7. **El final se detecta con `EOFException`.** Cuando ya no quedan bytes, el siguiente `readUTF` lanza la excepción y el `catch` muestra "Lectura del fichero finalizada". Aquí la excepción no es un error: es la forma normal de saber que se ha acabado.

> [!tip] Prueba
> Ejecuta `Ejercicio1`: salen los 3 contactos y "Lectura del fichero finalizada". El fichero `files/agenda.dat` ocupa 227 bytes. Si lo abres con un editor de texto, verás los nombres mezclados con símbolos raros: son los `int`, `boolean` y `double` guardados en binario.

## Esquema comparativo de conceptos clave

| Necesidad | API utilizada | Idea principal |
| --- | --- | --- |
| Escribir datos con su tipo | `DataOutputStream` + `FileOutputStream` | Un `write…` por tipo: `writeUTF`, `writeInt`, `writeBoolean`, `writeDouble`. |
| Leer datos con su tipo | `DataInputStream` + `FileInputStream` | Los `read…` equivalentes, en el mismo orden de escritura. |
| Guardar una fecha | `writeUTF` / `readUTF` | No es primitivo: se guarda como cadena `dd/MM/yyyy`. |
| Saber cuándo acaba el fichero | `while (true)` + `catch (EOFException e)` | En binario no existe el `-1` de los ficheros de texto. |
| Evitar `FileNotFoundException` al escribir | `Files.createDirectories` | `FileOutputStream` crea el fichero, pero no la carpeta. |
