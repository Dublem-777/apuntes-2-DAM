## Ejercicio 1: Agenda telefónica con objetos

> [!question] Enunciado
> Realiza la agenda telefónica del [[01.3 - Ejercicios 1 Ficheros binarios|ejercicio anterior]] pero almacenando objetos en el fichero binario. Realiza el siguiente menú:
>
> 1. Consultar
> 2. Sobrescribir
> 3. Añadir
>
> En la opción 1, se lee el fichero y se muestra por consola. En la opción 2, se sobrescribe el fichero. En la opción 3, se mantienen los objetos que hubiera en el fichero y se añaden objetos nuevos.

### Clases y métodos introducidos

- `Serializable`: la clase del contacto la implementa (con `serialVersionUID`) para poder guardarse.
- `ObjectOutputStream.writeObject` y `ObjectInputStream.readObject`: escriben y leen objetos completos.
- `AppendableObjectOutputStream`: subclase que no escribe la cabecera, necesaria en la opción 3.

> **Términos explicados:** [[01 - Ficheros#9.3 ObjectInputStream y ObjectOutputStream|`ObjectInputStream`, `ObjectOutputStream` y la cabecera al añadir]]

> [!warning] Opción 3 (añadir)
> Si se abre el fichero en modo añadir (`new FileOutputStream(file, true)`) con un `ObjectOutputStream` normal, se escribe una segunda cabecera y al leer salta `StreamCorruptedException`. Si el fichero ya tiene objetos, usa `AppendableObjectOutputStream`.

#### Ejemplo simple de funcionamiento
```java
try (ObjectOutputStream writer = new ObjectOutputStream(new FileOutputStream("agenda.dat"))) {
    writer.writeObject(contact);          // el objeto entero, de una vez
}
try (ObjectInputStream reader = new ObjectInputStream(new FileInputStream("agenda.dat"))) {
    Contact read = (Contact) reader.readObject(); // devuelve Object: hay que hacer cast
}
```

### Conceptos clave

- **Serializar** es convertir un objeto en bytes. La clase tiene que implementar `Serializable`, una interfaz *de marcado* que no tiene métodos. Sus atributos también tienen que ser serializables, y `String`, `int`, `boolean` y `double` ya lo son.
- `serialVersionUID` identifica la versión de la clase. Si cambias los atributos y el número no coincide con el del fichero, la lectura falla con `InvalidClassException`.
- `ObjectOutputStream` escribe una **cabecera** al crearse y `ObjectInputStream` la espera al abrir el fichero. Tiene que haber **una sola** cabecera, al principio del fichero.
- `new FileOutputStream(file, false)` vacía el fichero (sobrescribir). Con `true`, escribe por el final (añadir).
- `readObject` puede lanzar `ClassNotFoundException` si la clase del objeto guardado no está en el programa.

### Código (`Contact.java`)

```java
package ficherosBinariosDeObjetos.ejercicio1;

import java.io.Serializable;

// Un contacto de la agenda. Serializable permite convertirlo a bytes para guardarlo
public class Contact implements Serializable {
    // Versión de la clase: si cambia su estructura, evita fallos al deserializar
    private static final long serialVersionUID = 1L;

    private final String name;
    private final String phone;
    private final String address;
    private final int postalCode;
    private final String birthDate;   // dd/MM/yyyy
    private final boolean moneyOwed;  // si le debo dinero
    private final double amountOwed;  // cuánto le debo

    public Contact(String name, String phone, String address, int postalCode,
                   String birthDate, boolean moneyOwed, double amountOwed) {
        this.name = name;
        this.phone = phone;
        this.address = address;
        this.postalCode = postalCode;
        this.birthDate = birthDate;
        this.moneyOwed = moneyOwed;
        this.amountOwed = amountOwed;
    }

    @Override
    public String toString() {
        return String.format("%s%n\tTeléfono: %s%n\tDirección: %s%n\tCódigo postal: %d%n"
                        + "\tFecha de nacimiento: %s%n\t¿Le debo dinero?: %s%n\tCantidad: %.2f €",
                name, phone, address, postalCode, birthDate, moneyOwed ? "Si" : "No", amountOwed);
    }
}
```

### Código (`AppendableObjectOutputStream.java`)

```java
package ficherosBinariosDeObjetos.ejercicio1;

import java.io.*;

// ObjectOutputStream que no escribe la cabecera: se usa para añadir objetos a un fichero que ya tiene
public class AppendableObjectOutputStream extends ObjectOutputStream {
    public AppendableObjectOutputStream(OutputStream out) throws IOException {
        super(out);
    }

    @Override
    protected void writeStreamHeader() throws IOException {
    }
}
```

### Código (`Ejercicio1.java`)

```java
package ficherosBinariosDeObjetos.ejercicio1;

import java.io.*;
import java.nio.file.*;
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class Ejercicio1 {

    private final Path file = Paths.get("files", "agendaObjetos.dat");
    private final Scanner keyboard = new Scanner(System.in);

    public void show() {
        int option;
        do {
            System.out.println("\n--- AGENDA TELEFÓNICA (objetos) ---");
            System.out.println("1. Consultar");
            System.out.println("2. Sobrescribir");
            System.out.println("3. Añadir");
            System.out.println("0. Salir");
            option = readInt("Elige una opción: ");

            switch (option) {
                case 1 -> readObjects();
                case 2 -> writeObjects(askContacts(), false);
                case 3 -> writeObjects(askContacts(), true);
                case 0 -> System.out.println("Fin del programa");
                default -> System.out.println("Opción no válida");
            }
        } while (option != 0);
    }

    // Opción 1: lee todos los objetos del fichero y los muestra
    private void readObjects() {
        Contact contact;
        try (ObjectInputStream reader = new ObjectInputStream(new FileInputStream(file.toFile()))) {
            while (true) {
                contact = (Contact) reader.readObject(); // Lee un objeto contacto del fichero
                System.out.println(contact);
            }
        } catch (EOFException e) {
            System.out.println("Lectura del fichero finalizada");
        } catch (ClassNotFoundException e) {
            System.err.printf("Clase no encontrada: %s%n", e.getMessage());
        } catch (FileNotFoundException e) {
            System.err.printf("El fichero no existe: %s%n", e.getMessage());
        } catch (IOException e) {
            System.err.printf("Error de entrada/salida: %s%n", e.getMessage());
        }
    }

    // Opción 2 (append = false) y opción 3 (append = true)
    private void writeObjects(List<Contact> contacts, boolean append) {
        try {
            Files.createDirectories(file.getParent());
            // Solo se omite la cabecera si se añade a un fichero que ya tiene contenido
            boolean hasContent = append && Files.exists(file) && Files.size(file) > 0;

            try (FileOutputStream fos = new FileOutputStream(file.toFile(), append);
                 ObjectOutputStream writer = hasContent
                         ? new AppendableObjectOutputStream(fos)
                         : new ObjectOutputStream(fos)) {
                for (Contact contact : contacts) {
                    writer.writeObject(contact); // Escribe un objeto contacto en el fichero
                }
            }
            System.out.printf("%d contacto(s) guardado(s) en %s%n", contacts.size(), file);
        } catch (IOException e) {
            System.err.printf("Error de entrada/salida: %s%n", e.getMessage());
        }
    }

    private List<Contact> askContacts() {
        List<Contact> contacts = new ArrayList<>();
        int count = readInt("¿Cuántos contactos quieres introducir?: ");
        for (int i = 1; i <= count; i++) {
            System.out.printf("Contacto %d:%n", i);
            contacts.add(askContact());
        }
        return contacts;
    }

    private Contact askContact() {
        String name = readText("\tNombre: ");
        String phone = readText("\tTeléfono: ");
        String address = readText("\tDirección: ");
        int postalCode = readInt("\tCódigo postal: ");
        String birthDate = readText("\tFecha de nacimiento (dd/MM/yyyy): ");
        boolean moneyOwed = readBoolean("\t¿Le debes dinero? (s/n): ");
        double amountOwed = moneyOwed ? readDouble("\t¿Cuánto le debes?: ") : 0;
        return new Contact(name, phone, address, postalCode, birthDate, moneyOwed, amountOwed);
    }

    // Métodos de lectura de teclado: repiten la pregunta hasta que el dato es válido

    private String readText(String prompt) {
        System.out.print(prompt);
        return keyboard.nextLine().trim();
    }

    private int readInt(String prompt) {
        while (true) {
            try {
                return Integer.parseInt(readText(prompt));
            } catch (NumberFormatException e) {
                System.out.println("Introduce un número entero válido.");
            }
        }
    }

    private double readDouble(String prompt) {
        while (true) {
            try {
                // Se admite la coma decimal (12,50) además del punto
                return Double.parseDouble(readText(prompt).replace(',', '.'));
            } catch (NumberFormatException e) {
                System.out.println("Introduce un número decimal válido.");
            }
        }
    }

    private boolean readBoolean(String prompt) {
        while (true) {
            String answer = readText(prompt).toLowerCase();
            if (answer.equals("s")) {
                return true;
            }
            if (answer.equals("n")) {
                return false;
            }
            System.out.println("Responde s o n.");
        }
    }

    public static void main(String[] args) {
        new Ejercicio1().show();
    }
}
```

### Explicación paso a paso

1. **`Contact` implementa `Serializable`.** Es lo único que hace falta para que `writeObject` sepa convertir el objeto en bytes. Aquí no necesita *getters*: el programa solo crea contactos y los muestra con `toString`.
2. **`AppendableObjectOutputStream` hereda de `ObjectOutputStream`** y sobrescribe `writeStreamHeader` con un cuerpo vacío. Así, al crearse, no escribe nada en el fichero. Es la misma clase que la de la teoría.
3. **Un solo `Scanner` como atributo.** Todos los métodos lo comparten y no se cierra: cerrarlo cerraría también `System.in` y ya no se podría leer más del teclado en todo el programa.
4. **El menú es un `do-while`**: se muestra al menos una vez y se repite hasta elegir `0`. El `switch` con `->` (Java 14+) no necesita `break`.
5. **Opción 1 (`readObjects`)**: igual que `readObjects` de la teoría. `readObject` devuelve un `Object`, así que se convierte con `(Contact)`. Se lee hasta que salta `EOFException`.
6. **Opciones 2 y 3 (`writeObjects`)**: un solo método con el parámetro `append`. Lo importante es elegir bien el flujo:

   | Opción | `FileOutputStream(…, append)` | ¿Ya tiene contenido? | Flujo que se usa | Cabeceras al final |
   | --- | --- | --- | --- | --- |
   | 2 · Sobrescribir | `false` (vacía el fichero) | da igual | `ObjectOutputStream` | 1 |
   | 3 · Añadir | `true` | no (nuevo o vacío) | `ObjectOutputStream` | 1 |
   | 3 · Añadir | `true` | sí | `AppendableObjectOutputStream` | 1 |

   Si se usara siempre el `Appendable`, un fichero nuevo quedaría **sin** cabecera y `ObjectInputStream` fallaría al abrirlo. Si no se usara nunca, cada "añadir" metería una cabecera más y saltaría `StreamCorruptedException`. Es como el título de un libro: va solo en la portada, no al principio de cada capítulo.
7. **El operador ternario dentro del `try-with-resources`** elige el flujo. Los dos recursos (`fos` y `writer`) se cierran solos al terminar, en orden inverso.
8. **`askContacts` y `askContact`** piden los datos del teclado. Si no se le debe dinero, la cantidad se guarda como `0` sin preguntar.
9. **Los `read…` de teclado usan `nextLine` y después convierten el texto.** Así se evita el problema de mezclar `nextInt` y `nextLine`: el salto de línea que se queda en el buffer y que en la teoría se limpia a mano con `keyboard.nextLine()`. Además, repiten la pregunta si el dato no es válido y aceptan la coma decimal (`12,5`).

> [!tip] Prueba
> 1. Opción **1** con el fichero sin crear → "El fichero no existe".
> 2. Opción **2** con 1 contacto (Ana) y opción **3** con otro (Luis) → la opción 1 muestra los dos.
> 3. Opción **3** otra vez (Marta) → salen los tres, sin `StreamCorruptedException`.
> 4. Opción **2** con un contacto nuevo → solo queda ese: se ha sobrescrito el fichero.

## Esquema comparativo de conceptos clave

| Necesidad | API utilizada | Idea principal |
| --- | --- | --- |
| Guardar objetos completos | `implements Serializable` + `serialVersionUID` | La clase se marca como serializable; sus atributos también deben serlo. |
| Escribir / leer un objeto | `writeObject` / `(Contact) readObject()` | Un objeto por llamada; al leer hay que hacer cast. |
| Sobrescribir el fichero | `new FileOutputStream(file, false)` + `ObjectOutputStream` | Se vacía el fichero y se escribe una cabecera nueva. |
| Añadir sin romper el fichero | `new FileOutputStream(file, true)` + `AppendableObjectOutputStream` | Solo si ya tiene contenido: así no se duplica la cabecera. |
| Leer números del teclado sin líos de buffer | `nextLine` + `Integer.parseInt` / `Double.parseDouble` | Siempre se lee la línea entera y después se convierte. |
