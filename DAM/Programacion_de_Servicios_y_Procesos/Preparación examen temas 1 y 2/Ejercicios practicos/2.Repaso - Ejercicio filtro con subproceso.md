# 2.E · Ejercicio: filtro de líneas con un subproceso

> [!info] Asignatura
> [[DAM/Programacion_de_Servicios_y_Procesos/Indice|Programación de Servicios y Procesos]] · Tema 2 · Gestión de procesos

## Enunciado

Realiza un programa filtro en Java que reciba como argumento la cadena con la que filtrar líneas. Debe mostrar por la salida estándar solo las líneas leídas desde la entrada estándar que contengan dicha cadena.

Realiza otro programa que solicite al usuario la cadena que quiere buscar, cree un subproceso que ejecute el programa de filtro y le pase una serie de líneas. Después, debe leer las líneas filtradas que devuelve el subproceso y mostrarlas por pantalla.

El filtro termina al recibir la línea `CENTINELA FIN`. El programa padre debe enviar esa línea al filtro para indicarle que ya no hay más datos.

## Solución

Se necesitan dos clases. `Filtro` procesa la entrada estándar y escribe las coincidencias en la salida estándar. `ProgramaPadre` crea el proceso, le envía los datos por su entrada estándar y recoge los resultados de su salida estándar.

### 1. Programa filtro

**`Filtro.java`**

```java
// Clases para leer/escribir texto y codificarlo en UTF-8.
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.nio.charset.StandardCharsets;

public class Filtro {
    // Texto especial que indica al filtro que ya no recibirá más líneas.
    private static final String CENTINELA = "CENTINELA FIN";

    // args contiene los argumentos recibidos al arrancar el programa.
    public static void main(String[] args) throws IOException {
        // El primer argumento debe ser la cadena que se buscará.
        if (args.length == 0) {
            System.err.println("Uso: java Filtro <cadena-a-buscar>");
            System.exit(1); // Termina con código 1: falta un argumento obligatorio.
        }

        String cadenaBuscada = args[0]; // Guarda el texto que se comparará con cada línea.

        // System.in es la entrada estándar conectada al padre. El try cierra los flujos al terminar.
        try (BufferedReader entrada = new BufferedReader(
                    new InputStreamReader(System.in, StandardCharsets.UTF_8));
             // System.out es la salida estándar que el padre leerá; true activa el vaciado automático.
             PrintWriter salida = new PrintWriter(
                    new OutputStreamWriter(System.out, StandardCharsets.UTF_8), true)) {

            String linea;
            // readLine() obtiene una línea; devuelve null si se cierra la entrada.
            while ((linea = entrada.readLine()) != null) {
                // Si llega el centinela, se termina el bucle sin filtrarlo ni mostrarlo.
                if (linea.equals(CENTINELA)) {
                    break;
                }

                // contains devuelve true si la línea incluye la cadena buscada.
                if (linea.contains(cadenaBuscada)) {
                    salida.println(linea); // Envía la coincidencia por la salida estándar al padre.
                }
            }
        }
    }
}
```

El filtro examina cada línea con `contains`. La búsqueda distingue entre mayúsculas y minúsculas. La línea centinela se comprueba antes del filtrado, por lo que nunca forma parte de los resultados.

### 2. Programa padre

**`ProgramaPadre.java`**

```java
// Clases para comunicar procesos mediante flujos de texto y construir el comando Java.
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.nio.charset.StandardCharsets;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class ProgramaPadre {
    // El padre y el filtro usan el mismo texto para señalar el final de los datos.
    private static final String CENTINELA = "CENTINELA FIN";

    // Las excepciones declaradas pueden producirse al crear, leer o esperar al subproceso.
    public static void main(String[] args)
            throws IOException, InterruptedException {
        // Scanner lee lo que escribe el usuario en la entrada estándar del padre.
        Scanner teclado = new Scanner(System.in, StandardCharsets.UTF_8);

        System.out.print("Cadena que se buscará: ");
        String cadenaBuscada = teclado.nextLine(); // Esta cadena se pasará como argumento al filtro.

        // Guardamos primero las líneas para poder enviarlas cuando el subproceso esté creado.
        List<String> lineas = new ArrayList<>();
        System.out.println("Escribe las líneas que se enviarán al filtro.");
        System.out.println("Para terminar, escribe: " + CENTINELA);

        String linea;
        // Lee líneas del usuario hasta que escriba exactamente el centinela.
        // No guardamos el centinela aquí: el padre lo enviará al filtro más adelante.
        while (!(linea = teclado.nextLine()).equals(CENTINELA)) {
            lineas.add(linea);
        }

        // Localiza el ejecutable java del mismo JDK/JRE con el que se está ejecutando este padre.
        // En Windows el archivo se llama java.exe; en otros sistemas, java.
        String ejecutableJava = Path.of(
                System.getProperty("java.home"), "bin",
                System.getProperty("os.name").toLowerCase().contains("win")
                        ? "java.exe" : "java")
                .toString();

        // Construye el comando: java -cp <classpath actual> Filtro <cadena buscada>.
        // Cada argumento es una posición separada; así la cadena puede contener espacios.
        ProcessBuilder constructor = new ProcessBuilder(
                ejecutableJava,
                "-cp", System.getProperty("java.class.path"),
                "Filtro", cadenaBuscada);
        // Los errores del filtro se muestran directamente en la consola del padre.
        constructor.redirectError(ProcessBuilder.Redirect.INHERIT);
        Process proceso = constructor.start(); // Arranca Filtro como un proceso independiente.

        // getOutputStream() del padre está conectado a la entrada estándar del subproceso.
        try (BufferedWriter entradaProceso = new BufferedWriter(
                new OutputStreamWriter(proceso.getOutputStream(), StandardCharsets.UTF_8))) {
            for (String texto : lineas) {
                entradaProceso.write(texto); // Escribe una línea de texto para que la lea Filtro.
                entradaProceso.newLine(); // Añade el salto de línea que readLine() espera.
            }

            // Envía el centinela para que el bucle de Filtro sepa que debe terminar.
            entradaProceso.write(CENTINELA);
            entradaProceso.newLine();
        } // Al cerrar este flujo, el padre indica que ya terminó de enviar datos.

        // getInputStream() del padre está conectado a la salida estándar del subproceso.
        // Leemos las respuestas después de enviar todos los datos y el centinela.
        List<String> resultados = new ArrayList<>();
        try (BufferedReader salidaProceso = new BufferedReader(
                new InputStreamReader(proceso.getInputStream(), StandardCharsets.UTF_8))) {
            String resultado;
            while ((resultado = salidaProceso.readLine()) != null) {
                resultados.add(resultado); // Guarda cada línea filtrada que envía el hijo.
            }
        }

        // waitFor() espera a que termine el proceso y devuelve su código de salida.
        int codigoSalida = proceso.waitFor();

        System.out.println("\nLíneas que contienen «" + cadenaBuscada + "»:");
        for (String resultado : resultados) {
            System.out.println(resultado); // Muestra en la consola cada coincidencia recibida.
        }

        // Por convenio, cero indica que terminó correctamente; otro valor suele indicar error.
        if (codigoSalida != 0) {
            System.err.println("El filtro terminó con el código " + codigoSalida);
        }
    }
}
```

El padre acumula las líneas introducidas, inicia el proceso `Filtro` con la cadena buscada como argumento y le envía las líneas seguidas de `CENTINELA FIN`. El cierre de `entradaProceso` indica que el padre ha acabado de escribir. Después, el padre lee la salida del filtro hasta que se cierra y espera a que el subproceso termine.

## Compilación y ejecución

Guarda ambos archivos en la misma carpeta y ejecuta desde ella:

```bash
javac Filtro.java ProgramaPadre.java
java ProgramaPadre
```

Introduce la cadena a buscar y, después, las líneas de texto. Para terminar la entrada, escribe exactamente `CENTINELA FIN`. El padre añade esa línea al flujo enviado al filtro; el filtro la reconoce y finaliza.

### Ejemplo

Si se busca `Java` y se introducen estas líneas:

```text
Me gusta Java
Aprendo Kotlin
Java permite crear aplicaciones
CENTINELA FIN
```

El padre mostrará:

```text
Líneas que contienen «Java»:
Me gusta Java
Java permite crear aplicaciones
```

## Flujo de comunicación

| Dirección | Flujo | Contenido |
|---|---|---|
| Padre → filtro | Entrada estándar del subproceso (`getOutputStream()`) | Líneas de texto y `CENTINELA FIN` |
| Filtro → padre | Salida estándar del subproceso (`getInputStream()`) | Solo las líneas que contienen la cadena buscada |
| Filtro → consola | Salida de error (heredada con `redirectError`) | Mensajes de error del subproceso |

> [!warning] No confundir los flujos
> Desde el punto de vista del padre, `getOutputStream()` permite **escribir hacia la entrada** del subproceso; `getInputStream()` permite **leer su salida**. Los nombres se entienden desde la perspectiva del proceso padre.

## Esquema resumen

- `ProcessBuilder` crea un proceso independiente y permite pasar argumentos al programa ejecutado.
- `Process.getOutputStream()` conecta el padre con la entrada estándar del subproceso.
- `Process.getInputStream()` conecta la salida estándar del subproceso con el padre.
- La cadena `CENTINELA FIN` es el protocolo acordado para indicar que ya no quedan líneas.
- Cerrar el flujo de entrada y esperar a que termine el proceso son pasos importantes para completar la comunicación.

> [!warning] Tamaño de la entrada
> Esta versión envía primero todas las líneas y luego lee los resultados, adecuada para una cantidad pequeña de datos como la del ejercicio. Si se enviase una cantidad muy grande de líneas coincidentes, el búfer de salida del sistema operativo podría llenarse y bloquear el subproceso; para ese caso habría que leer y escribir simultáneamente con técnicas de concurrencia.
