## Esperar a que termine un subproceso

`Process.waitFor()` bloquea el hilo llamador hasta que termine el proceso y devuelve su código de salida. Si el proceso ya terminó, retorna inmediatamente. Puede lanzar `InterruptedException`.

La sobrecarga `waitFor(timeout, unit)` espera hasta el límite y devuelve `true` si el proceso terminó, o `false` si sigue activo. Si terminó, `exitValue()` permite consultar el código de salida.

```java
if (proceso.waitFor(3, TimeUnit.SECONDS)) {
    int codigo = proceso.exitValue();
} else {
    // Sigue activo al vencer el plazo.
}
```

## Consultar estado sin bloquear

`isAlive()` indica si el proceso sigue ejecutándose. `exitValue()` devuelve su código una vez terminado; si aún vive, lanza `IllegalThreadStateException`.

Un bucle de consulta con pausas es una forma de espera activa y suele ser menos eficiente que `waitFor(timeout, unit)`. Evita sondear de forma continua.

## Acciones asíncronas con onExit

`Process.onExit()` devuelve un `CompletableFuture<Process>` que se completa cuando termina el proceso. Se pueden encadenar acciones sin bloquear el hilo actual o esperar explícitamente al future. Cancelar el future no termina el proceso.

## Terminación explícita

Los subprocesos suelen continuar ejecutándose aunque termine el proceso Java que los inició; no se debe asumir terminación en cascada. El padre puede solicitar su terminación con `destroy()` y forzarla con `destroyForcibly()`.

`supportsNormalTermination()` (Java 9+) indica si `destroy()` puede solicitar un cierre normal. El comportamiento depende de la plataforma. Patrón recomendado:

1. Solicitar terminación con `destroy()`.
2. Esperar un plazo razonable con `waitFor(timeout, unit)`.
3. Si sigue vivo, recurrir a `destroyForcibly()`.

Si el hilo es interrumpido durante la espera, restaura el estado de interrupción con `Thread.currentThread().interrupt()` y aplica la política de limpieza elegida.

## Drenar flujos durante la espera

Si el padre no consume `stdout` o `stderr`, los búferes limitados de las tuberías pueden llenarse y bloquear al hijo. A su vez, el padre puede quedar esperando en `waitFor()`: se forma un interbloqueo.

Lee los flujos mientras el proceso trabaja, por ejemplo con hilos dedicados o redirección a archivos. Tras destruir el proceso, un flujo puede cerrarse y lecturas posteriores pueden producir `IOException`; gestiona el cierre como parte de la limpieza.

## Esquema

- `waitFor()` espera y devuelve código de salida; la sobrecarga con timeout informa si terminó a tiempo.
- `isAlive()` consulta el estado; `exitValue()` solo es válido tras la terminación.
- `onExit()` permite reaccionar de forma asíncrona; cancelar su future no termina el proceso.
- Terminación escalonada: `destroy()`, espera limitada y `destroyForcibly()` si hace falta.
- Drena stdout/stderr para evitar bloqueo por búferes llenos.
