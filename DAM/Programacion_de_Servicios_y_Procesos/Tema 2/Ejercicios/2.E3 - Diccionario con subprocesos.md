# 2.E3 · Ejercicio: diccionario con subprocesos

> [!info] Asignatura
> [[DAM/Programacion_de_Servicios_y_Procesos/Indice|Programación de Servicios y Procesos]] · Tema 2 · Gestión de procesos

## Enunciado

> [!question] Enunciado (copiado de Moodle)
> En este ejercicio tienes que realizar dos programas complementarios:
>
> 1. Realiza un programa llamado language.jar que reciba como argumento el número de palabras "inventadas" que debe enviar a salida estándar, una palabra en cada línea. Cada palabra debe tener un número aleatorio de entre 2 y 8 caracteres, y las letras que la conforman también deben elegirse aleatoriamente de entre las letras minúsculas del idioma inglés.
> Si el programa no recibe ningún argumento o el número de palabras recibido no es mayor que 0 el programa mostrará por la salida de error un mensaje de uso correcto y retornará el valor 1. Si el programa funciona correctamente retornará el valor 0.
> 2. Crea un programa dictionary.jar, que lance 10 instancias del programa language.jar, presuponiendo que éste se encuentra en el mismo directorio del propio programa dictionary. En cada llamada al programa language se debe propocionar el número de palabras que debe generar. En la primera instancia se deberá generar 1 palabra, en la segunda 2, y así sucesivamente, hasta la última instancia en la que se debe solicitar la generación de 10 palabras. Todas las instancias de language.jar deben estar ejecutándose a la vez.
> Una vez lanzadas, el programa dictionary.jar debe mostrar un mensaje por pantalla diciendo "Generando todas las palabras para el diccionario...".
> Si alguna de las instancias de language.jar finalizara con error se deberá mostrar por pantalla la salida de error producida por dicha instancia y no realizar ninguna acción adicional. Una vez se hayan generado todas las palabras correctamente, el programa dictionary.jar debe crear una lista de cadenas con todas las palabras generadas para el diccionario. Finalmente, deberá filtrar todas las palabras del diccionario para que no haya palabras repetidas, y mostrarlas por pantalla, una palabra en cada línea.

## Solución

Son dos programas que se comunican **solo por sus flujos estándar y su código de salida**:

- `Language` (el hijo) inventa palabras y las escribe en su salida estándar.
- `Dictionary` (el padre) lanza **10 hijos a la vez**, espera a que terminen, comprueba sus códigos de salida y recoge sus palabras sin repetidas.

> [!example] Analogía
> `Dictionary` es un profesor que reparte 10 hojas a la vez: a la primera persona le pide 1 palabra, a la segunda 2... hasta 10. No espera a que uno acabe para dar la hoja al siguiente (eso es lo que significa "ejecutándose a la vez"). Cuando todos han entregado, revisa si alguien ha puesto "error" en su hoja; si nadie lo ha hecho, junta todas las palabras en un único listado sin repeticiones.

### 1. Programa hijo: `Language.java`

```java
import java.util.Random;

public class Language {
    public static void main(String[] args) {
        if (args.length != 1) {
            showUsage();
            return;
        }

        int wordCount;

        try {
            wordCount = Integer.parseInt(args[0]);
        } catch (NumberFormatException e) {
            showUsage();
            return;
        }

        if (wordCount <= 0) {
            showUsage();
            return;
        }

        Random random = new Random();

        for (int i = 0; i < wordCount; i++) {
            int wordLength = random.nextInt(7) + 2;
            StringBuilder word = new StringBuilder();

            for (int j = 0; j < wordLength; j++) {
                char letter = (char) ('a' + random.nextInt(26));
                word.append(letter);
            }

            System.out.println(word);
        }
    }

    private static void showUsage() {
        System.err.println(
                "Uso correcto: java -jar language.jar <numero-de-palabras>");
        System.exit(1);
    }
}
```

**Explicación paso a paso**

1. **Validación del argumento.** Hay tres filtros, uno detrás de otro (*cláusulas de guarda*): que llegue exactamente un argumento, que sea un número (`Integer.parseInt` lanza `NumberFormatException` si no lo es) y que sea mayor que 0. Si alguno falla, se llama a `showUsage()`.
2. **`showUsage()`** escribe el mensaje de uso en la **salida de error** (`System.err`), no en la estándar, y termina con `System.exit(1)`. Ese `1` es el **código de salida** que luego leerá el padre con `waitFor()`. Por convenio, 0 significa "todo bien" y cualquier otro valor, "error".
3. **Longitud aleatoria.** `random.nextInt(7)` devuelve un número entre 0 y 6; al sumarle 2 queda **entre 2 y 8**, justo lo que pide el enunciado.
4. **Letra aleatoria.** `'a' + random.nextInt(26)` suma a la letra `a` un desplazamiento de 0 a 25. Como un `char` es internamente un número (su código Unicode), el resultado va de `a` a `z`. El `(char)` convierte ese número de nuevo en letra.
5. **`StringBuilder`** va pegando letras sin crear un `String` nuevo en cada vuelta (ver [[Programación basica/Tema 1/1.4 Cadenas#8. La clase StringBuilder|Cadenas → 8. La clase StringBuilder]]).
6. **`System.out.println(word)`** escribe cada palabra en una línea de la salida estándar. Para el padre, esa salida es un flujo que puede leer.

> [!note] El `return` después de `showUsage()`
> `System.exit(1)` termina la JVM en el acto, así que esos `return` nunca llegan a ejecutarse. No sobran del todo: el compilador no sabe que `showUsage()` nunca vuelve, y sin el `return` del bloque `catch` se quejaría de que `wordCount` podría usarse sin inicializar.

### 2. Programa padre: `Dictionary.java`

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Set;

public class Dictionary {
    public static void main(String[] args) throws IOException, InterruptedException {
        String operatingSystem = System.getProperty("os.name").toLowerCase();
        String javaExecutableName =
                operatingSystem.startsWith("windows") ? "java.exe" : "java";

        String javaExecutable = Path.of(
                System.getProperty("java.home"),
                "bin",
                javaExecutableName
        ).toString();

        String languageJarPath =
                Path.of("language.jar").toAbsolutePath().toString();

        List<Process> processes = new ArrayList<>();

        // Start all ten instances before waiting for any of them.
        for (int wordCount = 1; wordCount <= 10; wordCount++) {
            ProcessBuilder builder = new ProcessBuilder(
                    javaExecutable,
                    "-jar",
                    languageJarPath,
                    String.valueOf(wordCount)
            );

            processes.add(builder.start());
        }

        System.out.println(
                "Generando todas las palabras para el diccionario...");

        List<Integer> exitCodes = new ArrayList<>();

        for (Process process : processes) {
            exitCodes.add(process.waitFor());
        }

        boolean errorOccurred = false;

        for (int i = 0; i < processes.size(); i++) {
            if (exitCodes.get(i) != 0) {
                errorOccurred = true;
                showError(processes.get(i));
            }
        }

        if (errorOccurred) {
            return;
        }

        Set<String> uniqueWords = getUniqueWords(processes);

        for (String word : uniqueWords) {
            System.out.println(word);
        }
    }

    private static Set<String> getUniqueWords(List<Process> processes) throws IOException {
        List<String> words = new ArrayList<>();

        for (Process process : processes) {
            try (BufferedReader output = new BufferedReader(
                    new InputStreamReader(
                            process.getInputStream(),
                            StandardCharsets.UTF_8))) {
                String word;

                while ((word = output.readLine()) != null) {
                    words.add(word);
                }
            }
        }

        Set<String> uniqueWords = new LinkedHashSet<>(words);
        return uniqueWords;
    }

    private static void showError(Process process) throws IOException {
        try (BufferedReader errorOutput = new BufferedReader(
                new InputStreamReader(
                        process.getErrorStream(),
                        StandardCharsets.UTF_8))) {
            String line;

            while ((line = errorOutput.readLine()) != null) {
                System.err.println(line);
            }
        }
    }
}
```

**Explicación paso a paso**

1. **Localizar el ejecutable `java`.** `System.getProperty("java.home")` da la carpeta de la JVM con la que se ejecuta el padre. Se le añade `bin/java` (o `bin\java.exe` en Windows). Así los hijos usan **la misma versión de Java** que el padre, aunque `java` no esté en el `PATH` (ver [[2.2 - Gestión de subprocesos#Variables de entorno y propiedades del sistema|2.2 → Variables de entorno y propiedades del sistema]]).
2. **Ruta del `language.jar`.** `Path.of("language.jar").toAbsolutePath()` la convierte en ruta absoluta **a partir del directorio de trabajo** (ver el aviso de más abajo).
3. **Lanzar los 10 hijos.** En cada vuelta se crea un `ProcessBuilder` con el comando `java -jar <ruta>/language.jar N`. Cada argumento va en su propia posición, y `String.valueOf(wordCount)` convierte el número en texto porque los argumentos de un proceso siempre son cadenas. `builder.start()` arranca el hijo **y vuelve en el acto, sin esperar a que termine**. Por eso los 10 quedan funcionando a la vez (ver [[2.2 - Gestión de subprocesos#Creación y configuración con ProcessBuilder|2.2 → ProcessBuilder]]).
4. **Mensaje.** Se muestra cuando ya están todos lanzados, tal como pide el enunciado.
5. **Esperar a todos.** `waitFor()` bloquea hasta que termina ese hijo y devuelve su código de salida. Se guardan los 10 códigos en `exitCodes`, en el mismo orden que `processes` (ver [[2.4 - Finalización de subprocesos#Esperar a que termine un subproceso|2.4 → Esperar a que termine]]).
6. **Comprobar errores.** Si algún código no es 0, se marca `errorOccurred` y `showError()` vuelca la **salida de error** de ese hijo (`getErrorStream()`) en la consola del padre. Si hubo algún error, `return` termina el programa sin hacer nada más ("no realizar ninguna acción adicional").
7. **Recoger palabras.** `getUniqueWords()` lee línea a línea la **salida estándar** de cada hijo (`getInputStream()`, porque desde el padre es una *entrada*) y las mete en una `List<String>`, que es la "lista de cadenas" del enunciado (ver [[2.3 - Flujos de comunicación#Lectura y escritura de datos|2.3 → Lectura y escritura de datos]]).
8. **Quitar repetidas.** `new LinkedHashSet<>(words)` copia la lista en un conjunto. Un `Set` no admite duplicados, y la variante `LinkedHashSet` además **mantiene el orden de inserción**, así que las palabras salen en el orden en que se generaron (ver [[Programación basica/Tema 12/Colecciones#9.2 Clase LinkedHashSet|Colecciones → 9.2 LinkedHashSet]]).
9. **Mostrar.** Un `for-each` imprime cada palabra en su línea.

> [!tip] `StandardCharsets.UTF_8`
> Al leer los flujos se indica la codificación de forma explícita. Así no depende de la configuración del sistema operativo: ver [[2.3 - Flujos de comunicación#Codificación de caracteres|2.3 → Codificación de caracteres]].

## Compilación y ejecución

`Dictionary` lanza `language.jar` con `java -jar`, así que hay que empaquetar los dos programas como JAR ejecutables. Desde la carpeta del proyecto:

```bash
javac -d out src/*.java
printf 'Main-Class: Language\n' > language.mf
printf 'Main-Class: Dictionary\n' > dictionary.mf
jar cfm language.jar language.mf -C out Language.class
jar cfm dictionary.jar dictionary.mf -C out Dictionary.class
java -jar dictionary.jar
```

En IntelliJ se puede hacer lo mismo con *File → Project Structure → Artifacts → JAR* y *Build → Build Artifacts*.

### Ejemplo

Salida real (las palabras cambian en cada ejecución). En total salen hasta **55 palabras** (1 + 2 + … + 10), menos alguna si coincidiera una repetida:

```text
Generando todas las palabras para el diccionario...
tgyr
orbfph
dizcwjyh
qyhwxacc
zczqn
kht
dsrwwm
…
```

`language.jar` por separado, sin argumento y con argumento válido:

```bash
$ java -jar language.jar
Uso correcto: java -jar language.jar <numero-de-palabras>
$ echo $?
1
$ java -jar language.jar 3
xl
mvcdy
cuabggs
$ echo $?
0
```

> [!warning] Ejecutarlo desde otra carpeta
> `Path.of("language.jar").toAbsolutePath()` busca el JAR en el **directorio de trabajo** (desde donde lanzas el comando), no en la carpeta donde está `dictionary.jar`. Si lo ejecutas desde otra carpeta (`java -jar ../dictionary.jar`), los 10 hijos fallan:
> ```text
> Generando todas las palabras para el diccionario...
> Error: Unable to access jarfile /ruta/de/trabajo/language.jar
> Error: Unable to access jarfile /ruta/de/trabajo/language.jar
> …
> ```
> Es el caso de error del enunciado: el padre muestra la salida de error de cada hijo y no hace nada más. Para que funcione siempre, lanza `dictionary.jar` desde su propia carpeta. En IntelliJ, pon esa carpeta en *Run → Edit Configurations → Working directory*.

## Flujo de comunicación

| Dirección | Flujo | Contenido |
|---|---|---|
| Padre → hijo | Argumento del comando (`ProcessBuilder`) | Número de palabras: `1`…`10` |
| Hijo → padre | Salida estándar del hijo (`getInputStream()`) | Una palabra por línea |
| Hijo → padre | Salida de error del hijo (`getErrorStream()`) | Mensaje de uso correcto, si falla |
| Hijo → padre | Código de salida (`waitFor()`) | `0` correcto · `1` error |

> [!warning] Leer después de `waitFor()`
> El padre espera a que terminen **todos** los hijos antes de leer lo que escriben. Aquí funciona porque cada hijo escribe como mucho 10 palabras cortas. Si un hijo escribiera muchísimo, llenaría el búfer del sistema operativo y se quedaría bloqueado esperando a que el padre leyera, mientras el padre sigue esperando a que el hijo termine: un **interbloqueo**. Lo explica [[2.4 - Finalización de subprocesos#Drenar flujos durante la espera|2.4 → Drenar flujos durante la espera]].

> [!note] Estilo del curso
> `getUniqueWords()`, `showError()` y `showUsage()` son métodos auxiliares `static` llamados desde `main`. El estilo del curso prefiere objetos con métodos de instancia (por ejemplo, `new Dictionary().run()` desde `main`). El código se deja tal como se entregó.

## Esquema resumen

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Lanzar un proceso | `new ProcessBuilder(cmd, args...).start()` | Arranca el hijo y vuelve sin esperar |
| Varios hijos a la vez | `start()` en un bucle y `waitFor()` en otro | Todos se ejecutan en paralelo |
| Esperar y leer el código | `int code = process.waitFor()` | Bloquea hasta que termina; `0` = correcto |
| Terminar con error | `System.exit(1)` | El padre recibe `1` en `waitFor()` |
| Leer la salida del hijo | `process.getInputStream()` | Lo que el hijo escribió con `System.out` |
| Leer los errores del hijo | `process.getErrorStream()` | Lo que el hijo escribió con `System.err` |
| Quitar duplicados con orden | `new LinkedHashSet<>(list)` | Conjunto sin repetidos, en orden de inserción |
| Mismo Java que el padre | `System.getProperty("java.home")` | Ruta de la JVM en ejecución |
