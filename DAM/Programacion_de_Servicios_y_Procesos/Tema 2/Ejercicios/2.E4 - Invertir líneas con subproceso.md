# 2.E4 · Ejercicio: invertir líneas con un subproceso

> [!info] Asignatura
> [[DAM/Programacion_de_Servicios_y_Procesos/Indice|Programación de Servicios y Procesos]] · Tema 2 · Gestión de procesos
> Ejercicio anterior: [[2.E3 - Diccionario con subprocesos]] · Enunciado original: [[2.Repaso - Valor de salida]]
> **Ruta fuente:** `/home/dublem/Documentos/Programas_clase/procesos/Ejercicio4/src/`

## Enunciado

> [!question] Enunciado (copiado de Moodle)
> Crea un programa externo (Inverter.java) lea una cadena de texto desde su stdin, después la invierta y escriba la cadena invertida en su stdout. Si recibe una cadena vacía o "EXIT", debe escribir un mensaje de error en su stderr y terminar con un código de salida 1.
> Por su parte, el programa Java principal debe lanzar el proceso Inverter.java, y después enviarle 4 cadenas de prueba al subproceso, leyendo las respuestas con las cadenas invertidas. Después enviará a Inverter.java la señal de terminación ("EXIT"). Finalmente deberá esperar a que el subproceso y después verificar que su código de salida es 1.

## Solución

Son dos programas que hablan **por turnos**:

- `Inverter` (el hijo) lee una línea de su entrada estándar, la escribe al revés en su salida estándar y espera la siguiente. Si recibe una línea vacía o `EXIT`, avisa por la salida de error y termina con código **1**.
- `Main` (el padre) lanza `Inverter`, le manda 4 cadenas **de una en una** (esperando cada respuesta), le envía `EXIT` y comprueba que el código de salida es 1.

> [!example] Analogía
> Es una conversación por walkie-talkie: el padre dice una frase y **suelta el botón** (`flush()`) para que el hijo pueda contestar. Si no lo suelta, la frase se queda en su aparato (en el búfer), el hijo nunca la oye y los dos se quedan esperando para siempre.

> [!note] Diferencia con [[2.E - Ejercicio filtro con subproceso|2.E]]
> En el filtro, el padre enviaba **todas** las líneas, cerraba el flujo y luego leía **todos** los resultados. Aquí se intercalan: escribir una → leer una → escribir otra... Por eso aquí el `flush()` es imprescindible.

### 1. Programa hijo: `Inverter.java`

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.io.PrintWriter;
import java.nio.charset.StandardCharsets;

public class Inverter {
    public static void main(String[] args) throws Exception {
        try (BufferedReader input = new BufferedReader(
                new InputStreamReader(System.in, StandardCharsets.UTF_8));
             PrintWriter output = new PrintWriter(
                     new OutputStreamWriter(System.out, StandardCharsets.UTF_8), true)) {

            String line;

            while ((line = input.readLine()) != null) {
                if (line.isEmpty() || line.equals("EXIT")) {
                    System.err.println("Error: empty input or EXIT received.");
                    System.exit(1);
                    return;
                }

                output.println(new StringBuilder(line).reverse());
            }
        }
    }
}
```

**Explicación paso a paso**

1. **Flujos con try con recursos.** `input` lee de `System.in` (lo que le manda el padre) y `output` escribe en `System.out` (lo que leerá el padre), los dos en UTF-8. El `try (...)` los cierra solos al terminar.
2. **El `true` del `PrintWriter`** activa el *autoflush*: cada `println` se envía al momento en vez de quedarse en el búfer. Sin él, el padre se quedaría esperando la respuesta en `readLine()` mientras el texto sigue retenido en el hijo: un bloqueo.
3. **Bucle de lectura.** `readLine()` devuelve la siguiente línea, o `null` cuando el padre cierra el flujo. Mientras haya líneas, se procesan.
4. **Señal de fin.** Si la línea está vacía o es `EXIT`, escribe el error en `System.err` y termina con `System.exit(1)`. Ese 1 es el código que comprobará el padre.
5. **Invertir.** `new StringBuilder(line).reverse()` le da la vuelta a la cadena. `String` no tiene un método `reverse()`, pero `StringBuilder` sí (ver [[Programación basica/Tema 1/1.4 Cadenas#8. La clase StringBuilder|Cadenas → 8. La clase StringBuilder]]).

> [!note] Detalles del hijo
> - El `return` que va después de `System.exit(1)` nunca se ejecuta, porque `exit` termina la JVM en el acto. No da problemas, simplemente sobra.
> - Por la misma razón, al salir con `System.exit` el try con recursos no llega a cerrar los flujos. Aquí da igual, porque al terminar el proceso el sistema operativo los cierra todos.
> - Si el padre cerrase el flujo **sin** mandar `EXIT`, `readLine()` devolvería `null` y el hijo acabaría normalmente con código **0**.
> - `throws Exception` es muy genérico; bastaría con `throws IOException` (ver [[Programación basica/Tema 6/Excepciones#7. Throws|Excepciones → 7. Throws]]).

### 2. Programa padre: `Main.java`

```java
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStreamWriter;
import java.nio.charset.StandardCharsets;
import java.nio.file.Path;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException, InterruptedException {
        String operatingSystem = System.getProperty("os.name").toLowerCase();
        String javaName = operatingSystem.startsWith("windows")
                ? "java.exe"
                : "java";

        String javaExecutable = Path.of(
                System.getProperty("java.home"),
                "bin",
                javaName
        ).toString();

        String inverterSource = Path.of("Inverter.java")
                .toAbsolutePath()
                .toString();

        ProcessBuilder builder = new ProcessBuilder(javaExecutable, inverterSource);
        builder.redirectError(ProcessBuilder.Redirect.INHERIT);

        Process process = builder.start();
        List<String> testStrings = List.of(
                "Hello",
                "Process Builder",
                "Java 25",
                "12345"
        );

        try (BufferedWriter processInput = new BufferedWriter(
                new OutputStreamWriter(
                        process.getOutputStream(),
                        StandardCharsets.UTF_8));
             BufferedReader processOutput = new BufferedReader(
                     new InputStreamReader(
                             process.getInputStream(),
                             StandardCharsets.UTF_8))) {

            for (String testString : testStrings) {
                processInput.write(testString);
                processInput.newLine();
                processInput.flush();

                String reversedString = processOutput.readLine();

                if (reversedString == null) {
                    throw new IOException("Inverter exited before sending a response.");
                }

                System.out.println(reversedString);
            }

            processInput.write("EXIT");
            processInput.newLine();
            processInput.flush();
        }

        int exitCode = process.waitFor();

        if (exitCode == 1) {
            System.out.println("Verified: Inverter exited with code 1.");
        } else {
            System.err.println("Expected exit code 1, got " + exitCode + ".");
            System.exit(1);
        }
    }
}
```

**Explicación paso a paso**

1. **Ejecutable `java`.** Igual que en [[2.E3 - Diccionario con subprocesos|2.E3]]: se construye la ruta a `bin/java` dentro de `java.home` para que el hijo use la misma JVM que el padre (ver [[2.2 - Gestión de subprocesos#Variables de entorno y propiedades del sistema|2.2 → Variables de entorno y propiedades del sistema]]).
2. **Modo archivo fuente.** El comando es `java /ruta/Inverter.java`, **sin compilar antes**. Desde Java 11, `java` puede recibir directamente un `.java` con una sola clase principal: lo compila en memoria y lo ejecuta. Por eso no hace falta un `Inverter.class` ni un JAR.
3. **`redirectError(INHERIT)`.** La salida de error del hijo va directamente a la consola del padre. Así, el mensaje `Error: empty input or EXIT received.` aparece en pantalla sin que el padre tenga que leerlo (ver [[2.3 - Flujos de comunicación#Redirección de los flujos|2.3 → Redirección de los flujos]]).
4. **`List.of(...)`** crea una lista inmutable con las 4 cadenas de prueba que pide el enunciado.
5. **Dos flujos a la vez.** `processInput` escribe en la **entrada** del hijo (`getOutputStream()`) y `processOutput` lee su **salida** (`getInputStream()`). Los nombres se entienden desde el punto de vista del padre (ver [[2.3 - Flujos de comunicación#Lectura y escritura de datos|2.3 → Lectura y escritura de datos]]).
6. **El bucle por turnos.** Por cada cadena: `write` + `newLine()` (el hijo usa `readLine()`, que necesita el salto de línea) + **`flush()`** para que salga del búfer **ya**. Después, `readLine()` espera la respuesta. Si llega `null`, es que el hijo murió antes de contestar y se lanza una `IOException` con un mensaje claro.
7. **Señal de fin.** Se envía `EXIT` (con su `flush()`). Al salir del `try`, se cierran los dos flujos.
8. **Verificación.** `waitFor()` espera a que el hijo termine y devuelve su código de salida (ver [[2.4 - Finalización de subprocesos#Esperar a que termine un subproceso|2.4 → Esperar a que termine]]). Si es 1, todo ha ido como pide el enunciado. Si no, el padre lo dice por `System.err` y él mismo termina con código 1, para que quien lo lance también sepa que algo falló.

## Compilación y ejecución

El padre busca `Inverter.java` **en el directorio de trabajo**, así que hay que ejecutarlo desde la carpeta `src/`:

```bash
cd src
javac Main.java
java Main
```

`Inverter.java` no se compila a mano: lo compila `java` al lanzarlo en modo archivo fuente.

### Ejemplo

Salida real:

```text
olleH
redliuB ssecorP
52 avaJ
54321
Error: empty input or EXIT received.
Verified: Inverter exited with code 1.
```

La línea `Error: …` la escribe el **hijo** por su `stderr`. Aparece en la consola gracias a `redirectError(INHERIT)`.

`Inverter` también se puede probar solo, con una tubería del shell:

```bash
$ printf 'Hola\nEXIT\n' | java Inverter.java
aloH
Error: empty input or EXIT received.
$ echo $?
1
```

> [!warning] Ejecutarlo desde IntelliJ
> IntelliJ ejecuta por defecto desde la **raíz del proyecto** (`Ejercicio4/`), no desde `src/`. Entonces `Path.of("Inverter.java")` apunta a un archivo que no existe y sale esto:
> ```text
> Error: Could not find or load main class …Inverter.java
> Exception in thread "main" java.io.IOException: Inverter exited before sending a response.
> ```
> Solución: *Run → Edit Configurations → Working directory* = `$PROJECT_DIR$/src`.

## Flujo de comunicación

| Dirección | Flujo | Contenido |
|---|---|---|
| Padre → hijo | Entrada estándar del hijo (`getOutputStream()`) | Las 4 cadenas y `EXIT`, una por línea |
| Hijo → padre | Salida estándar del hijo (`getInputStream()`) | Cada cadena invertida |
| Hijo → consola | Salida de error (heredada con `redirectError(INHERIT)`) | `Error: empty input or EXIT received.` |
| Hijo → padre | Código de salida (`waitFor()`) | `1` al recibir `EXIT` |

> [!warning] Sin `flush()` hay bloqueo
> `BufferedWriter` guarda lo escrito en memoria hasta llenar su búfer. Si el padre no hiciera `flush()`, la cadena no llegaría al hijo. El padre esperaría en `readLine()` una respuesta que el hijo no puede dar, porque sigue esperando la cadena: un **interbloqueo**. Lo mismo pasaría en el hijo sin el autoflush del `PrintWriter`.

## Esquema resumen

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Lanzar un `.java` sin compilar | `new ProcessBuilder(java, "Inverter.java")` | `java` lo compila en memoria y lo ejecuta |
| Heredar la salida de error | `builder.redirectError(Redirect.INHERIT)` | Los errores del hijo salen en la consola del padre |
| Escribir al hijo | `process.getOutputStream()` + `write`/`newLine` | Llega a `System.in` del hijo |
| Vaciar el búfer | `flush()` · `new PrintWriter(..., true)` | Envía los datos al momento |
| Leer del hijo | `process.getInputStream()` + `readLine()` | Lo que el hijo escribió con `System.out` |
| Invertir una cadena | `new StringBuilder(s).reverse()` | Devuelve la cadena al revés |
| Terminar con error | `System.exit(1)` | El padre lo recibe en `waitFor()` |
| Comprobar el código | `int code = process.waitFor()` | Bloquea hasta que termina el hijo |
