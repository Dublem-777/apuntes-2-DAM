## Proceso, PID y estado de terminación

Un programa es la representación en disco de una aplicación; un proceso es una instancia de ese programa en ejecución. El sistema operativo asigna a cada proceso un identificador (**PID**) y mantiene su contexto y recursos.

Al finalizar, un proceso proporciona un código de salida: por convención, `0` indica éxito y un valor distinto de cero indica error. En Java, `System.exit(status)` termina la JVM; si el método `main` termina normalmente, el código suele ser `0`.

`System` da acceso a los flujos estándar, variables de entorno y propiedades de la JVM. `Runtime.getRuntime()` devuelve el objeto único que representa el entorno de ejecución y permite, entre otras cosas, iniciar procesos y consultar recursos.

## Variables de entorno y propiedades del sistema

Las variables de entorno pertenecen al entorno del sistema operativo y se consultan con `System.getenv()`. `System.getenv("PATH")` devuelve el valor o `null`; sin argumentos, `System.getenv()` devuelve un mapa de solo lectura.

Las propiedades del sistema son propias de la JVM y se leen con `System.getProperty(nombre)`. Se pueden definir algunas desde la línea de comandos con `-Dnombre=valor`.

| Propiedad | Significado |
|---|---|
| `java.version` | Versión de Java |
| `os.name`, `os.version` | Sistema operativo y versión |
| `user.home`, `user.dir` | Directorio personal y directorio de trabajo |
| `file.separator`, `line.separator` | Separadores propios del sistema |
| `java.home`, `java.class.path` | Instalación Java y classpath actual |

Para detectar el sistema operativo, puede compararse `os.name` sin distinguir mayúsculas. Evita asumir que todo sistema no Windows es Unix si el programa debe admitir otras plataformas.

## Órdenes y shell por sistema operativo

Un ejecutable independiente puede iniciarse directamente. En Windows, órdenes internas como `dir` necesitan el intérprete `cmd.exe /c`; en Unix-like, operaciones del shell como tuberías, redirecciones, comodines o `cd` requieren un shell con `-c`. No hace falta shell para invocar directamente ejecutables como `ls`, `java` o `python`.

`start` es un comando interno de `cmd.exe` que abre una aplicación de forma separada. Si el proceso queda desvinculado, Java no puede capturar sus flujos y no lo termina automáticamente.

Para rutas multiplataforma, usa `Path` o `File.separator`; las barras invertidas de literales Java deben escaparse (`\`).

## Creación con Runtime.exec

`Runtime.exec` inicia un programa y devuelve un objeto `Process`:

```java
Process proceso = Runtime.getRuntime().exec(new String[]{"ls", "-l"});
```

La forma `exec(String)` está obsoleta desde Java 18; se recomienda `ProcessBuilder` o una sobrecarga que reciba el comando como array. Cada elemento del array es un token independiente. Otras sobrecargas permiten configurar el entorno (`envp`) y el directorio de trabajo (`dir`). Una orden inválida o inaccesible puede producir `IOException`.

No pases una cadena con shell syntax esperando que `exec` la interprete: si necesitas tuberías o redirecciones, inicia explícitamente un intérprete.

## Creación y configuración con ProcessBuilder

`ProcessBuilder` es la API recomendada para configurar y lanzar procesos. Sus constructores reciben tokens separados; un argumento con espacios debe mantenerse como un único elemento:

```java
ProcessBuilder pb = new ProcessBuilder("cmd.exe", "/c", "dir", "/o");
Process proceso = pb.start();
```

`start()` crea un proceso nuevo cada vez que se invoca. El objeto `Process` representa una ejecución concreta y no puede reiniciarse.

Antes de `start()`, la lista devuelta por `command()` se puede modificar o reemplazar. Cambiar la configuración después de iniciar el proceso solo afecta a futuros `start()`.

El mapa de `environment()` comienza como copia del entorno heredado y puede modificarse antes del inicio. `directory(File)` establece el directorio de trabajo; por defecto se usa el directorio de trabajo del proceso padre.

Para lanzar otro programa Java desde el mismo entorno, pueden obtenerse `java.home`, `java.class.path` y el nombre binario de la clase (`Clase.class.getName()`). Evita codificar rutas dependientes del IDE o del sistema.

## Abrir aplicaciones con Desktop

`java.awt.Desktop` abre archivos, URLs o el cliente de correo predeterminado del sistema. No ofrece el control directo de un `Process`: normalmente no permite leer la salida del programa abierto ni gestionar su ciclo de vida.

Antes de usarlo, comprueba `Desktop.isDesktopSupported()` y `desktop.isSupported(Desktop.Action.BROWSE)` (o la acción correspondiente). Acciones comunes: `open(File)`, `edit(File)`, `print(File)`, `browse(URI)` y `mail()`.

> [!warning] Límite
> `Desktop` puede no estar disponible en entornos *headless* o plataformas que no soporten la acción solicitada.

## Esquema

- Un proceso es una instancia en ejecución; el sistema asigna PID y registra un código de salida.
- `System.getenv` lee entorno del SO; `System.getProperty` lee configuración de la JVM.
- `Runtime.exec` y `ProcessBuilder` crean procesos; prefiere `ProcessBuilder` y argumentos separados.
- Configura comando, entorno y directorio de trabajo antes de `start()`.
- Usa shell solo cuando necesites interpretar órdenes internas o sintaxis del shell.
- `Desktop` abre recursos con aplicaciones asociadas, pero no sustituye el control de `Process`.
