## 1. Prioridad en los hilos

Como vimos anteriormente al hablar de la clase `Thread`, uno de los atributos de información gestionados internamente por cada hilo es su prioridad. La prioridad de un hilo es un valor entero que indica la importancia relativa de ese hilo con respecto a otros hilos en el sistema. La prioridad se utiliza como una guía para el planificador de hilos (scheduler) del sistema operativo y de la Máquina Virtual de Java (JVM) a la hora de decidir qué hilo debe ejecutarse en cada momento cuando hay múltiples hilos listos para ejecutarse.

En Java, cada hilo tiene asignada una prioridad que puede ser consultada y modificada (aunque con ciertas limitaciones, como veremos). Mediante el método `setPriority(int prioridad)` podemos establecer la prioridad de un determinado hilo, indicando al sistema la importancia que le damos a la ejecución de este hilo en relación con otros hilos del programa.

![Prioridades de hilos](https://educacionadistancia.juntadeandalucia.es/centros/cadiz/pluginfile.php/242057/mod_resource/content/10/files/thread_priority.webp)
*Prioridades de hilos*

La clase Thread nos proporciona una serie de constantes estáticas que representan los valores estándar de prioridad que podemos utilizar al establecer la prioridad de un hilo. Estas constantes son:

- `Thread.MIN_PRIORITY`: Representa la prioridad mínima que puede tener un hilo. Su valor numérico es `1`. Se utiliza para hilos que realizan tareas de muy baja prioridad o en segundo plano que pueden ser relegadas a un segundo plano en favor de otros hilos más importantes.
- `Thread.NORM_PRIORITY`: Representa la prioridad normal o prioridad por defecto que se asigna a los hilos si no se especifica otra prioridad explícitamente. Su valor numérico es `5`. Se utiliza para la mayoría de los hilos que realizan tareas ordinarias en la aplicación.
- `Thread.MAX_PRIORITY`: Representa la prioridad máxima que puede tener un hilo. Su valor numérico es `10`. Se utiliza para hilos que realizan tareas de alta prioridad o críticas que deben tener preferencia en la ejecución sobre otros hilos menos importantes (aunque, como hemos advertido, sin garantías absolutas).

El rango de prioridades válidas para los hilos en Java es de `1` (mínima prioridad) a `10` (máxima prioridad), pasando por la prioridad normal `5`. Si intentamos establecer una prioridad fuera de este rango (por ejemplo, 0 o 11), el método `setPriority()` lanzará una excepción de tipo `IllegalArgumentException`.

Por defecto, si no establecemos explícitamente la prioridad de un hilo al crearlo, se le asigna la prioridad normal (`Thread.NORM_PRIORITY = 5`).

## 2. Recomendación sobre el uso de prioridades

> [!warning] Aviso
> `setPriority(priority)` solo hace una sugerencia al sistema operativo, no es una orden ni una garantía

Es importante entender que la prioridad de Java es solo una sugerencia que la Máquina Virtual de Java (JVM) transmite al sistema operativo, y este último decide cómo aplicarla.

Cuando llamamos a `thread.setPriority(priority)`, la JVM intenta mapear este valor (1-10) a los niveles de prioridad nativos que utiliza el planificador del sistema operativo (que suelen ser valores numéricos diferentes, o incluso constantes como "normal", "alta", o "tiempo real").

Los sistemas operativos POSIX (Linux, macOS) generalmente tienen un buen soporte para la prioridad de hilos. El planificador del sistema suele honrar la sugerencia de Java, dando más tiempo de CPU a los hilos de mayor prioridad (10) y menos a los de menor prioridad (1).

Windows utiliza un mapeo más "grueso" de las prioridades. A menudo, mapea todo el rango de Java (1-10) a solo unos pocos niveles de prioridad nativos (ej., NORMAL, HIGH, IDLE). Esto significa que cambiar la prioridad de Java de 6 a 8 podría no tener ningún efecto discernible porque ambos podrían mapear al mismo nivel de prioridad nativa de Windows.

En algunas plataformas incrustadas o sistemas en tiempo real, el mapeo de prioridades puede ser muy estricto o ignorarse por completo si el planificador del SO no permite la manipulación de prioridades por parte de programas de usuario.

El empleo de prioridades es útil para indicar al SO qué hilos son críticos para la capacidad de respuesta (ej., el hilo de interfaz de usuario) y cuáles pueden ejecutarse en segundo plano (ej., el hilo de guardado automático).

Sin embargo, por lo general **no se recomienda generalmente cambiar la prioridad de los hilos** en la mayoría de las aplicaciones multihilo.

Aunque Java proporciona el mecanismo para establecer la prioridad de los hilos, modificar las prioridades de los hilos de forma indiscriminada o sin una justificación muy clara puede ser contraproducente y generar más problemas que soluciones en la programación concurrente.

Es una práctica común evitar usar `MIN_PRIORITY` y `MAX_PRIORITY` a menos que el hilo sea verdaderamente crítico o un proceso de fondo que no importa si tarda más.

En particular, cambiar las prioridades de los hilos puede aumentar el riesgo de problemas de inanición (o _starvation_ en inglés) en los hilos de menor prioridad. Si en nuestra aplicación aumentamos artificialmente la prioridad de algunos hilos y disminuimos la prioridad de otros, podemos provocar involuntariamente situaciones de inanición en los hilos de menor prioridad, haciendo que nunca lleguen a ejecutarse o que tarden muchísimo tiempo en completar su tarea, incluso si tienen trabajo pendiente y están listos para ejecutarse.

En general, es preferible dejar que el scheduler del sistema operativo gestione la planificación de los hilos de forma equitativa y automática, basándose en criterios internos del sistema operativo y de la JVM, sin interferir manualmente con las prioridades de los hilos.

De hecho, nunca deben usarse para garantizar la corrección o la sincronización de un programa. Para eso se usan mecanismos de sincronización y coordinación que estudiaremos más adelante, como monitores, cerrojos, colas concurrentes, etc., para controlar el flujo de ejecución y la concurrencia entre los hilos, en lugar de manipular las prioridades de los hilos de forma manual.

Debemos tener muy claro que al utilizar el método `setPriority(prioridad)` para establecer la prioridad de un hilo, tan solo estamos haciendo una sugerencia al sistema operativo subyacente. NO estamos dando una orden imperativa al sistema operativo ni a la JVM, y NO tenemos ninguna garantía absoluta de que dicha sugerencia vaya a ser tenida en cuenta o de que vaya a producir el efecto deseado en la planificación de la ejecución de los hilos. La prioridad de los hilos en Java es un mecanismo orientativo y no determinista. El scheduler del sistema operativo (y de la JVM) intentará favorecer la ejecución de los hilos con mayor prioridad frente a los de menor prioridad, pero no está obligado a hacerlo siempre ni en todo momento.

## 3. Proyecto Priority

Similar al proyecto anterior de las tablas de multiplicar con Runnable, en este nuevo proyecto vamos a explorar el concepto de prioridad de los hilos y comprobar si realmente la prioridad influye en el orden de ejecución de los hilos. Vamos a modificar el proyecto anterior para asignar prioridades diferentes a los hilos que calculan las tablas de multiplicar, y observar si esto tiene algún efecto perceptible en el orden en que se muestran las líneas de salida de las tablas. En concreto, vamos a establecer la prioridad máxima (Thread.MAX_PRIORITY) para los hilos que calculan las tablas de los números pares, y la prioridad mínima (Thread.MIN_PRIORITY) para los hilos que calculan las tablas de los números impares, y comprobaremos si los hilos con prioridad máxima se ejecutan antes o con mayor frecuencia que los hilos con prioridad mínima.

**Proyecto Priority** · [▶ Replit](https://repl.it/@PedroJoya/PR003-Priority)

> [!warning] Código incompleto
> En Moodle el proyecto tiene las pestañas `Main`, `MultiplicationTable`, pero al copiarlo solo se guardó **`Main`**.

`Main.java`
```java
public class Main {

    public static void main(String[] args) {
        for (int i = 1; i <= 10; i++) {
            Thread thread = new Thread(new MultiplicationTable(i));
            if ((i % 2) == 0) {
                thread.setPriority(Thread.MAX_PRIORITY);
            } else {
                thread.setPriority(Thread.MIN_PRIORITY);
            }
            thread.start();
        }
    }

}
```

Al ejecutar el proyecto podemos comprobar como el orden en que se muestran las líneas de las diferentes tablas de multiplicar no es igual al de un programa con un único hilo, e incluso puede ser diferentes en distintas ejecuciones. Además vemos como establecer la prioridad no es ninguna garantía de ejecución temprana.

## Esquema

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Cambiar prioridad | `hilo.setPriority(p)` | Solo una **sugerencia** al SO |
| Constantes | `MIN_PRIORITY` (1) · `NORM_PRIORITY` (5) · `MAX_PRIORITY` (10) | Por defecto, 5 |
| Fuera de rango | `setPriority(0)` / `setPriority(11)` | `IllegalArgumentException` |
| Linux/macOS vs. Windows | — | POSIX la respeta mejor; Windows agrupa en pocos niveles |
| Riesgo | prioridades muy distintas | Inanición de los hilos de baja prioridad |
