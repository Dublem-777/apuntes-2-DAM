## 1. La interfaz Runnable

La técnica que vimos en el apartado anterior, de definir una clase que extiende de `Thread`, es una forma directa y sencilla de crear hilos en Java. Sin embargo, presenta una limitación importante: como bien sabemos, Java no permite la herencia múltiple de clases. Esto significa que, si definimos una clase que extiende de `Thread`, esta clase no podrá heredar de ninguna otra clase en la jerarquía de herencia de Java. Esta restricción de la herencia única puede ser un inconveniente significativo en muchos escenarios de programación orientada a objetos, donde podríamos querer que nuestra clase de hilo herede de otra clase base para reutilizar código o implementar una jerarquía de clases más compleja.

**Definición de Runnable**
```java
package java.lang;

@FunctionalInterface
public interface Runnable {
    void run();
}
```

Para solucionar este problema y proporcionar una forma más flexible y versátil de definir tareas concurrentes en Java, se introdujo la interfaz `Runnable`, perteneciente al paquete `java.lang`. La interfaz `Runnable` representa el comportamiento de una "tarea", es decir, un conjunto de líneas de código que puede ser ejecutado en un hilo de ejecución. La interfaz `Runnable` se ha convertido en la forma idiomática y recomendada en Java para definir tareas concurrentes, ya que evita la limitación de la herencia única y proporciona una mayor flexibilidad en el diseño de aplicaciones multihilo.

De esta manera, en vez de definir una clase que extienda de `Thread`, definiremos una clase que implemente la interfaz `Runnable`, permitiéndonos que la clase extienda de cualquier otra clase que nos interese.

La interfaz `Runnable` es muy sencilla y concisa. Su único objetivo es definir la tarea que se quiere ejecutar de forma concurrente. La interfaz `Runnable` posee un único método abstracto: el método `run()`. El método `run()` de la interfaz `Runnable` es análogo al método `run()` de la clase `Thread`. Cuando implementamos la interfaz `Runnable` en una clase, debemos sobrescribir el método `run()` para indicar el código que debe ser ejecutado como una tarea concurrente.

De hecho, es importante destacar que la propia clase `Thread` implementa la interfaz `Runnable`, y es por eso que la clase `Thread` ya dispone del método `run()` (heredado de la interfaz `Runnable`).

Así, definiremos una clase que represente la "tarea" y que implementará la interfaz `Runnable`:

**Implementando Runnable**
```java
class MyRunnable implements Runnable {

    // ...
    @Override
    public void run() {
        // ...
    }

}
```

## 2. Creación de un hilo que ejecute un Runnable

Sin embargo, es fundamental entender que la interfaz `Runnable` por sí sola no crea ni gestiona un hilo de ejecución. La interfaz `Runnable` solo define la tarea, el código que se va a ejecutar de forma concurrente. Para ejecutar realmente la tarea definida en un `Runnable` en un nuevo hilo de ejecución, necesitamos utilizar la clase `Thread` y asociar el objeto `Runnable` a un objeto `Thread`, como veremos a continuación.

Para ejecutar la tarea en un nuevo hilo de ejecución haremos:

**Ejecutando un Runnable en un hilo**
```java
public class Main {

    public static void main(String[] args) {
        new Thread(new MyRunnable()).start();
    }

}
```

Dado que la interfaz `Runnable` corresponde a una interfaz funcional, porque posee un único método abstracto, si estamos empleando Java 8+ podemos usar una expresión lambda o una referencia a método para representar el objeto `Runnable`. En el siguiente ejemplo creamos un nuevo objeto `Thread` al que le pasamos un nuevo objeto `Runnable` representado mediante una expresión _lambda_:

**Ejecutando en un hilo una lambda como Runnable**
```java
public class Main {

    public static void main(String[] args) {
        new Thread(() -> {
            // ...
        }).start();
    }

}
```

Es importante tener en cuenta que, si necesitamos pasar argumentos o datos al código que se va a ejecutar dentro del método `run()` del `Runnable`, debemos hacerlo a través del constructor de la clase que implementa `Runnable` o mediante métodos setter definidos en esa clase. La idea es almacenar los argumentos recibidos en el constructor o con los setters como atributos (campos) de la clase `Runnable`, de manera que el código del método `run()` pueda acceder a estos atributos y utilizar los valores de los argumentos durante la ejecución de la tarea.

Estas técnicas de paso de argumentos mediante constructor o setters son incompatibles con el empleo directo de expresiones lambda para crear Runnables, debido a las características de las lambdas (las lambdas son funciones anónimas y no tienen constructores ni atributos). Si necesitamos pasar argumentos a la tarea concurrente, normalmente tendremos que definir una clase separada que implemente Runnable y que tenga un constructor o setters para recibir los argumentos.

El constructor de la clase `Thread` está sobrecargado, `Thread(String name, Runnable runnable)`, de manera que podemos pasarle el nombre que queremos que tenga el hilo.

## 3. Acceso desde el Runnable al hilo

> [!definition] Acceso al hilo desde el Runnable
> `Thread.currentThread()` retorna el objeto `Thread` en el que nos estamos ejecutando

Si desde el objeto `Runnable` necesitamos **acceder a información sobre el hilo de ejecución** en el que se está ejecutando, podemos usar **el método estático `Thread.currentThread()`, que retorna el objeto `Thread` en el que está ejecutando** dicha línea de código.

## 4. Beneficios de Runnable

En general, el uso de la interfaz `Runnable` se considera más flexible y recomendable que la herencia directa de `Thread` para la creación de hilos en Java, especialmente en la mayoría de los escenarios de programación multihilo. La principal ventaja de `Runnable` es la mayor flexibilidad que proporciona al evitar la limitación de la herencia única de Java.

Además, la interfaz Runnable es más genérica y versátil que la clase Thread. Los objetos `Runnable` no solo se pueden utilizar con la clase `Thread`, sino que también se pueden utilizar con otras clases y APIs de Java que gestionan la ejecución de tareas concurrentes, como los executors (ejecutores en español), que estudiaremos más adelante.

Así, la interfaz `Runnable` se considera la forma preferida y más idiomática de definir tareas concurrentes en Java en la mayoría de los casos.

## 5. Cómo "retornar" un valor desde un Runnable

Un aspecto importante a tener en cuenta es que el método `run()` de la interfaz `Runnable` está definido para no retornar ningún valor (`void`). Esto significa que, directamente, no podemos hacer que un hilo secundario (que ejecuta un `Runnable`) devuelva un resultado a través del método `run()`. Entonces, ¿cómo podemos hacer si necesitamos que un hilo secundario calcule un resultado y devuelva ese resultado al hilo que lo inició? Aunque el método `run()` no permite retornar directamente un valor, existen varias formas de "simular" el retorno de un resultado desde un Runnable:

- Definir un objeto compartido entre el hilo que inicia la tarea (hilo principal) y el hilo secundario (que ejecuta el `Runnable`), para almacenar el resultado. Es esencial utilizar mecanismos de sincronización adecuados para proteger el acceso concurrente al objeto compartido y evitar problemas de concurrencia.
- Defnir un atributo en la clase que implementa `Runnable` para almacenar el resultado del cálculo. El hilo principal, después de iniciar el hilo secundario y esperar a que termine, puede acceder al objeto `Runnable` y obtener el resultado accediendo al valor del campo que hemos definido. Esta técnica también requiere precauciones con la concurrencia si varios hilos acceden al mismo objeto `Runnable` y a su campo de resultado.
- Utilizar la interfaz `Callable` como alternativa a `Runnable` para definir tareas concurrentes que sí pueden retornar un resultado. Solo podemos usar objetos `Callable` con los ejecutores, que estudiaremos más adelante.

## 6. Proyecto Runnable

Este proyecto nos permitirá comparar ambas formas de crear hilos en Java y ver cómo se utiliza la interfaz `Runnable` en la práctica para definir tareas concurrentes. Al igual que en el proyecto anterior, representaremos la tabla de multiplicar de un número definiendo una clase llamada `MultiplicationTable`, pero en este caso, esta clase implementará la interfaz `Runnable` en lugar de extender la clase `Thread`.

## Esquema

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Definir la tarea | `class X implements Runnable` + `run()` | Solo define el código, no crea hilo |
| Ejecutarla en un hilo | `new Thread(new X()).start()` | El `Thread` ejecuta el `run()` del `Runnable` |
| Con lambda | `new Thread(() -> { ... }).start()` | `Runnable` es interfaz funcional |
| Con nombre | `new Thread(runnable, "nombre")` | Nombre del hilo |
| Hilo actual | `Thread.currentThread()` | El `Thread` que ejecuta esa línea |
| Pasar datos | constructor o setters | Las lambdas no tienen atributos ni constructor |
| "Devolver" un valor | objeto compartido · atributo del `Runnable` · `Callable` | `run()` es `void` |
