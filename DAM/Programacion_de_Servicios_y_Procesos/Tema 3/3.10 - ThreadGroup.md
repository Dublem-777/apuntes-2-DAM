## 1. Grupos de hilos

Una funcionalidad muy interesante y útil que nos ofrece Java para la programación multihilo es la posibilidad de agrupar hilos en grupos de hilos (_thread groups_). La agrupación de hilos permite organizar y gestionar conjuntos de hilos relacionados entre sí como si fueran una sola unidad lógica. Esto facilita la realización de operaciones globales sobre todos los hilos de un grupo de forma conjunta y eficiente, simplificando la gestión y el control de aplicaciones multihilo complejas.

Por ejemplo, si tenemos varios hilos que colaboran en la misma tarea o que pertenecen al mismo subsistema de la aplicación, podemos agruparlos bajo un mismo grupo de hilos. Una vez agrupados, podemos aplicar operaciones a todo el grupo de forma simultánea, como interrumpir todos los hilos del grupo de una sola vez, cambiar la prioridad de todos los hilos del grupo, monitorizar el estado general del grupo, o establecer un manejador de excepciones común para todos los hilos del grupo.

## 2. Creación de un grupo de hilos

Java nos proporciona la clase `ThreadGroup` para trabajar con grupos de hilos. Un objeto `ThreadGroup` representa un grupo de hilos. Un objeto `ThreadGroup` puede contener tanto objetos `Thread` (hilos) como otros objetos `ThreadGroup` (subgrupos de hilos), permitiendo crear jerarquías de grupos de hilos con una estructura de árbol.

El grupo raíz de la jerarquía de grupos de hilos es el grupo "system", que se crea automáticamente al inicio de la JVM y que contiene todos los demás grupos de hilos. Cada hilo pertenece a un único grupo de hilos, y un grupo de hilos puede contener múltiples hilos y múltiples subgrupos.

Si queremos crear un nuevo hilo y agregarlo a un determinado grupo de hilos existente, simplemente tendremos que especificar el objeto `ThreadGroup` correspondiente al grupo como primer parámetro del constructor de `Thread`. La clase `Thread` proporciona constructores sobrecargados para este cometido, que permiten especificar el grupo de hilos al que pertenecerá el nuevo hilo en el momento de su creación. Las sintaxis posibles de estos constructores sobrecargados son:

- `Thread(ThreadGroup grupo, Runnable objeto)`: Crea un nuevo hilo que ejecutará el objeto Runnable objeto y que pertenecerá al grupo de hilos grupo. El hilo heredará el nombre por defecto del grupo de hilos.
- `Thread(ThreadGroup grupo, Runnable objeto, String nombreHilo)`: Crea un nuevo hilo que ejecutará el objeto Runnable objeto, que pertenecerá al grupo de hilos grupo, y que tendrá el nombre nombreHilo.

En ambas sintaxis, el primer parámetro es siempre el objeto `ThreadGroup` que representa el grupo de hilos al que se desea agregar el nuevo hilo.

Es importante tener en cuenta que la asignación de un hilo a un grupo de hilos se realiza en el momento de la creación del hilo utilizando estos constructores, y **una vez que el hilo ha sido creado, no se puede modificar el grupo de hilos al que pertenece**. Un hilo pertenece a un grupo de hilos durante toda su vida.

## 3. Métodos de un grupo de hilos

La clase `ThreadGroup` proporciona diversos métodos para realizar operaciones conjuntas sobre todos los hilos del grupo o para obtener información sobre el estado del grupo y sus hilos. Algunos de los métodos más importantes de `ThreadGroup` son:

- `interrupt()`: Este método marca para interrupción todos los hilos que pertenecen al grupo (y a todos sus subgrupos de forma recursiva). Cuando se llama a `grupoHilos.interrupt()`, se invoca el método `interrupt()` de cada uno de los hilos contenidos directamente en grupoHilos, y también se repite la operación de interrupción para todos los hilos contenidos en cualquier subgrupo de grupoHilos. Este método es muy útil para cancelar o terminar de forma coordinada un conjunto de tareas paralelas ejecutadas por los hilos de un grupo. Por ejemplo, si queremos detener una tarea compleja que se ha dividido en varios hilos, basta con interrumpir el grupo de hilos que ejecutan esas subtareas para cancelar toda la tarea de forma global.
- `activeCount()`: Este método retorna el número de hilos activos (en estado `RUNNABLE` o `BLOCKED`) que pertenecen al grupo de hilos (y a todos sus subgrupos de forma recursiva). Este método es útil para monitorizar el número de hilos en ejecución en un grupo en un momento dado, y determinar si el grupo todavía tiene hilos trabajando o si todos los hilos del grupo han terminado. Por ejemplo, se puede utilizar `activeCount()` para esperar a que todos los hilos de un grupo terminen su ejecución antes de continuar con otra tarea que dependa de los resultados de esos hilos.
- `list()`: Este método muestra por la salida estándar de error (System.err) información detallada sobre todos los hilos que pertenecen al grupo (y a todos sus subgrupos de forma recursiva). La información que se muestra para cada hilo incluye el nombre del hilo, su prioridad, y el grupo de hilos al que pertenece. Este método es útil para depurar y monitorizar el estado de los hilos de un grupo durante la ejecución de la aplicación, proporcionando una visión general de los hilos activos en el grupo y su configuración. La salida de list() se suele utilizar para propósitos de diagnóstico y depuración, no para obtener información programáticamente para la lógica de la aplicación.
- `enumerate(Thread[] lista)`: Este método copia en el array de `Thread` lista pasado como argumento una lista de todos los hilos activos (en estado `RUNNABLE` o `BLOCKED`) que pertenecen al grupo de hilos (y a todos sus subgrupos de forma recursiva). El método retorna el número de hilos que se han copiado en el array. Si el array pasado como argumento es demasiado pequeño para contener todos los hilos activos del grupo, solo se copiarán los hilos que quepan en el array, y el método seguirá retornando el número total de hilos activos (que puede ser mayor que el tamaño del array). Este método es útil para obtener una lista de los hilos activos de un grupo de forma programática, para poder iterar sobre ellos y realizar operaciones individuales sobre cada hilo (si es necesario).

## 4. Gestión de excepciones del grupo

Por otro lado, como mencionamos cuando hablamos de `UncaughtExceptionHandler`, la clase `ThreadGroup` también implementa la interfaz `Thread.UncaughtExceptionHandler`. Esto significa que un objeto `ThreadGroup` puede actuar como un manejador de excepciones no capturadas por defecto para todos los hilos que pertenecen a ese grupo. Si un hilo del grupo no tiene asignado un manejador de excepciones individual (mediante `setUncaughtExceptionHandler(handler)`), y se produce una _unchecked exception_ dentro de su método `run()`, la JVM buscará un manejador de excepciones para ese hilo siguiendo el procedimiento que vimos en el apartado anterior. Si la JVM llega al paso de comprobar el manejador del grupo de hilos al que pertenece el hilo, y el grupo de hilos tiene un manejador de excepciones definido (que es el propio objeto `ThreadGroup`), la JVM llamará al método `uncaughtException(Thread t, Throwable e)` del objeto `ThreadGroup` para que gestione la excepción no capturada. De esta manera podemos gestionar las excepciones a nivel de gurpo de hilos.

## 5. Usos habituales de los grupos de hilos

Algunas situaciones típicas donde es especialmente útil utilizar grupos de hilos son:

- **Aplicaciones con tareas paralelas relacionadas entre sí**: En aplicaciones que realizan tareas complejas que se pueden dividir en subtareas paralelas ejecutadas por múltiples hilos, agrupar los hilos que realizan las subtareas de la misma tarea principal en un grupo facilita la gestión y el control de la tarea principal en su conjunto. Por ejemplo, en un servidor web multihilo, se podrían agrupar los hilos que gestionan las peticiones de un mismo cliente en un grupo, para poder gestionar las peticiones de cada cliente como una unidad lógica.
- **Aplicaciones con subsistemas o componentes independientes que utilizan múltiples hilos**: En aplicaciones grandes y modulares, se pueden utilizar grupos de hilos para organizar los hilos que pertenecen a cada subsistema o componente de la aplicación. Esto permite aislar y gestionar los hilos de cada subsistema de forma independiente, mejorando la organización y la modularidad del código multihilo. Por ejemplo, en un sistema operativo, se podrían utilizar grupos de hilos para agrupar los hilos del planificador de procesos, del gestor de memoria, del sistema de archivos, etc., cada uno gestionando su propio conjunto de hilos de forma independiente.
- **Aplicaciones que necesitan cancelar o interrumpir conjuntamente varios hilos**: En situaciones donde es necesario cancelar o interrumpir la ejecución de un conjunto de hilos relacionados entre sí de forma simultánea, agrupar estos hilos en un grupo permite interrumpirlos a todos de una sola vez con una única llamada al método interrupt() del grupo. Esto simplifica la lógica de cancelación y terminación de tareas multihilo, evitando tener que iterar y llamar a `interrupt()` individualmente para cada hilo.

Por otro lado, como mencionamos cuando hablamos de `UncaughtExceptionHandler`, en caso se producirse una _uncaught exception_ dentro del método `run()` de un hilo, la JVM sigue el siguiente procedimiento trata de llamar al método `uncaughtException()` del objeto manejador establecido individualmente para dicho hilo. Pero si no se ha establecido en el hilo un manejador para ese tipo de excepciones, la JVM llamará al método `uncaughtException(Thread t, Throwable e)` del `ThreadGroup` grupo de hilos al que pertenezca el hilo. Por tanto si queremos manejar este tipo de excepciones a nivel de `ThreadGroup` simplemente tendremos que sobrescribir en el `TheadGroup` dicho método.

## 6. Proyecto ThreadGroup

Este ejemplo simula una aplicación que realiza una serie de tareas en segundo plano (por ejemplo, descargas, cálculos, etc.). Estas tareas se agrupan en un ThreadGroup. La aplicación permite al usuario cancelar todas las tareas en segundo plano de forma conjunta. Además, se implementa un manejador de excepciones no capturadas para registrar cualquier error que ocurra en los hilos del grupo.

**Proyecto ThreadGroup**

> [!warning] Código incompleto
> En Moodle el proyecto tiene las pestañas `Main`, `Tarea`, pero al copiarlo solo se guardó **`Main`**.

`Main.java`
```java
public class Main {
    public static void main(String[] args) {
        // Se crea un nuevo ThreadGroup para las tareas en segundo plano.
        ThreadGroup tareas = new ThreadGroup("Tareas en Segundo Plano");

        // Se define un manejador de excepciones no capturadas para el grupo.
        tareas.setUncaughtExceptionHandler(new Thread.UncaughtExceptionHandler() {
            @Override
            public void uncaughtException(Thread t, Throwable e) {
                System.err.printf("Hilo %s del grupo %s lanzó excepción no capturada: %s\n",
                        t.getName(), t.getThreadGroup().getName(), e.getMessage());
                // Aquí se podría añadir lógica adicional de manejo de errores, como
                // registrar el error en un log, notificar al usuario, etc.
            }
        });

        // Se simulan algunas tareas en segundo plano.
        for (int i = 0; i < 5; i++) {
            Tarea tarea = new Tarea("Tarea-" + i);
            Thread hiloTarea = new Thread(tareas, tarea, "Hilo-Tarea-" + i);
            hiloTarea.start();
        }

        System.out.println("Tareas en segundo plano iniciadas. Esperando 5 segundos...");
        try {
            TimeUnit.SECONDS.sleep(5); // Se simula un tiempo de ejecución de la aplicación.
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        // Simulación de la cancelación por parte del usuario.
        System.out.println("Simulando cancelación de tareas por el usuario...");
        tareas.interrupt(); // Se interrumpen todas las tareas en segundo plano.
        System.out.println("Programa principal finalizado.");
    }
}
```

## Esquema

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Crear un grupo | `new ThreadGroup("nombre")` | Árbol de grupos; la raíz es `system` |
| Hilo en un grupo | `new Thread(grupo, runnable[, nombre])` | Solo al crearlo; no se puede cambiar |
| Interrumpir todos | `grupo.interrupt()` | Recursivo en los subgrupos |
| Contar activos | `grupo.activeCount()` | Estimación de hilos vivos |
| Listar | `grupo.list()` · `grupo.enumerate(array)` | Depuración / copia a un array |
| Excepciones | sobrescribir `uncaughtException()` del grupo | Manejador común del grupo |
