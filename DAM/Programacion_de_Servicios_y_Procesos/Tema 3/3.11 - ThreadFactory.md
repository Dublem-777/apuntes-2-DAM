## 1. Fábrica de hilos

Uno de los patrones de diseño más clásicos y utilizados en el mundo de la programación orientada a objetos es el conocido como fábrica de objetos (_factory pattern_, en inglés). Un objeto fábrica tiene la misión principal de crear otros objetos de uno o varias clases. Cuando queremos instanciar un objeto de una de esas clases, en lugar de utilizar directamente el operador de instanciación new, utilizamos un método de la fábrica para obtener el objeto deseado. El patrón de fábrica encapsula el proceso de creación de objetos, ocultando la lógica de instanciación compleja o variable dentro de la fábrica, y proporcionando una interfaz más sencilla y uniforme para la creación de objetos desde el exterior.

Si utilizamos una fábrica de hilos, lo más recomendable y coherente es asegurarnos de que todos los hilos de nuestro programa son creados exclusivamente a través de dicha fábrica. En lugar de crear hilos directamente con el operador `new Thread(...)` en diferentes partes del código, utilizamos siempre la fábrica de hilos para obtener objetos `Thread`. De esta forma, garantizamos que todos los hilos de la aplicación se crean siguiendo la misma política de configuración y gestión definida en la fábrica. Esto mejora la consistencia, la mantenibilidad y la gestión global de los hilos de la aplicación, facilitando la aplicación de cambios o mejoras en la creación de hilos en un único punto (la fábrica), en lugar de tener que modificar la creación de hilos en múltiples lugares del código.

![ThreadFactory](https://educacionadistancia.juntadeandalucia.es/centros/cadiz/pluginfile.php/242057/mod_resource/content/10/files/threadfactory.png)
*ThreadFactory*

Utilizar una fábrica de hilos de forma consistente para toda la aplicación es una buena práctica de programación multihilo que contribuye a la creación de aplicaciones más organizadas, flexibles y fáciles de mantener a largo plazo, y aporta varias ventajas importantes:

- **Centralización de la creación de hilos y desacoplamiento del código de creación de hilos del código que los utiliza**: Al utilizar una fábrica de hilos, la lógica de creación de hilos se encapsula en un único lugar (la fábrica), separándola del código que necesita utilizar hilos para ejecutar tareas. Esto mejora la organización y la modularidad del código multihilo, facilitando el mantenimiento y la reutilización del código de creación de hilos. El código que utiliza hilos no necesita conocer los detalles de cómo se crean los hilos, simplemente solicita la creación de un nuevo hilo a la fábrica y recibe el objeto Thread ya creado y configurado.
- **Flexibilidad para cambiar la clase de los hilos creados o la forma en la que se crean sin modificar el código cliente**: Si en el futuro necesitamos cambiar la forma en que se crean los hilos (por ejemplo, utilizar una subclase de Thread diferente, establecer propiedades específicas de los hilos, o utilizar un pool de hilos en lugar de crear hilos nuevos cada vez), solo tenemos que modificar la implementación de la fábrica de hilos. El código que utiliza la fábrica de hilos no se verá afectado por estos cambios, ya que seguirá utilizando la misma interfaz de la fábrica para crear hilos. Esto aumenta la flexibilidad y la adaptabilidad del código multihilo a posibles cambios en los requisitos o en la implementación.
- **Posibilidad de limitar el número de hilos creados o de gestionar recursos limitados asociados a la creación de hilos**: Una fábrica de hilos puede implementar lógica para controlar el número de hilos que se crean, evitando la creación excesiva de hilos que pueda sobrecargar el sistema o consumir recursos limitados de forma ineficiente. Por ejemplo, una fábrica de hilos podría limitar el número máximo de hilos concurrentes, reutilizar hilos existentes en lugar de crear hilos nuevos cada vez (implementando un pool de hilos básico), o asignar hilos a diferentes grupos de hilos según su tipo o función. Esto permite optimizar el uso de recursos y mejorar el rendimiento y la estabilidad de las aplicaciones multihilo.
- **Facilidad para generar datos estadísticos o registrar información sobre la creación de hilos**: Una fábrica de hilos puede registrar información sobre cada hilo que crea, como la hora de creación, el nombre del hilo, el grupo de hilos al que pertenece, o cualquier otra información relevante para el seguimiento y la monitorización de los hilos de la aplicación. Estos registros pueden ser útiles para depurar problemas, analizar el rendimiento de la aplicación multihilo, o generar estadísticas sobre el uso de hilos.

## 2. Creación de hilos mediante una fábrica de hilos

Java nos proporciona la interfaz `ThreadFactory` para implementar fábricas de hilos. La interfaz `ThreadFactory` define el contrato que deben cumplir todas las fábricas de hilos en Java, garantizando que todas las fábricas de hilos proporcionen un método estándar para crear nuevos hilos.

**Definición de ThreadFactory**
```java
package java.util.concurrent;

public interface ThreadFactory {
    Thread newThread(Runnable r);
}
```

La interfaz `ThreadFactory` define un único método abstracto llamado `newThread(Runnable r)`. Cualquier clase que quiera implementar una fábrica de hilos en Java debe implementar esta interfaz y proporcionar una implementación para el método `newThread(Runnable r)`. El método `newThread(Runnable r)` recibe como argumento el objeto `Runnable` que representa la tarea que se desea ejecutar en el nuevo hilo. La implementación de `newThread(Runnable r)` debe crear y retornar un nuevo objeto `Thread` que esté configurado para ejecutar la tarea `r`.

Cuando queramos crear un hilo a través de la factoría tan solo tendremos que llamar al método `newThread()` de esta, pasándole el objeto `Runnable` correspondiernte a la tarea que debe ejecutar el hilo. Por ejemplo:

**Creación de un hilo a través de un ThreadFactory**
```java
public class MyThreadFactory implements ThreadFactory {
    // ...
    @Override
    public Thread newThread(Runnable runnable) {
        Thread thread = new Thread(...);
        // ...
        return thread;
    }
}

public class Task implements Runnable {
    // ...
    @Override
    public void run() {
        // ...
    }
}

ThreadFactory factory = new MyThreadFactory();
Task task = new Task();
Thread thread = factory.newThread(task);
thread.start();
```

Es importante destacar que el método `newThread(Runnable r)` solo crea el objeto `Thread`, pero NO inicia la ejecución del hilo. La responsabilidad de iniciar el hilo recae en el código que utiliza la fábrica de hilos, no en la propia fábrica.

Dentro de la implementación del método `newThread(Runnable r)` en una clase que implementa `ThreadFactory`, se suelen realizar operaciones de configuración y personalización del hilo que se va a crear, antes de retornarlo. Algunas operaciones típicas que se pueden realizar dentro de `newThread(Runnable r)` son:

- **Crear una instancia de la clase `Thread` (o de una subclase de `Thread`)**: Utilizando el constructor adecuado de `Thread`, pasándole el objeto `Runnable` como argumento (y opcionalmente, un nombre para el hilo, un grupo de hilos, etc.).
- **Establecer el nombre del hilo**: Utilizando el método `setName()` del objeto `Thread`. Se puede generar un nombre descriptivo y único para cada hilo creado por la fábrica, facilitando la identificación y el seguimiento de los hilos en logs o herramientas de monitorización.
- **Establecer la prioridad del hilo**: Utilizando el método `setPriority()` del objeto Thread. Se puede asignar una prioridad específica a los hilos creados por la fábrica, según el tipo de tarea que van a ejecutar o la importancia relativa de esos hilos en la aplicación.
- **Asignar el hilo a un grupo de hilos específico**: Utilizando el constructor de `Thread` que permite especificar el `ThreadGroup`. Se pueden agrupar los hilos creados por la fábrica en un grupo de hilos lógico, facilitando la gestión y el control de conjuntos de hilos relacionados.
- **Establecer un manejador de excepciones no capturadas personalizado para el hilo**: Utilizando el método `setUncaughtExceptionHandler()` del objeto `Thread`. Se puede asignar un `UncaughtExceptionHandler` específico a los hilos creados por la fábrica, personalizando el manejo de errores no capturados en esos hilos y estableciendo una política de gestión de errores coherente para todos los hilos creados por la fábrica.
- **Registrar la creación del hilo en un log o sistema de monitorización**: Se puede registrar información sobre la creación de cada hilo, como la hora de creación, el nombre del hilo, la fábrica que lo creó, etc., para propósitos de seguimiento, depuración o análisis de rendimiento.
- **Realizar cualquier otra configuración o inicialización específica del hilo antes de retornarlo**: En general, dentro del método `newThread(Runnable r)` se puede incluir cualquier código necesario para preparar y configurar el hilo antes de que sea utilizado por el código cliente.

## 3. Proyecto ThreadFactory

En el siguiente ejemplo vamos a crear una fábrica de hilos personalizada que ilustra el uso de la interfaz `ThreadFactory` para implementar una lógica de creación de hilos específica. Desarrollaremos una fábrica de hilos que construye los hilos con un nombre base personalizado y que mantiene un registro de la creación de cada hilo, almacenando información como la hora de creación y el nombre del hilo. Al finalizar la ejecución de todos los hilos creados por la fábrica, se mostrará el registro de creación de hilos generado por la fábrica.

**Proyecto ThreadFactory** · [▶ Replit](https://repl.it/@PedroJoya/PR-ThreadFactory)

> [!warning] Código incompleto
> En Moodle el proyecto tiene las pestañas `Main`, `Task`, `MyThreadFactory`, pero al copiarlo solo se guardó **`Main`**.

`Main.java`
```java
import java.util.ArrayList;
import java.util.concurrent.TimeUnit;

public class Main {

    public static void main(String[] args) {
        final MyThreadFactory threadFactory = new MyThreadFactory("MyThreadFactory");
        ArrayList<Thread> threads = new ArrayList<>();
        for (int i = 0; i < 3; i++) {
            Thread thread = threadFactory.newThread(new Task());
            threads.add(thread);
            thread.start();
            try {
                TimeUnit.SECONDS.sleep(1);
            } catch (InterruptedException exception) {
                return;
            }
        }
        for (Thread thread : threads) {
            try {
                thread.join();
            } catch (InterruptedException exception) {
                return;
            }
        }
        System.out.printf("\n\nMyThreadFactory Log\n\n%s", threadFactory.getLog());
    }

}
```

Si ejecutamos el programa veremos que los hilos se crean usando la factoría y que se guarda un registro con la hora de creación de los hilos.

## Esquema

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Interfaz | `java.util.concurrent.ThreadFactory` | Un método: `Thread newThread(Runnable r)` |
| Crear un hilo | `factory.newThread(task)` | Crea y configura el hilo, **no** lo inicia |
| Configuración típica | nombre, prioridad, grupo, manejador, log | Política común en un solo sitio |
| Buena práctica | crear **todos** los hilos con la fábrica | Coherencia y mantenimiento |
