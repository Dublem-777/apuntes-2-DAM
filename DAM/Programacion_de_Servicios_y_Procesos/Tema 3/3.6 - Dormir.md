## 1. Motivos para dormir un hilo

En muchas ocasiones, en la programación multihilo, resulta interesante poder suspender temporalmente la ejecución de un hilo durante un periodo de tiempo determinado. La capacidad de "dormir" un hilo es una técnica fundamental en la programación concurrente, que permite lograr diversos objetivos, como por ejemplo:

- **Liberar la CPU para otros hilos o procesos**: Cuando un hilo está inactivo o no necesita ejecutarse de forma continua durante un cierto tiempo (por ejemplo, porque está esperando un evento externo, o porque necesita reducir su consumo de CPU), dormir el hilo permite que el sistema operativo pueda asignar el tiempo de CPU a otros hilos o procesos que sí tengan trabajo pendiente, mejorando la eficiencia y la capacidad de respuesta general del sistema. En lugar de que el hilo se quede en un bucle de espera activa (consumiendo CPU innecesariamente), dormir el hilo lo pone en estado de espera pasiva, liberando la CPU para que otros hilos puedan utilizarla.
- **Controlar la frecuencia de ejecución de tareas periódicas**: En aplicaciones que realizan tareas periódicas (como el ejemplo del sensor que se menciona, o como tareas de monitorización, lectura de datos a intervalos regulares, actualización de interfaces gráficas a cierta frecuencia, etc.), dormir el hilo entre cada ejecución de la tarea permite controlar la frecuencia con la que se realiza la tarea, evitando que se ejecute de forma excesivamente rápida o innecesaria, y ajustando la frecuencia a las necesidades de la aplicación. Por ejemplo, si un hilo debe comprobar el estado de un sensor cada minuto, después de cada comprobación, el hilo puede dormirse durante aproximadamente un minuto, liberando la CPU durante ese tiempo y asegurando que la siguiente comprobación se realice aproximadamente un minuto después.
- **Simular esperas o retrasos en la ejecución**: En pruebas, simulaciones o demos de aplicaciones multihilo, puede ser útil introducir retrasos artificiales en la ejecución de ciertos hilos para simular condiciones de carga, latencia o espera en el sistema. Dormir un hilo es una forma sencilla de simular estos retrasos y observar el comportamiento de la aplicación en diferentes escenarios.

> [!definition] Uso de Thread.sleep()
> Nosotros usaremos `Thread.sleep()` para simular tareas que tardan un determinado tiempo en ejecutarse

## 2. Dormir un hilo

![Dormir un hilo](https://educacionadistancia.juntadeandalucia.es/centros/cadiz/pluginfile.php/242057/mod_resource/content/10/files/thread_sleep.png)
*Dormir un hilo*

Para dormir un hilo en Java, podemos utilizar el método estático `Thread.sleep(long milliseconds)`, que recibe como argumento un valor entero que indica el número de milisegundos que queremos que el hilo suspenda su ejecución. Cuando se invoca el método `Thread.sleep(milliseconds)` desde un hilo, el hilo que está ejecutando la llamada libera la CPU y pasa al estado de suspendido por tiempo (_time waiting_) durante el tiempo especificado. Durante este tiempo, el hilo no consume tiempo de CPU y no puede ejecutarse. La CPU queda libre para ejecutar otros hilos o procesos.

Una vez que transcurre el tiempo indicado (o si el hilo es interrumpido antes de tiempo, como veremos más adelante), el hilo vuelve a estar listo para ejecutarse (pasa al estado listo o ejecutable), y continuará su ejecución en la instrucción siguiente a la llamada a `sleep()`, tan pronto como el planificador de hilos (_scheduler_) del sistema operativo le asigne tiempo de CPU (lo ponga en estado "en ejecución").

Java 19 trajo consigo una nueva versión del método estático `Thread.sleep(Duration duration)`, que recibe un objeto `Duration` con el que se indica el tiempo que se desea "dormir" el hilo.

Existe otra posibilidad alternativa y más flexible para dormir un hilo, que consiste en utilizar el método `sleep()` de algún elemento de la enumeración `TimeUnit`, definida en el paquete `java.util.concurrent`. La enumeración `TimeUnit` proporciona una serie de constantes que representan diferentes unidades de tiempo (como segundos, milisegundos, nanosegundos, minutos, horas, días), y cada constante de `TimeUnit` tiene un método `sleep(long tiempo)` que permite dormir el hilo durante el tiempo especificado en la unidad de tiempo correspondiente a esa constante, en lugar de tener que especificar el tiempo siempre en milisegundos como en `Thread.sleep(milliseconds)`. Por ejemplo: `TimeUnit.SECONDS.sleep(1)`, `TimeUnit.MILLISECONDS.sleep(100)`, `TimeUnit.MINUTES.sleep(5)`, etc.

Utilizar `TimeUnit.unidad.sleep(tiempo)` puede ser más legible y expresivo que utilizar `Thread.sleep(milisegundos)`, especialmente cuando se quieren especificar tiempos de suspensión en unidades diferentes a milisegundos (como segundos, minutos, horas, etc.).

## 3. Interacción con el mecanismo de interrupción

Un aspecto muy importante a tener en cuenta al utilizar `Thread.sleep()` (o `TimeUnit.unidad.sleep()`) es su interacción con el mecanismo de interrupción de hilos. Como vimos en el apartado anterior, si un hilo es marcado como interrumpido (con `thread.interrupt()`), y ese hilo intenta ejecutar una operación bloqueante, como `sleep()`, la operación bloqueante no se completará de forma normal, sino que lanzará inmediatamente la excepción `InterruptedException`.

Esto ocurre incluso si el hilo ya estaba dormido (bloqueado en `sleep()`) y se le marca como interrumpido desde otro hilo. En ese caso, el hilo se despertará inmediatamente de su estado de dormido y se le lanzará la excepción `InterruptedException`, sin esperar a que concluya el tiempo durante el cual el hilo debía estar dormido. Es decir, si se interrumpe un hilo mientras está dormido con `sleep()`, la interrupción tiene prioridad sobre el tiempo de suspensión, y el hilo se despierta inmediatamente y es notificado de la interrupción mediante la excepción `InterruptedException`.

Además, es importante recordar que, cuando se lanza la excepción `InterruptedException` en respuesta a una interrupción durante `sleep()`, la marca de interrupción del hilo se limpia (se establece a `false`). Esto significa que, si se quiere que la señal de interrupción se mantenga activa después de capturar la excepción `InterruptedException`, es necesario restaurar manualmente la marca de interrupción llamando de nuevo a `Thread.currentThread().interrupt()` dentro del bloque catch de `InterruptedException`.

## 4. El método yield()

> [!warning] Aviso
> No se recomienda el uso del método `yield()`

La clase `Thread` posee otro método llamado `yield()` (que significa "ceder") que parece a primera vista que podría servir para liberar voluntariamente la CPU y dar oportunidad a otros hilos de ejecutarse. El método `yield()` intenta hacer que el hilo que lo invoca ceda voluntariamente el uso de la CPU al planificador de hilos (scheduler) del sistema operativo, sugiriendo que el hilo actual está dispuesto a dejar de ejecutarse temporalmente para que otros hilos iguales o de mayor prioridad puedan tener la oportunidad de ejecutarse.

Sin embargo, es fundamental entender que la JVM no garantiza que dicha cesión se lleve a cabo siempre ni de forma inmediata. El comportamiento exacto del método yield() es altamente dependiente de la implementación de la JVM y del sistema operativo subyacente. La JVM puede ignorar completamente la llamada a `yield()` y seguir ejecutando el hilo que lo invocó sin ceder la CPU, o puede intentar ceder la CPU, pero sin ninguna garantía de que otros hilos realmente vayan a ser ejecutados inmediatamente después. En muchos casos, la llamada a `yield()` puede no tener ningún efecto perceptible en el comportamiento de la aplicación multihilo.

Debido a esta falta de garantías y a su comportamiento impredecible y dependiente de la plataforma, el método `yield()` no se considera una herramienta fiable ni útil para la programación multihilo en Java. Utilizar `yield()` para intentar controlar el flujo de ejecución de los hilos o para mejorar el rendimiento de la aplicación es generalmente ineficaz y puede llevar a comportamientos inesperados y difíciles de depurar, por lo que se recomienda no usar este método.

En la gran mayoría de los casos, existen alternativas mucho más adecuadas y fiables para lograr los objetivos que teóricamente se podrían intentar conseguir con `yield()`, como por ejemplo, utilizar mecanismos de sincronización adecuados (monitores, cerrojos, colas concurrentes, etc.) para controlar el acceso a recursos compartidos y la coordinación entre hilos, o utilizar `Thread.sleep()` para introducir pausas temporales controladas en la ejecución de los hilos.

## 5. Precisión de sleep()

Es importante tener en cuenta que el tiempo de suspensión especificado en `Thread.sleep()` es un valor aproximado y no una garantía de precisión absoluta. El tiempo real que el hilo permanece dormido puede ser igual o ligeramente mayor al valor especificado, pero nunca menor. La precisión de `sleep()` depende de la granularidad del reloj del sistema operativo y de la carga del sistema. En sistemas operativos en tiempo real, la precisión del `sleep()` puede ser mayor, pero en sistemas operativos de propósito general, la precisión puede ser menor. En general, podemos considerar que `Thread.sleep()` proporciona una suspensión temporal razonablemente precisa para la mayoría de las aplicaciones Java, pero no debemos confiar en una precisión milimétrica o en tiempo real.

## 6. Proyecto Clock

En este proyecto vamos a desarrollar un programa sencillo que ilustra el uso del método `Thread.sleep()` para introducir pausas temporales en la ejecución de un hilo y para implementar tareas periódicas. Crearemos un hilo que simule un reloj digital, mostrando por pantalla la hora actual (horas, minutos y segundos) cada segundo. Para lograr esto, utilizaremos el método `sleep()` para dormir el hilo durante un segundo entre cada muestra de la hora, creando así un bucle de ejecución periódica que se repite aproximadamente cada segundo. Además, transcurridos unos segundos, el hilo principal interrumpirá al hilo reloj utilizando el mecanismo de interrupción que vimos en el apartado anterior, para detener la ejecución del reloj de forma controlada.

**Proyecto Clock** · [▶ Replit](https://repl.it/@PedroJoya/PR006-Clock)

> [!warning] Código incompleto
> En Moodle el proyecto tiene las pestañas `Main`, `SecondsHand`, pero al copiarlo solo se guardó **`Main`**.

`Main.java`
```java
import java.util.concurrent.TimeUnit;

public class Main {

    public static void main(String[] args) throws InterruptedException {
        Thread thread = new Thread(new SecondsHand(), "Seconds hand");
        thread.start();
        TimeUnit.SECONDS.sleep(5);
        thread.interrupt();
    }

}
```

Si ejecutamos el programa veremos que se va mostrando la hora segundo a segundo hasta que pasan 5 segundos, momento en el que el hilo principal interrumpe al hilo secundario.

|---|---|---|
