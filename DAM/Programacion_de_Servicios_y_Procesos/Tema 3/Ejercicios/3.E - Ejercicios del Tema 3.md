## Ejercicio 3.1 · Tablas de potencias con 10 hilos

> [!question] Enunciado (copiado de Moodle)
> 1. Lee los apartados 3.1 y 3.2 de los apuntes (ambos inclusive).
> 2. Visualiza los vídeos del 09 al 11, 16 y 17 de la lista de vídeos del Tema 1 y de la lista de vídeos del Tema 3.
> 3. Realiza una aplicación parecida a la del Proyecto Thread del apartado 3.2 pero que en vez de mostrar las tablas de multiplicar, muestre las tablas de potencia de ese número. El hilo principal debe crear e iniciar 10 hilos distintos, cada uno de los cuales debe mostrar la tabla de potencias de un número. Por ejemplo el hilo correspondiente al número 2 deberá mostrar por pantalla:
> ```text
> 2 ^ 0 = 1
> 2 ^ 1 = 2
> 2 ^ 2 = 4
> 2 ^ 3 = 8
> .... (así hasta 2 ^ 10)
> ```

> [!info] Proyecto
> **Proyecto IntelliJ:** `Tema3_Ejercicio1`
> **Ruta fuente:** `/home/dublem/Documentos/Programas_clase/procesos/Tema3_Ejercicio1/src/`
> **Lectura (puntos 1 y 2):** [[3.1 - Introduccion]] y [[3.2 - Thread]]. Los vídeos están enlazados en los callouts `Vídeo` de los apuntes.

### Punto de partida: el Proyecto Thread de los apuntes

En [[3.2 - Thread#7. Proyecto Thread|3.2 → Proyecto Thread]] se muestran las tablas de multiplicar del 1 al 10 con **un hilo por tabla**:

- `MultiplicationTable` **extiende `Thread`**, recibe su número en el constructor y escribe su tabla en `run()`.
- `Main` crea las 10 tablas en un bucle y llama a `start()` en cada una.

El ejercicio pide lo mismo cambiando la multiplicación por la potencia. Así que la solución calca esa estructura: `PowerTable` hace el papel de `MultiplicationTable`.

> [!example] Analogía
> El hilo principal es un jefe de cocina que reparte 10 comandas a 10 cocineros y se va. Cada cocinero (`PowerTable`) prepara su plato (su tabla) a su ritmo. Como **trabajan a la vez**, los platos no tienen por qué salir en el orden en que se repartieron las comandas.

### Clases y métodos introducidos

| Elemento | Para qué se usa aquí | Apuntes |
|---|---|---|
| `class PowerTable extends Thread` | Cada objeto es un hilo | [[3.2 - Thread#1. La clase Thread\|3.2 → La clase Thread]] |
| `@Override public void run()` | Código que ejecutará el hilo | [[3.2 - Thread#1. La clase Thread\|3.2 → La clase Thread]] |
| `start()` | Crea el hilo en el SO y llama a `run()` en él | [[3.2 - Thread#1. La clase Thread\|3.2 → La clase Thread]] |
| Estados `NEW` → `RUNNABLE` → `TERMINATED` | Ciclo de vida de cada `PowerTable` | [[3.1 - Introduccion#7. Estados de un hilo\|3.1 → Estados de un hilo]] |

### Código fuente (`Tema3_Ejercicio1/src/PowerTable.java`)

```java
// Hilo que muestra la tabla de potencias de un número (exponentes del 0 al 10)
public class PowerTable extends Thread {

    private static final int MAX_EXPONENT = 10;

    private final int number;

    public PowerTable(int number) {
        this.number = number;
    }

    // Código que ejecuta el hilo nuevo cuando se llama a start()
    @Override
    public void run() {
        long power = 1; // number ^ 0 = 1
        for (int exponent = 0; exponent <= MAX_EXPONENT; exponent++) {
            System.out.printf("%d ^ %d = %d\n", number, exponent, power);
            power *= number; // la siguiente potencia es la actual por el número
        }
    }

}
```

### Código fuente (`Tema3_Ejercicio1/src/Main.java`)

```java
public class Main {

    private static final int LAST_NUMBER = 10;

    public static void main(String[] args) {
        for (int i = 1; i <= LAST_NUMBER; i++) {
            PowerTable table = new PowerTable(i);
            table.start();
            // start() NO bloquea al hilo principal, que sigue con la siguiente
            // vuelta del bucle mientras el hilo creado se ejecuta concurrentemente.
        }
        // El hilo principal termina aquí, pero el programa sigue ejecutándose
        // hasta que terminen los 10 hilos PowerTable.
    }

}
```

### Explicación paso a paso

**`PowerTable`, el hilo**

1. **`extends Thread`.** Es la primera forma de crear hilos que dan los apuntes: una clase que hereda de `Thread` y sobrescribe `run()` (ver [[Programación basica/Tema 7/Herencia#3. Sobrecarga y anulación de métodos|Herencia → 3. Sobrecarga y anulación de métodos]]). En el apartado 3.3 se verá la alternativa recomendada, `Runnable`, que evita gastar la única herencia de la clase.
2. **Atributo `number` + constructor.** El hilo necesita saber de qué número es su tabla. Como `run()` no recibe parámetros, el dato se pasa por el constructor y se guarda como atributo, igual que hace `MultiplicationTable`. Es `final` porque no cambia.
3. **`run()` con `@Override`.** Es el código que se ejecutará **en el hilo nuevo**. La anotación hace que el compilador avise si nos equivocamos con el nombre (por ejemplo `Run()`), porque entonces no estaríamos sobrescribiendo nada y el hilo no haría nada.
4. **Potencias sin `Math.pow`.** Se empieza en `power = 1` (todo número elevado a 0 es 1) y en cada vuelta se multiplica por el número: 1 → 2 → 4 → 8… `Math.pow` devuelve `double` y mostraría `1024.0`.
5. **`long` y no `int`.** La potencia mayor es `10 ^ 10 = 10000000000`, que no cabe en un `int` (máximo ≈ 2 147 483 647). Con `int` saldría un número sin sentido (desbordamiento).
6. **`printf` con `%d`.** Escribe una línea completa con el formato del enunciado (`2 ^ 3 = 8`). Es el mismo estilo que usa el Proyecto Runnable de los apuntes.

**`Main`, el hilo principal**

1. **`main` se ejecuta en el hilo `main`**, que crea la JVM al arrancar el programa ([[3.3 - Runnable#6. Proyecto Runnable|3.3 → Proyecto Runnable]] lo muestra con `Thread.currentThread().getName()`).
2. **`new PowerTable(i)` deja el hilo en estado `NEW`.** Es solo un objeto: todavía no existe ningún hilo en el sistema operativo.
3. **`start()` lo pasa a `RUNNABLE`.** Ahora sí se crea el hilo, y la JVM llamará a `run()` dentro de él cuando el planificador le dé CPU. `start()` vuelve enseguida: el bucle sigue creando hilos sin esperar a que acaben los anteriores.
4. **`main` termina antes que los hilos**, pero el programa no acaba ahí: un proceso sigue vivo mientras quede algún hilo que no sea daemon (ver [[3.2 - Thread#4. ¿Cuándo finaliza un proceso con varios hilos?|3.2 → ¿Cuándo finaliza un proceso con varios hilos?]]). Cada `PowerTable` pasa a `TERMINATED` al salir de `run()`.

> [!warning] Error típico: `run()` en lugar de `start()`
> `table.run()` compila y "funciona", pero no crea ningún hilo: `run()` se ejecuta en el hilo principal como un método normal y las tablas salen siempre en orden, del 1 al 10. Es el aviso *Nunca hagas esto* de [[3.2 - Thread#1. La clase Thread|3.2 → La clase Thread]].

Desde IntelliJ: abrir la carpeta `Tema3_Ejercicio1` y ejecutar `Main`. Desde terminal:

```bash

javac Main.java PowerTable.java
java Main
```

#### Ejemplo

Salen 110 líneas (10 hilos × 11 potencias). Para no copiarlas todas, esto es el **número de líneas seguidas de cada tabla** en tres ejecuciones reales:

```text
Ejecución 1:  2 (11) · 1 (11) · 3 (11) · 4 (11) · 5 (11) · 6 (11) · 7 (11) · 8 (11) · 9 (11) · 10 (11)
Ejecución 2:  2 (11) · 1 (11) · 3 (11) · 4 (11) · 5 (4) · 6 (11) · 7 (11) · 8 (11) · 9 (11) · 10 (11) · 5 (7)
Ejecución 3:  1 (11) · 2 (7) · 3 (11) · 4 (11) · 5 (11) · 6 (11) · 7 (11) · 8 (11) · 9 (11) · 10 (11) · 2 (4)
```

En la ejecución 2, la tabla del 5 se corta tras 4 líneas y sus 7 últimas salen al final. El hilo del 2, por ejemplo, siempre escribe:

```text
2 ^ 0 = 1
2 ^ 1 = 2
2 ^ 2 = 4
...
2 ^ 10 = 1024
```

> [!tip] Cómo interpretar la salida
> - **El orden de las tablas cambia entre ejecuciones** (a veces empieza la del 2 y no la del 1). Lo decide el planificador del sistema operativo, no el orden del bucle: es el comportamiento no determinista que describe [[3.2 - Thread#7. Proyecto Thread|3.2 → Proyecto Thread]] y el orden parcial de [[1.5 - Orden de ejecucion#1. Orden total vs. orden parcial|1.5 → Orden total vs. orden parcial]].
> - **Casi siempre las tablas salen enteras.** Cada hilo hace muy poco trabajo (11 líneas) y suele terminar antes de que el planificador le quite la CPU. Aun así, a veces un hilo se interrumpe a mitad y su tabla queda partida (el 5 en la ejecución 2). Si cada tabla fuese más larga o hubiera más núcleos ocupados, la mezcla sería mucho mayor.
> - **Dentro de un hilo el orden siempre se respeta**: `2 ^ 3` sale siempre después de `2 ^ 2`.
> - Cada línea sale entera y sin mezclarse con otras porque `System.out` sincroniza cada llamada de escritura.

> [!note] ¿Y si quisiera las tablas siempre en orden?
> Habría que hacer que `main` esperase a cada hilo con `join()` antes de lanzar el siguiente ([[3.7 - Esperar la finalización]]), pero entonces los hilos no trabajarían a la vez. El enunciado solo pide crear e iniciar los 10 hilos, así que la salida mezclada es la esperada.

## Ejercicio 3.2 · Tablas de potencias con Runnable, nombres y prioridades

> También deberás proporcionar más prioridad a los hilos correspondientes a los número pares que los hilos correspondientes a números impares. Por ejemplo, el hilo correspondiente al número 2 deberá tener más prioridad que el correspondiente al número 1.

### Punto de partida: los proyectos Runnable y Priority

El ejercicio junta tres cosas de los apuntes sobre el ejercicio 3.1:

| Qué pide | De dónde sale | Cambio respecto al 3.1 |
|---|---|---|
| Usar `Runnable` en vez de heredar de `Thread` | [[3.3 - Runnable#6. Proyecto Runnable\|3.3 → Proyecto Runnable]] | `PowerTable implements Runnable` y `Main` crea un `Thread` para cada tarea |
| Mostrar el nombre del hilo | [[3.3 - Runnable#3. Acceso desde el Runnable al hilo\|3.3 → Acceso desde el Runnable al hilo]] | `Thread.currentThread().getName()` dentro de `run()` |
| Pares con más prioridad | [[3.4 - Prioridad#3. Proyecto Priority\|3.4 → Proyecto Priority]] | `setPriority(MAX_PRIORITY)` a los pares y `MIN_PRIORITY` a los impares |

> [!example] Analogía
> En el 3.1 cada cocinero *era* su receta (`PowerTable` **era** un `Thread`). Ahora separamos la **receta** (`PowerTable`, el `Runnable`: qué hay que hacer) del **cocinero** (`Thread`: quién lo hace). A cada cocinero se le pone un nombre en la chaqueta (`"Thread-2"`) y a algunos se les dice "tú eres más importante" (prioridad)… aunque el jefe de sala, el planificador del SO, puede no hacer caso.

### Clases y métodos introducidos

| Elemento | Para qué se usa aquí | Apuntes |
|---|---|---|
| `class PowerTable implements Runnable` | Define la tarea, no el hilo | [[3.3 - Runnable#1. La interfaz Runnable\|3.3 → La interfaz Runnable]] |
| `new Thread(Runnable, String nombre)` | Crea el hilo que ejecutará la tarea, con su nombre | [[3.3 - Runnable#2. Creación de un hilo que ejecute un Runnable\|3.3 → Creación de un hilo que ejecute un Runnable]] |
| `Thread.currentThread().getName()` | Saber desde la tarea en qué hilo se ejecuta | [[3.3 - Runnable#3. Acceso desde el Runnable al hilo\|3.3 → Acceso desde el Runnable al hilo]] |
| `setPriority(...)` · `MAX_PRIORITY` · `MIN_PRIORITY` | Prioridad 10 para pares y 1 para impares | [[3.4 - Prioridad#1. Prioridad en los hilos\|3.4 → Prioridad en los hilos]] |

### Código fuente (`Tema3_Ejercicio2/src/PowerTable.java`)

```java
// Tarea que muestra la tabla de potencias de un número (exponentes del 0 al 10)
public class PowerTable implements Runnable {

    private static final int MAX_EXPONENT = 10;

    private final int number;

    public PowerTable(int number) {
        this.number = number;
    }

    // Código que ejecuta el hilo al que se le pasa esta tarea
    @Override
    public void run() {
        // Nombre del hilo que está ejecutando esta tarea
        String threadName = Thread.currentThread().getName();
        long power = 1; // number ^ 0 = 1
        for (int exponent = 0; exponent <= MAX_EXPONENT; exponent++) {
            System.out.printf("%s: %d ^ %d = %d\n", threadName, number, exponent, power);
            power *= number; // la siguiente potencia es la actual por el número
        }
    }

}
```

### Código fuente (`Tema3_Ejercicio2/src/Main.java`)

```java
public class Main {

    private static final int LAST_NUMBER = 10;

    public static void main(String[] args) {
        for (int i = 1; i <= LAST_NUMBER; i++) {
            // El hilo se llama "Thread-i" para que coincida con su número
            Thread thread = new Thread(new PowerTable(i), "Thread-" + i);
            // Más prioridad para los números pares que para los impares
            if ((i % 2) == 0) {
                thread.setPriority(Thread.MAX_PRIORITY);
            } else {
                thread.setPriority(Thread.MIN_PRIORITY);
            }
            thread.start();
        }
    }

}
```

### Explicación paso a paso

**`PowerTable`, ahora una tarea**

1. **`implements Runnable` en vez de `extends Thread`.** `PowerTable` ya no es un hilo: es solo el trabajo que hará un hilo. La ventaja es que la clase sigue libre para heredar de otra, porque en Java solo se hereda de una clase (ver [[3.3 - Runnable#4. Beneficios de Runnable|3.3 → Beneficios de Runnable]] y [[Programación basica/Tema 7/Herencia#12. Interfaces|Herencia → 12. Interfaces]]).
2. **El resto de la clase no cambia.** El número sigue llegando por el constructor y guardándose en un atributo. Por eso no se usa una lambda: una lambda no tiene constructor ni atributos para recibir el número (lo explica [[3.3 - Runnable#2. Creación de un hilo que ejecute un Runnable|3.3 → Creación de un hilo]]).
3. **`Thread.currentThread().getName()`.** Como `PowerTable` ya no hereda de `Thread`, no tiene un `getName()` propio. `Thread.currentThread()` devuelve el objeto `Thread` que está ejecutando esa línea, y de él se saca el nombre.
4. **El nombre se lee una vez, antes del bucle.** El hilo no cambia durante `run()`, así que no hace falta pedirlo en cada vuelta.
5. **`printf("%s: %d ^ %d = %d\n", …)`.** Añade el nombre delante de cada línea, con el formato `Thread-2: 2 ^ 3 = 8` que pide el enunciado.

**`Main`, hilos con nombre y prioridad**

1. **`new Thread(new PowerTable(i), "Thread-" + i)`.** Se crea la tarea y se le pasa a un `Thread`, que es quien la ejecutará. El segundo argumento es el nombre del hilo.
2. **¿Por qué poner el nombre a mano?** Si no se indica, la JVM numera los hilos desde 0 (`Thread-0`, `Thread-1`…). La tabla del 1 iría en `Thread-0` y la del 2 en `Thread-1`, sin coincidir con el ejemplo del enunciado (`"Thread-2"` para el 2).
3. **Prioridad según la paridad.** `(i % 2) == 0` es verdadero para los pares, que reciben `Thread.MAX_PRIORITY` (10). Los impares reciben `Thread.MIN_PRIORITY` (1). Es el mismo `if` del Proyecto Priority. La prioridad se pone **antes** de `start()`, para que el hilo arranque ya con ella.
4. **`thread.start()`.** Igual que en el 3.1: crea el hilo y este ejecuta el `run()` de su `PowerTable`.

> [!warning] Nombre por defecto
> Si en `Main` usaras `new Thread(new PowerTable(i))` sin nombre, saldría `Thread-1: 2 ^ 0 = 1`: el número del hilo no coincidiría con el de la tabla.

#### Ejemplo

Salen 110 líneas, cada una con el nombre de su hilo. El hilo del 2:

```text
Thread-2: 2 ^ 0 = 1
Thread-2: 2 ^ 1 = 2
Thread-2: 2 ^ 2 = 4
...
Thread-2: 2 ^ 10 = 1024
```

Bloques de líneas seguidas de cada hilo en tres ejecuciones reales:

```text
Ejecución 1:  Thread-1 (11) · Thread-2 (7) · Thread-3 (11) · Thread-4 (11) · … · Thread-10 (11) · Thread-2 (4)
Ejecución 2:  Thread-1 (11) · Thread-2 (11) · Thread-3 (11) · Thread-4 (11) · … · Thread-10 (11)
Ejecución 3:  Thread-1 (11) · Thread-2 (7) · Thread-3 (11) · Thread-4 (11) · Thread-5 (8) · … · Thread-10 (11) · Thread-2 (4) · Thread-5 (3)
```

> [!tip] Comprobación: ¿se nota la prioridad?
> **No**, y es justo lo que avisa [[3.4 - Prioridad#2. Recomendación sobre el uso de prioridades|3.4 → Recomendación sobre el uso de prioridades]]: `setPriority()` es solo una sugerencia. En las ejecuciones de arriba, `Thread-1` (prioridad 1) sale siempre el primero, y `Thread-2` (prioridad 10) hasta se queda cortado. En 30 ejecuciones seguidas, las líneas de los hilos pares salieron de media en la posición 62 de 110 y las de los impares en la 49: los pares no se adelantan.
>
> Hay dos motivos:
> - **Los hilos se crean en orden y tienen muy poco trabajo.** El del 1 se lanza primero y casi siempre acaba antes de que arranquen los demás, sea cual sea su prioridad.
> - **En Linux, la JVM ignora las prioridades por defecto.** Con la opción `ThreadPriorityPolicy=0` (la de serie), todos los hilos se ejecutan con la prioridad normal del sistema operativo. Puedes ver el valor con `java -XX:+PrintFlagsFinal -version | grep ThreadPriorityPolicy`.
>
> Para comprobar que la prioridad **sí se ha asignado** en Java, añade `Thread.currentThread().getPriority()` al `printf`: saldrá 10 en los pares y 1 en los impares.

## Ejercicio 3.3 · Cronómetro interrumpible

> [!question] Enunciado (copiado de Moodle)
> Realiza un programa principal que muestre un mensaje por pantalla que diga: Pulsa Intro para comenzar el cronómetro.
> Cuando el usuario pulse Intro, el hilo principal creará uno secundario cuyo cometido es mostrar la hora actual cada segundo de manera infinita hasta que sea interrumpido.
> El hilo principal una vez lanzado el hilo secundario, deberá mostrar un mensaje que diga: Cronómetro en ejecución. Esperando 5 segundos.
> Después de eso, el hilo principal se echará a dormir durante 5 segundos y transcurrido los cuales, deberá interrumpir al hilo secundario correspondiente al cronómetro.
> El hilo del cronometro cuando sea interrumpido, tendrá que mostrar un mensaje diciendo: Me han parado
> El hilo principal después de interrumpir al cronometro, deberá mostrar un mensaje diciendo: Cronometro terminado, hasta luego
> Todos los mensajes deben mostrar antes del texto el nombre del hilo desde el que se ejecutan y el hilo cronometro debes implementarlo usando la interfaz runnable

> [!info] Proyecto
> **Proyecto IntelliJ:** `Tema3_Ejercicio3`
> **Ruta fuente:** `/home/dublem/Documentos/Programas_clase/procesos/Tema3_Ejercicio3/src/`
> **Apuntes:** [[3.5 - Interrumpir]], [[3.6 - Dormir]] y [[3.7 - Esperar la finalización]].

### Punto de partida: los proyectos Clock e Interrupt

El ejercicio es casi el **Proyecto Clock** de [[3.6 - Dormir#6. Proyecto Clock|3.6 → Proyecto Clock]]: un hilo muestra la hora cada segundo y el principal lo interrumpe pasados 5 segundos. Lo que se añade:

| Qué pide | De dónde sale |
|---|---|
| Bucle "infinito hasta que sea interrumpido" | `while (!isInterrupted())` de [[3.5 - Interrumpir#3. Comprobación de haber sido interrumpido\|3.5 → Comprobación de haber sido interrumpido]] |
| Dormir 1 s entre horas y 5 s en el principal | `TimeUnit.SECONDS.sleep()` de [[3.6 - Dormir#2. Dormir un hilo\|3.6 → Dormir un hilo]] |
| Interrumpir al cronómetro | `interrupt()` del [[3.5 - Interrumpir#6. Proyecto Interrupt\|3.5 → Proyecto Interrupt]] |
| Nombre del hilo en cada mensaje | `Thread.currentThread().getName()` del [[#Ejercicio 3.2 · Tablas de potencias con Runnable, nombres y prioridades\|ejercicio 3.2]] |
| Esperar a la tecla Intro | `Scanner.nextLine()` |

> [!example] Analogía
> El hilo principal es un entrenador con un silbato. Pone en marcha al corredor (el cronómetro), se sienta 5 segundos y luego pita (`interrupt()`). El pitido no tumba al corredor: este lo **oye** (comprueba el _flag_ o recibe la `InterruptedException`), dice "me han parado" y se retira por su cuenta. Es la interrupción **cooperativa** del 3.5.

### Clases y métodos introducidos

| Elemento | Para qué se usa aquí | Apuntes |
|---|---|---|
| `Thread.currentThread().isInterrupted()` | Condición del bucle del cronómetro | [[3.5 - Interrumpir#3. Comprobación de haber sido interrumpido\|3.5 → Comprobación de haber sido interrumpido]] |
| `hilo.interrupt()` | El principal pide al cronómetro que pare | [[3.5 - Interrumpir#2. Mecanismo de interrupción\|3.5 → Mecanismo de interrupción]] |
| `TimeUnit.SECONDS.sleep(n)` | Pausas de 1 s y de 5 s | [[3.6 - Dormir#2. Dormir un hilo\|3.6 → Dormir un hilo]] |
| `InterruptedException` | Salta si interrumpen al hilo mientras duerme | [[3.6 - Dormir#3. Interacción con el mecanismo de interrupción\|3.6 → Interacción con el mecanismo de interrupción]] |
| `hilo.join()` | El principal espera a que el cronómetro termine | [[3.7 - Esperar la finalización#2. Esperar la finalización de un hilo\|3.7 → Esperar la finalización de un hilo]] |
| `LocalTime.now()` + `DateTimeFormatter` | Hora actual con formato `HH:mm:ss` | — |

### Código fuente (`Tema3_Ejercicio3/src/Clock.java`)

```java
import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.util.concurrent.TimeUnit;

// Tarea que muestra la hora actual cada segundo hasta que interrumpen su hilo
public class Clock implements Runnable {

    private static final DateTimeFormatter TIME_FORMAT = DateTimeFormatter.ofPattern("HH:mm:ss");

    @Override
    public void run() {
        String threadName = Thread.currentThread().getName();
        while (!Thread.currentThread().isInterrupted()) {
            System.out.printf("%s: %s\n", threadName, LocalTime.now().format(TIME_FORMAT));
            try {
                TimeUnit.SECONDS.sleep(1);
            } catch (InterruptedException e) {
                // sleep() limpia el flag al lanzar la excepción: se vuelve a marcar
                // para que el while detecte la interrupción y termine el bucle
                Thread.currentThread().interrupt();
            }
        }
        System.out.printf("%s: Me han parado\n", threadName);
    }

}
```

### Código fuente (`Tema3_Ejercicio3/src/Main.java`)

```java
import java.util.Scanner;
import java.util.concurrent.TimeUnit;

public class Main {

    private static final int WAITING_SECONDS = 5;

    public static void main(String[] args) throws InterruptedException {
        String threadName = Thread.currentThread().getName();
        Scanner scanner = new Scanner(System.in);

        System.out.printf("%s: Pulsa Intro para comenzar el cronómetro\n", threadName);
        scanner.nextLine();

        Thread clockThread = new Thread(new Clock(), "Cronómetro");
        clockThread.start();
        System.out.printf("%s: Cronómetro en ejecución. Esperando %d segundos.\n", threadName, WAITING_SECONDS);

        TimeUnit.SECONDS.sleep(WAITING_SECONDS);
        clockThread.interrupt();
        // Se espera a que el cronómetro termine para que su "Me han parado"
        // salga siempre antes que la despedida del hilo principal
        clockThread.join();

        System.out.printf("%s: Cronometro terminado, hasta luego\n", threadName);
    }

}
```

### Explicación paso a paso

**`Clock`, la tarea del cronómetro**

1. **`implements Runnable`.** Lo exige el enunciado. Como en el 3.2, la clase es solo el trabajo: el hilo lo crea `Main`.
2. **Formato de la hora.** `LocalTime.now()` da la hora actual con nanosegundos (`13:50:34.123456789`). `DateTimeFormatter.ofPattern("HH:mm:ss")` la deja en `13:50:34`. El formateador va en una constante `static final` porque es el mismo para todas las líneas.
3. **`while (!Thread.currentThread().isInterrupted())`.** Es el "de manera infinita hasta que sea interrumpido": el bucle da vueltas mientras el _flag_ de interrupción esté a `false`. Se usa `isInterrupted()` y no `Thread.interrupted()` porque solo consulta el _flag_, sin borrarlo (el consejo de [[3.5 - Interrumpir#4. El método estático Thread.interrupted()|3.5 → Thread.interrupted()]]).
4. **`TimeUnit.SECONDS.sleep(1)`.** Duerme el hilo un segundo entre una hora y la siguiente. Mientras duerme está en estado _timed waiting_ y no gasta CPU.
5. **El `catch` de `InterruptedException`.** El cronómetro pasa casi todo el tiempo dentro de `sleep()`, así que la interrupción le llegará casi seguro mientras duerme. En ese caso `sleep()` **lanza `InterruptedException` y pone el _flag_ otra vez a `false`**. Si el `catch` no hiciera nada, el `while` vería `false` y el reloj seguiría para siempre. Por eso se llama a `Thread.currentThread().interrupt()`: restaura el _flag_, tal como recomienda [[3.5 - Interrumpir#5. Interrupción y métodos bloqueantes|3.5 → Interrupción y métodos bloqueantes]].
6. **"Me han parado" después del bucle.** Se llega ahí tanto si la interrupción llegó durante `sleep()` (vía `catch`) como si llegó justo mientras se escribía la hora (el `while` la ve directamente). Con el mensaje fuera del `catch`, sale una sola vez en los dos casos.

**`Main`, el hilo principal**

1. **Nombre del hilo.** `Thread.currentThread().getName()` vale `main` en el hilo principal. Se guarda al principio porque se usa en todos los mensajes.
2. **Esperar a Intro.** `scanner.nextLine()` bloquea al hilo principal hasta que el usuario pulsa Intro. No se lee lo escrito: solo interesa la pulsación.
3. **Crear y lanzar el cronómetro.** `new Thread(new Clock(), "Cronómetro")` le da nombre al hilo, así sus mensajes salen como `Cronómetro: 13:50:34`. Después, `start()` y el mensaje "Cronómetro en ejecución…".
4. **`TimeUnit.SECONDS.sleep(5)`.** El principal se duerme 5 segundos mientras el cronómetro trabaja. `main` declara `throws InterruptedException` (como el Proyecto Clock), porque nadie va a interrumpir al hilo principal.
5. **`clockThread.interrupt()`.** Activa el _flag_ del cronómetro. No lo para a la fuerza: es el propio cronómetro el que reacciona.
6. **`clockThread.join()`.** Espera a que el cronómetro escriba "Me han parado" y termine. Sin él, los dos últimos mensajes los escriben dos hilos a la vez y **el orden no está garantizado**: a veces la despedida del principal saldría antes que el "Me han parado".
7. **Despedida.** "Cronometro terminado, hasta luego", con el texto exacto del enunciado (sin tilde).

> [!warning] Error típico: un `catch` que no restaura el _flag_
> ```java
> } catch (InterruptedException e) {
>     // vacío
> }
> ```
> El reloj **no se para nunca**: `sleep()` ha borrado el _flag_, el `while` sigue viendo `false` y el programa no acaba. Las dos soluciones correctas son restaurar el _flag_ (lo que se hace aquí) o salir con `return`/`break` desde el `catch`.

## Ejercicio 3.4 · Suma de una matriz con un hilo por fila

> [!question] Enunciado (copiado de Moodle)
> Realiza una aplicación en la que construyas una matriz 5x5 de enteros, después rellénala con números aleatorios de 0 a 9, después recórrela y calcula la suma de todos los números. Este valor nos servirá solo para comprobación.
> El hilo principal tiene que crear 5 hilos sumadores de manera que cada hilo sumador debe sumar 1 fila de la matriz y almacenar en una propiedad suya el resultado de la suma de los valores de dicha fila.
> El hilo principal después de lanzar los hilos secundarios debe mostrar un mensaje diciendo "Sumadores iniciados" y después debe esperar a que cada uno de los sumadores terminen su ejecución.
> Cuando todos terminen deberá obtener de cada sumador la suma correspondiente a cada fila y finalmente calcular la suma total de la matriz a partir de las sumas parciales y comprobar que se obtiene el mismo valor que habíamos calculado de manera secuencial.
> Para simular que el cálculo es costoso en los sumadores, cada vez que acumule el valor de una celda deberá dormir 0,5 segundos.

> [!info] Proyecto
> **Proyecto IntelliJ:** `Tema3_Ejercicio4`
> **Ruta fuente:** `/home/dublem/Documentos/Programas_clase/procesos/Tema3_Ejercicio4/src/`
> **Apuntes:** [[3.7 - Esperar la finalización]], [[3.3 - Runnable]] y [[3.6 - Dormir]].

### Punto de partida: el Proyecto Join y el patrón equipo de trabajo

- **Lanzar varios hilos y esperarlos a todos** es el [[3.7 - Esperar la finalización#5. Proyecto Join|3.7 → Proyecto Join]]: un array de `Thread`, un bucle que los arranca y otro bucle que hace `join()` sobre cada uno.
- **"Almacenar en una propiedad suya el resultado"** es la segunda forma de "devolver" un valor desde un `Runnable` que explica [[3.3 - Runnable#5. Cómo "retornar" un valor desde un Runnable|3.3 → Cómo "retornar" un valor desde un Runnable]]: un atributo en la clase que implementa `Runnable`, que el hilo principal lee **después** de que el hilo haya terminado.
- **Repartir los datos (una fila por hilo) y juntar al final las sumas parciales** es el patrón *equipo de trabajo* de [[3.1 - Introduccion#9.2 Patrón equipo de trabajo (Work team)|3.1 → Patrón equipo de trabajo]]. Los `join()` hacen de barrera final.

> [!example] Analogía
> Hay que contar el dinero de 5 cajas registradoras. En vez de que una persona cuente las 5 (suma secuencial), 5 empleados cuentan una caja cada uno a la vez y apuntan el total en su hoja (`sum`). El encargado dice "empezad" ("Sumadores iniciados"), espera a que **todos** le entreguen la hoja (`join()`), suma las 5 hojas y comprueba que coincide con lo que había contado él antes.

### Código fuente (`Tema3_Ejercicio4/src/Matrix.java`)

```java
import java.util.Random;

// Matriz cuadrada de enteros rellena con números aleatorios
public class Matrix {

    private static final int MAX_VALUE = 9;

    private final int[][] cells;

    public Matrix(int size) {
        cells = new int[size][size];
        Random random = new Random();
        for (int row = 0; row < size; row++) {
            for (int column = 0; column < size; column++) {
                cells[row][column] = random.nextInt(MAX_VALUE + 1); // de 0 a 9
            }
        }
    }

    public int getSize() {
        return cells.length;
    }

    public int[] getRow(int row) {
        return cells[row];
    }

    // Suma secuencial de todas las celdas (solo para comprobar el resultado)
    public int sum() {
        int total = 0;
        for (int[] row : cells) {
            for (int value : row) {
                total += value;
            }
        }
        return total;
    }

    public void show() {
        for (int[] row : cells) {
            for (int value : row) {
                System.out.print(value + " ");
            }
            System.out.println();
        }
    }

}
```

### Código fuente (`Tema3_Ejercicio4/src/RowAdder.java`)

```java
import java.util.concurrent.TimeUnit;

// Tarea que suma los valores de una fila y guarda el resultado en un atributo
public class RowAdder implements Runnable {

    private static final int CELL_DELAY_MILLIS = 500;

    private final int[] row;
    private int sum;

    public RowAdder(int[] row) {
        this.row = row;
    }

    @Override
    public void run() {
        for (int value : row) {
            sum += value;
            try {
                // Simula que acumular cada celda es un cálculo costoso
                TimeUnit.MILLISECONDS.sleep(CELL_DELAY_MILLIS);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
        }
        System.out.printf("%s: suma de la fila = %d\n", Thread.currentThread().getName(), sum);
    }

    // Solo es fiable cuando el hilo que ejecuta la tarea ha terminado (join)
    public int getSum() {
        return sum;
    }

}
```

### Código fuente (`Tema3_Ejercicio4/src/Main.java`)

```java
public class Main {

    private static final int SIZE = 5;

    public static void main(String[] args) throws InterruptedException {
        Matrix matrix = new Matrix(SIZE);
        matrix.show();
        int sequentialSum = matrix.sum();
        System.out.printf("Suma secuencial: %d\n", sequentialSum);

        // Un sumador (tarea) y un hilo por cada fila
        RowAdder[] adders = new RowAdder[SIZE];
        Thread[] threads = new Thread[SIZE];
        long start = System.currentTimeMillis();
        for (int i = 0; i < SIZE; i++) {
            adders[i] = new RowAdder(matrix.getRow(i));
            threads[i] = new Thread(adders[i], "Sumador-" + i);
            threads[i].start();
        }
        System.out.println("Sumadores iniciados");

        // Esperar a que terminen todos los sumadores
        for (int i = 0; i < SIZE; i++) {
            threads[i].join();
        }

        // Suma total a partir de las sumas parciales
        int parallelSum = 0;
        for (int i = 0; i < SIZE; i++) {
            System.out.printf("Fila %d: %d\n", i, adders[i].getSum());
            parallelSum += adders[i].getSum();
        }
        long elapsed = System.currentTimeMillis() - start;

        System.out.printf("Suma con hilos: %d (%d ms)\n", parallelSum, elapsed);
        if (parallelSum == sequentialSum) {
            System.out.println("Comprobación correcta: las dos sumas coinciden");
        } else {
            System.out.println("Error: las sumas no coinciden");
        }
    }

}
```

### Explicación paso a paso

**`Matrix`, los datos**

1. **Una clase para la matriz.** En lugar de métodos `static` auxiliares en `Main` (estilo del curso), la matriz es un objeto: su constructor la crea y la rellena, y tiene métodos de instancia para mostrarla (`show()`), sumarla en secuencia (`sum()`) y dar una fila (`getRow()`).
2. **Relleno aleatorio.** `random.nextInt(MAX_VALUE + 1)` da un entero de 0 a 9, porque `nextInt(n)` va de 0 (incluido) a `n` (excluido).
3. **`sum()` es la suma de comprobación.** Recorre todas las celdas con dos `for-each` anidados. Es el valor "solo para comprobación" del enunciado.
4. **`getRow(i)` devuelve la fila tal cual** (la referencia al array interno). Cada sumador recibe su fila y solo la **lee**, así que compartirla entre hilos no da problemas.

**`RowAdder`, el sumador**

1. **`implements Runnable` con un atributo `sum`.** Es la "propiedad suya" del enunciado. `run()` es `void` y no puede devolver la suma, así que la guarda en el atributo y el hilo principal la lee después con `getSum()`.
2. **Un `sleep(500)` por celda.** Acumula una celda y duerme medio segundo: 5 celdas = unos 2,5 s por fila. El retraso se pone en una constante en milisegundos (`CELL_DELAY_MILLIS`).
3. **El `catch`.** Si alguien interrumpiera al sumador, restaura el _flag_ y deja de sumar (como en el [[#Ejercicio 3.3 · Cronómetro interrumpible|ejercicio 3.3]]). En este programa nadie lo interrumpe, pero `sleep()` obliga a tratar la excepción.
4. **Mensaje al terminar.** Cada sumador dice su suma con su nombre (`Sumador-2: …`). No lo pide el enunciado, pero deja ver que terminan en cualquier orden.

**`Main`, el hilo principal**

1. **Matriz y suma secuencial.** Se crea la matriz, se muestra y se guarda `sequentialSum`.
2. **Dos arrays paralelos.** `adders[i]` es la tarea (para leer luego su suma) y `threads[i]` el hilo que la ejecuta (para hacer `join()`). Hace falta guardar **los dos**: del `Thread` no se puede sacar la suma, y del `RowAdder` no se puede hacer `join()`.
3. **Lanzar y avisar.** Se arrancan los 5 hilos y, justo después, "Sumadores iniciados". Como `start()` no espera, este mensaje sale casi siempre **antes** que los de los sumadores.
4. **Los `join()`.** Bloquean al principal hasta que termina cada sumador. Da igual el orden en que acaben: si el 3 termina antes que el 0, su `join()` simplemente retorna al momento.
5. **Leer las sumas parciales después de los `join()`.** Si se leyera `getSum()` sin esperar, saldría un valor a medias (o 0). Además, `join()` garantiza que el hilo principal **ve** el valor final que escribió el sumador.
6. **Comprobación.** Se suman las 5 parciales y se comparan con `sequentialSum`.
7. **Tiempo (extra).** `System.currentTimeMillis()` antes de lanzar los hilos y después de los `join()` mide cuánto tardan.

> [!warning] Error típico: leer el resultado sin `join()`
> Si quitas el bucle de `join()`, el principal lee `getSum()` mientras los sumadores siguen durmiendo: las filas salen con 0 o con sumas incompletas, y la comprobación falla.

## Esquema resumen de conceptos clave

| Concepto | Sintaxis | Comportamiento |
|---|---|---|
| Definir un hilo | `class PowerTable extends Thread` | El objeto es un hilo |
| Trabajo del hilo | `@Override public void run()` | Código que ejecutará el hilo nuevo |
| Pasar datos al hilo | atributo + constructor | Cada hilo trabaja con su número |
| Crear el objeto | `new PowerTable(i)` | Estado `NEW`: aún no hay hilo en el SO |
| Arrancar un hilo | `table.start()` | Estado `RUNNABLE`; `run()` se ejecuta en el hilo nuevo |
| Llamar a `run()` directamente | `table.run()` | ❌ Se ejecuta en el hilo actual, sin concurrencia |
| Fin del programa | — | Cuando terminan todos los hilos no daemon, no al acabar `main` |
| Orden de ejecución | — | Entre hilos, impredecible; dentro de un hilo, secuencial |
| Potencia entera | `power *= number` con `long` | Evita `double` y el desbordamiento de `int` |
| Definir una tarea | `class PowerTable implements Runnable` | Solo el trabajo; el hilo lo pone un `Thread` (3.2) |
| Hilo con nombre | `new Thread(tarea, "Thread-" + i)` | Sin nombre: `Thread-0`, `Thread-1`… (3.2) |
| Nombre desde la tarea | `Thread.currentThread().getName()` | El hilo que ejecuta esa línea (3.2) |
| Prioridad | `setPriority(Thread.MAX_PRIORITY / MIN_PRIORITY)` | Solo una sugerencia; en Linux, ignorada por defecto (3.2) |
| Bucle hasta interrupción | `while (!Thread.currentThread().isInterrupted())` | Consulta el _flag_ sin borrarlo (3.3) |
| Pedir que pare | `hilo.interrupt()` | Activa el _flag_; el hilo decide cuándo parar (3.3) |
| Dormir | `TimeUnit.SECONDS.sleep(n)` | _Timed waiting_; lanza `InterruptedException` si lo interrumpen (3.3) |
| Restaurar el _flag_ | `Thread.currentThread().interrupt()` en el `catch` | `sleep()` lo deja a `false` al lanzar la excepción (3.3) |
| Esperar a un hilo | `hilo.join()` | Fija el orden de los últimos mensajes (3.3) |
| "Devolver" un valor | atributo en el `Runnable` + getter | Se lee tras `join()` (3.4) |
| Esperar a varios hilos | `for (...) threads[i].join();` | El principal sigue cuando han acabado todos (3.4) |
| Tarea + hilo | arrays `adders[]` y `threads[]` | Del `Runnable` se lee el resultado; del `Thread` se hace `join()` (3.4) |
