## 1. Aplicación

A menudo, los términos **aplicación**, **ejecutable** y **proceso** se utilizan de manera indistinta, pero cada uno hace referencia a un concepto diferente dentro de la programación y los sistemas operativos.

En general, conocemos como **software** el conjunto de programas informáticos que se ejecutan sobre el hardware del equipo.

### 1.1 Programa

> [!definition] Programa
> Conjunto de instrucciones que, diseñadas para ser ejecutadas en un ordenador, realizan una tarea específica o ayudan al usuario a realizarla.

Los programas se subdividen en dos grandes grupos:

| Grupo | Qué es | Ejemplos |
| --- | --- | --- |
| Programas para la gestión del hardware | Base sobre la que se ejecuta todo lo demás | Sistema operativo (Windows, GNU/Linux, macOS), controladores de dispositivos, firmware |
| Aplicaciones de usuario | Resuelven problemas específicos del usuario | Procesadores de texto (Word, Writer), navegadores (Chrome, Firefox), editores de imágenes (GIMP), reproductores (VLC) |

Las aplicaciones de usuario se ejecutan **sobre la base proporcionada por el sistema operativo**: el SO gestiona los recursos del hardware (memoria, procesador, E/S) y ofrece una interfaz para que las aplicaciones interactúen con el usuario y con el hardware de manera controlada y eficiente.

### 1.2 Aplicación

> [!definition] Aplicación
> Programa informático diseñado para resolver de manera automática un problema específico del usuario.

Desde el punto de vista de los sistemas operativos, llamamos **programa** a la **representación en disco** de una aplicación, que contiene tanto el código como los datos que maneja.

> [!tip] Idea clave
> **Programa** = representación estática en disco (código + datos). **Aplicación** = concepto más amplio que define la *finalidad y el uso* del programa para resolver un problema del usuario.

> [!example]- Ejercicios
> 1. Define con tus propias palabras: programa, aplicación, software. Explica las diferencias y pon un ejemplo de cada uno.
> 2. Clasifica como *gestión del hardware* o *aplicación de usuario*: Microsoft Word · Controlador de tarjeta de red · Sistema operativo Android · Navegador Google Chrome · Firmware de una impresora · Videojuego "Pac-Man".

## 2. Ejecutable

> [!definition] Ejecutable
> Fichero que contiene el código binario o interpretado que puede ser directamente ejecutado por un ordenador, o por una máquina virtual en el caso de código interpretado.

Nuestro punto de partida como programadores es el **código fuente**. Para que la máquina lo ejecute hay que traducirlo con un **compilador** o un **intérprete**, dando como resultado un fichero ejecutable.

- **Windows**: un ejecutable se reconoce por la extensión `.exe`.
- **GNU/Linux / macOS**: son ficheros con el **permiso de ejecución** activado; a veces con extensión `.bin` o sin extensión.

### 2.1 Clasificación según el tipo de código

| Tipo | Cómo funciona | Portabilidad |
| --- | --- | --- |
| **Binarios** | Instrucciones ejecutadas directamente por el procesador; se obtienen al compilar. Sólo funcionan en arquitecturas compatibles (requiere recompilar para cada plataforma) | Baja (no multiplataforma) |
| **Interpretados** | Código de operación que toma un intérprete (JVM para Java/bytecode, intérprete de Python…) y lo traduce a lenguaje máquina | Alta (multiplataforma) |

> [!tip] Balance
> Binarios → mayor **rendimiento**, menor portabilidad. Interpretados → sacrifican algo de rendimiento (necesitan intérprete) pero ganan en **portabilidad y flexibilidad**. La elección depende del proyecto.

### 2.2 Scripts

Tipo especial de ejecutables interpretados: contienen instrucciones que el intérprete ejecuta **una detrás de otra** y **no se compilan**, así que podemos abrirlos y ver el código con un editor de texto plano (no pasa con binarios ni interpretados compilados). Los intérpretes de este tipo se llaman **motores o intérpretes de script**.

Ejemplos: JavaScript, PHP, Python, `.BAT` (MS-DOS), PowerShell (Windows), bash (GNU/Linux), AppleScript (macOS).

```bash
#!/bin/bash
echo "Hola mundo desde un script bash"
```

Este script (`myecho.sh`) se ejecuta con la orden `bash myecho.sh` en la línea de comandos de Linux o macOS.

### 2.3 Librerías

Contienen código ejecutable **de utilidad para varios programas**, que invocan sus funciones. Altamente reutilizables: evitan reescribir el mismo código, fomentan la **modularidad** y facilitan el desarrollo y mantenimiento de aplicaciones complejas.

> [!example]- Ejercicios
> 1. Explica qué es un fichero ejecutable y la diferencia entre binario e interpretado. Cita lenguajes de cada tipo.
> 2. Ventajas y desventajas de ejecutables binarios e interpretados: rendimiento, portabilidad, facilidad de desarrollo y seguridad.

## 3. Proceso

> [!definition] Proceso
> Entidad dinámica que representa en el sistema operativo la ejecución de un programa.

Un fichero ejecutable por sí solo no realiza ninguna acción: es **al ejecutarlo** cuando surge el proceso. Para el SO, un programa no deja de ser un conjunto de ficheros en disco (al menos uno ejecutable); al ejecutarlo aparece el proceso, la **representación en el sistema operativo de un programa en ejecución**.

Un proceso no es sólo el código y los datos: también incluye **todos los recursos que el SO le asigna**:

| Componente | Qué es |
| --- | --- |
| Espacio de direcciones de memoria | Zona reservada para el código, datos y pila del proceso |
| Contador de programa | Indica la siguiente instrucción a ejecutar |
| Registros de la CPU | Valores intermedios y estado del procesador para el proceso |
| Descriptores de ficheros | Permisos para acceder a ficheros y otros recursos |
| Información de gestión del proceso | PID, prioridad, estado, etc. |

El conjunto de todos estos elementos en un momento dado se conoce como **contexto de proceso** o **imagen del proceso**. El SO gestiona el contexto de cada proceso para que se ejecuten de forma *aparentemente* simultánea, alternando rápidamente la ejecución entre ellos (en un monoprocesador).

Imagen del proceso:

![[proceso_memoria.png]]

> [!note] Dos relaciones importantes
> - **Un programa, varios procesos**: si ejecutamos el mismo programa dos veces, hay dos procesos distintos (contador, imagen de memoria y estado diferentes). Ejemplo: dos ventanas del mismo navegador.
> - **Un programa que lanza varios procesos**: el navegador puede crear procesos de interfaz, de red, de extensiones, por pestaña… Esta división mejora la **estabilidad** y la **capacidad de respuesta**.

> [!example]- Ejercicios
> 1. Diferencia entre programa y proceso usando la analogía del "libro de recetas" y el "chef cocinando".
> 2. Enumera y describe al menos cinco componentes del "contexto de proceso". ¿Por qué es importante que el SO los gestione?
> 3. Investiga cómo obtener el PID de un proceso en tu SO (línea de comandos o administrador de tareas).

## 4. Demonios y servicios

> [!definition] Demonio (daemon)
> Proceso que se ejecuta continuamente en segundo plano, en espera de peticiones o eventos, sin interactuar directamente con el usuario.

**Demonio** y **servicio** son términos sinónimos (Windows usa "servicio" para el mismo concepto): procesos en segundo plano que proveen funcionalidades esenciales al SO o a otras aplicaciones.

Características comunes:

- **Ejecución en segundo plano**: invisibles para el usuario directo.
- **Inicio automático** (frecuente): se arrancan con el sistema operativo.
- **Sin interfaz de usuario directa**: se gestionan con herramientas de administración u otras aplicaciones.
- **Larga duración**: funcionan de forma continua mientras el sistema está encendido.

Ejemplo del **servicio de impresión**: las aplicaciones envían trabajos a su cola sin preocuparse de los detalles de la impresora; el servicio va entregando los datos conforme la impresora los necesita (que no siempre tiene memoria para un trabajo completo), notifica al usuario al terminar y, si la cola se vacía, deja la impresora en *standby*.

| Tipo | Quién lo instala | Ejemplos |
| --- | --- | --- |
| Servicios del sistema operativo | El propio SO | Servicio de red, gestión de usuarios (autenticación/permisos), audio, gestión de energía |
| Servicios de aplicación | El usuario, configurables al arranque | Servidor web (Apache, Nginx), bases de datos (MySQL, PostgreSQL), correo, sincronización/copias en la nube |

> [!example]- Ejercicios
> 1. Define demonio/servicio y explica su importancia en un SO moderno.
> 2. Cita cinco demonios o servicios de tu sistema y su función.
> 3. Diferencias entre una aplicación de usuario "normal" y un servicio/demonio: implicaciones en interacción con el usuario y gestión de recursos.

## Esquema

- **Software** = programas sobre el hardware → gestión del hardware (SO, drivers, firmware) vs. aplicaciones de usuario.
- **Programa** = representación estática en disco · **Aplicación** = finalidad para el usuario · **Ejecutable** = fichero con código ejecutable · **Proceso** = entidad dinámica = programa en ejecución + recursos asignados.
- Ejecutables: **binarios** (directos, poco portables) vs. **interpretados** (intérprete/JVM, portables); **scripts** = interpretados no compilados, legibles en texto plano.
- **Contexto/imagen del proceso**: espacio de direcciones, contador de programa, registros, descriptores, PID/prioridad/estado.
- 1 programa → N procesos y 1 proceso puede requerir N procesos colaboradores (navegador por pestañas).
- **Demonio = servicio**: segundo plano, sin UI, larga duración, espera de peticiones.
