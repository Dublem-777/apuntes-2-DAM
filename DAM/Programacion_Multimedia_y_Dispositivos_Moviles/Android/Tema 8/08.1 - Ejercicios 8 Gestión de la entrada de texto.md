## Ejercicio 8.1 · Proyecto Login

> [!question] Enunciado
> En este proyecto deberás desarrollar la típica pantalla de login en la que el usuario introduce el nombre de usuario y la contraseña y pulsa un botón para hacer _login_. Ten en cuenta que inicialmente el campo username es el que coge el foco, que cada vez que un campo coge el foco el texto de arriba cambia de color y lo pierde cuando dicho campo pierde el foco. Además el teclado virtual está configurado para que muestre el botón de Done, de manera que al pulsarlo se realice la misma acción que se haría al pulsar el botón Login. La conexión se simulará mostrando un mensaje emergente con el usarname y password introducidos por el usuario. Para mostrar el mensaje emergente deberás usar lo que se conoce como un Toast, que podrás mostrar con la siguiente línea de código `Toast.makeText(context, message, Toast.LENGTH_SHORT).show()`. La imagen que se muestra en el login puede ser cualquier que tu quieras.
>
> Animación del proyecto en ejecución, en los apuntes del aula: [abrir imagen](https://educacionadistancia.juntadeandalucia.es/centros/cadiz/pluginfile.php/244507/mod_resource/content/1/files/prLogin.gif) (requiere iniciar sesión).

### Clases y métodos introducidos
- `<requestFocus/>`: el campo de usuario tiene el foco al abrir la pantalla.
- `setOnFocusChangeListener { _, hasFocus -> … }`: avisa cuando un campo gana o pierde el foco.
- `android:imeOptions="actionNext"` / `"actionDone"`: botón «siguiente» en el usuario y «hecho» en la contraseña.
- `setOnEditorActionListener { … }` + `EditorInfo.IME_ACTION_DONE`: reaccionar a la tecla Done.
- `android:inputType="textPassword"`: oculta lo que se escribe.
- `ContextCompat.getColor()` + `setTextColor()`: cambiar el color de la etiqueta desde un recurso de color.
- `hideSoftKeyboard()`: *extension function* de los apuntes para cerrar el teclado.
- `Toast.makeText(…).show()` y `getString(id, args)` con una cadena con parámetros.

#### Ejemplo simple de funcionamiento
```kotlin
binding.txtUsername.setOnFocusChangeListener { _, hasFocus ->
    // hasFocus vale true al entrar en el campo y false al salir
    println("¿Tiene el foco? $hasFocus")
}
```

#### `app/src/main/java/es/iessaladillo/pedrojoya/login/SoftInputUtils.kt`

```kotlin
package es.iessaladillo.pedrojoya.login

import android.app.Activity
import android.content.Context
import android.view.View
import android.view.inputmethod.InputMethodManager

fun Activity.showKeyboard(view: View) {
    val imm = getSystemService(Context.INPUT_METHOD_SERVICE) as InputMethodManager
    view.requestFocus()
    imm.showSoftInput(view, InputMethodManager.SHOW_IMPLICIT)
}

fun Activity.hideSoftKeyboard() {
    val view = currentFocus
    if (view != null) {
        val imm = getSystemService(Context.INPUT_METHOD_SERVICE) as InputMethodManager
        imm.hideSoftInputFromWindow(view.windowToken, 0)
    }
}
```

#### `app/src/main/java/es/iessaladillo/pedrojoya/login/MainActivity.kt`

```kotlin
package es.iessaladillo.pedrojoya.login

import android.os.Bundle
import android.view.KeyEvent
import android.view.inputmethod.EditorInfo
import android.widget.TextView
import android.widget.Toast
import androidx.appcompat.app.AppCompatActivity
import androidx.core.content.ContextCompat
import es.iessaladillo.pedrojoya.login.databinding.MainActivityBinding

class MainActivity : AppCompatActivity() {

    private val binding: MainActivityBinding by lazy {
        MainActivityBinding.inflate(layoutInflater)
    }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(binding.root)
        setupViews()
    }

    private fun setupViews() {
        // Al ganar o perder el foco, la etiqueta de su campo cambia de color
        binding.txtUsername.setOnFocusChangeListener { _, hasFocus ->
            changeColor(binding.lblUsername, hasFocus)
        }
        binding.txtPassword.setOnFocusChangeListener { _, hasFocus ->
            changeColor(binding.lblPassword, hasFocus)
        }
        binding.txtPassword.setOnEditorActionListener { _, actionId, keyEvent ->
            when (actionId) {
                // Tecla Done del teclado en pantalla: hace lo mismo que el botón Login
                EditorInfo.IME_ACTION_DONE -> {
                    login()
                    true    // evento consumido
                }
                // Enter de un teclado físico: llega al pulsar y al soltar, pero solo se actúa al pulsar
                EditorInfo.IME_NULL -> {
                    if (keyEvent?.action == KeyEvent.ACTION_DOWN) {
                        login()
                    }
                    true
                }
                else -> false
            }
        }
        binding.btnLogin.setOnClickListener { login() }
    }

    private fun changeColor(label: TextView, hasFocus: Boolean) {
        val colorResId = if (hasFocus) R.color.main_focused else R.color.main_unfocused
        label.setTextColor(ContextCompat.getColor(this, colorResId))
    }

    private fun login() {
        hideSoftKeyboard()
        val username = binding.txtUsername.text.toString()
        val password = binding.txtPassword.text.toString()
        // Se simula la conexión mostrando los datos en un Toast
        val message = getString(R.string.main_connecting, username, password)
        Toast.makeText(this, message, Toast.LENGTH_SHORT).show()
    }
}
```

### Explicación paso a paso
1. **Recursos.** Cada texto, color y medida tiene su nombre. Hay dos colores, «con foco» y «sin foco», y el mensaje del Toast es una cadena con dos parámetros (`%1$s` y `%2$s`), como se recomienda en el Tema 3 en lugar de concatenar.
2. **Foco inicial.** `<requestFocus />` dentro de `txtUsername` hace que ese campo tenga el foco al abrir la pantalla. Con `android:windowSoftInputMode="stateVisible"` en el manifiesto, además se abre el teclado directamente; sin esa línea el campo tendría el foco pero el teclado seguiría cerrado.
3. **Colores iniciales en el XML.** El *listener* de foco se asigna en `onCreate()`, **después** de que el *layout* haya puesto el foco en el usuario, así que ese primer cambio no lo avisa. Por eso el color de partida se fija en el *layout*: `lblUsername` empieza con `main_focused` y `lblPassword` con `main_unfocused`. A partir de ahí, los *listeners* se encargan de cada cambio.
4. **`setOnFocusChangeListener`.** `OnFocusChangeListener` tiene un solo método, así que se escribe como lambda. El primer parámetro (la vista) no se usa y se pone `_`. `hasFocus` indica si el campo acaba de entrar (`true`) o de salir (`false`), y `changeColor()` elige el color con un `if` usado como expresión.
5. **`changeColor()`.** `ContextCompat.getColor(this, id)` convierte el `resId` del color en su valor real. Es el método recomendado en los apuntes, porque `resources.getColor()` está obsoleto. Al ser una función aparte, sirve para las dos etiquetas.
6. **Teclas IME.** En el usuario, `actionNext` muestra la flecha de «siguiente», que lleva el foco a la contraseña (y entonces salta su *listener* de foco). En la contraseña, `actionDone` muestra «hecho». `setOnEditorActionListener` recibe el `actionId` y un `when` decide qué hacer:
   - `IME_ACTION_DONE` es la tecla ✓ del teclado en pantalla: llama a `login()` y devuelve `true` para decir que el evento ya está tratado.
   - `IME_NULL` es el **Enter de un teclado físico**, por ejemplo el del ordenador cuando pruebas en el emulador. No llega como «Done», y además llega dos veces: al pulsar (`ACTION_DOWN`) y al soltar (`ACTION_UP`). Solo se hace login al pulsar, para que el Toast no salga dos veces, pero se devuelve `true` en las dos. Si al soltar devolviera `false`, Android aplicaría su comportamiento por defecto y movería el foco al botón.
   - Cualquier otra acción devuelve `false` y Android hace lo de siempre.
7. **El botón.** `btnLogin` llama también a `login()`. Así, la tecla Done y el botón hacen exactamente lo mismo, que es lo que pide el enunciado, y la lógica está en un único sitio.
8. **`login()`.** Primero cierra el teclado con la *extension function* `hideSoftKeyboard()` de `SoftInputUtils.kt`; como extiende a `Activity`, dentro de la actividad se llama sin nada delante. Después lee los dos campos con `text.toString()` (`text` es un `Editable`), monta el mensaje con `getString(id, username, password)` y lo muestra con el `Toast` del enunciado, sin olvidar el `show()`.

> [!tip] Prueba
> 1. Al abrir la app, el teclado aparece y la etiqueta «Username» está en morado.
> 2. Escribe un usuario y pulsa «siguiente» en el teclado: el foco pasa a la contraseña, «Password» se pone en morado y «Username» vuelve al gris.
> 3. Escribe la contraseña (se ve con puntos) y pulsa Done: se cierra el teclado y sale el Toast «Connecting as … with password …».
> 4. Pulsa el botón Login: el resultado es el mismo.

> [!warning] Solo es una simulación
> Mostrar la contraseña en un Toast sirve para comprobar que se lee bien el campo, como pide el enunciado. En una app real nunca se muestra ni se guarda en claro.

## Esquema resumen de conceptos clave

| Concepto | Sintaxis | Uso en el ejercicio |
| --- | --- | --- |
| Foco inicial | `<requestFocus />` | El campo de usuario empieza con el foco. |
| Teclado al iniciar | `android:windowSoftInputMode="stateVisible"` | El teclado se abre solo. |
| Cambio de foco | `setOnFocusChangeListener { _, hasFocus -> … }` | Colorear la etiqueta del campo activo. |
| Color desde recurso | `ContextCompat.getColor(this, R.color.x)` | Valor real del color para `setTextColor()`. |
| Acciones IME | `android:imeOptions="actionNext"` · `"actionDone"` | «Siguiente» en el usuario, «hecho» en la contraseña. |
| Tecla Done | `setOnEditorActionListener { _, actionId, keyEvent -> when (actionId) { … } }` | `IME_ACTION_DONE` (teclado en pantalla) o `IME_NULL` (Enter físico): mismo efecto que el botón; devuelve `true` si lo trata. |
| Contraseña | `android:inputType="textPassword"` | Oculta lo escrito. |
| Cerrar teclado | `hideSoftKeyboard()` (*extension function*) | Antes de mostrar el resultado. |
| Mensaje | `Toast.makeText(this, getString(id, a, b), Toast.LENGTH_SHORT).show()` | Simula la conexión. |
