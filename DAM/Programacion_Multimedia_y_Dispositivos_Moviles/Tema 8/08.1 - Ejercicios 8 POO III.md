## Ejercicio 8.1 · Top-level functions y visibilidad private

> [!question] Enunciado
> Crea un **fichero de Kotlin** (simulado) para contener dos _top-level functions_ de utilidad.
>
> - Una función _top-level_ **`private`** llamada `padString(s: String, length: Int)` que devuelve la cadena `s` rellenada con espacios al final hasta alcanzar la `length` especificada.
> - Una función _top-level_ **`public`** (por defecto) llamada `formatTitle(title: String)` que utiliza `padString` internamente para rellenar la cadena a una longitud de `20` y luego devuelve la cadena en mayúsculas.
>
> En otro archivo, con la función `main`, haz lo siguiente:
>
> - Llama a `formatTitle("Project Name")` e imprime el resultado.
> - En un comentario, explica por qué la llamada a `padString("Short", 10)` **generaría un error de compilación** si se hiciera en este archivo.

### Clases y métodos introducidos
- _Top-level function_: función declarada directamente en el fichero, fuera de cualquier clase.
- `private` en una _top-level function_: la función solo es visible **dentro del mismo fichero**.
- `String.padEnd(length, ' ')`: devuelve la cadena rellenada por la derecha con el carácter indicado hasta la longitud pedida.
- `String.uppercase()`: devuelve la cadena en mayúsculas.

> **Términos explicados:** [[08 - POO III#1. Top-level functions|1. Top-level functions]]

### Código fuente (`Ejercicio8.1/src/StringUtils.kt` y `Ejercicio8.1/src/Main.kt`)

**StringUtils.kt**

```kotlin
// private: solo es visible dentro de este fichero (StringUtils.kt)
private fun padString(s: String, length: Int): String = s.padEnd(length, ' ')

// public (visibilidad por defecto): se puede usar desde cualquier fichero
fun formatTitle(title: String): String = padString(title, 20).uppercase()
```

**Main.kt**

```kotlin
fun main() {
    // Los corchetes permiten ver los espacios de relleno
    println("[${formatTitle("Project Name")}]")

    // padString("Short", 10)
    // ↑ Error de compilación: padString se declaró private en StringUtils.kt.
    //   Una top-level function private solo es visible dentro del fichero
    //   en el que se declara, así que desde Main.kt no existe.
}
```

> [!tip] Salida por consola
> ```text
> [PROJECT NAME        ]
> ```

### Explicación paso a paso
1. `StringUtils.kt` hace de "fichero de utilidades": en Java sería una clase con métodos `static`; en Kotlin basta con escribir las funciones sueltas.
2. `padString` es `private`, así que solo la pueden llamar las funciones de `StringUtils.kt`, como `formatTitle`.
3. `formatTitle` es pública (visibilidad por defecto): rellena el título hasta 20 caracteres con `padString` y lo pasa a mayúsculas.
4. En `Main.kt` se imprime el resultado entre corchetes para que se vean los espacios de relleno.
5. La llamada a `padString` se deja comentada: si se descomenta, el compilador da error porque esa función no es visible fuera de su fichero.

## Ejercicio 8.2 · Top-level property como contador de sesiones

> [!question] Enunciado
> Define una propiedad _top-level_ mutable llamada `sessionCount` de tipo `Int`, inicializada a `0`.
>
> Define las siguientes dos **funciones _top-level_**:
>
> - Una función llamada `startNewSession` que incrementa el valor de `sessionCount`.
> - Una función llamada `getSessionReport` que devuelve una `String` que diga: "Total sessions started: [Valor de sessionCount]".
>
> En la función `main`, simula el uso de la aplicación:
>
> - Llama a `startNewSession()` tres veces.
> - Llama a `getSessionReport()` e imprime el resultado.
> - Llama a `startNewSession()` una vez más.
> - Llama a `getSessionReport()` e imprime el resultado.

### Clases y métodos introducidos
- _Top-level property_: propiedad declarada fuera de cualquier clase. Es obligatorio inicializarla al declararla.
- Cualquier función del fichero (o de otro fichero que la importe) puede leerla y modificarla.

> **Términos explicados:** [[08 - POO III#2. Top-level properties|2. Top-level properties]]

### Código fuente (`Ejercicio8.2/src/Main.kt`)

```kotlin
// Top-level property: está fuera de cualquier clase y debe inicializarse al declararla
var sessionCount: Int = 0

fun startNewSession() {
    sessionCount++
}

fun getSessionReport(): String = "Total sessions started: $sessionCount"

fun main() {
    for (i in 1..3) {
        startNewSession()
    }
    println(getSessionReport())

    startNewSession()
    println(getSessionReport())
}
```

> [!tip] Salida por consola
> ```text
> Total sessions started: 3
> Total sessions started: 4
> ```

### Explicación paso a paso
1. `sessionCount` es `var` porque su valor va a cambiar, y se inicializa a `0` (una _top-level property_ no puede quedarse sin valor).
2. `startNewSession()` incrementa el contador con `++`; no necesita recibirlo como parámetro porque la propiedad es visible desde todo el fichero.
3. `getSessionReport()` es una función de expresión única que devuelve el texto con la plantilla `$sessionCount`.
4. En `main`, el bucle `for (i in 1..3)` llama tres veces a `startNewSession()`; el informe muestra `3` y, tras una sesión más, `4`.

## Ejercicio 8.3 · Constantes const en un companion object

> [!question] Enunciado
> Define una clase `PhysicsConstants`, cuyo _companion object_ contenga constantes físicas importantes:
>
> - La velocidad de la luz en el vacío (`c`) en metros por segundo (valor: `299_792_458`).
> - La constante de Planck (`h`) en julios por segundo (valor: `6.62607015e-34`).
> - La constante de gravitación universal (`G`) en metros cúbicos por kilogramo por segundo al cuadrado (valor: `6.67430e-11`).
>
> Luego, define una función main que imprima estos valores constantes.

### Clases y métodos introducidos
- `const val`: constante conocida en tiempo de compilación. Solo admite tipos primitivos o `String` y debe estar en el nivel superior o dentro de un `object` (como un _companion object_).
- `companion object`: sus miembros se usan con el nombre de la clase (`PhysicsConstants.SPEED_OF_LIGHT`), como los `static` de Java.
- Literales: `299_792_458` usa `_` como separador de miles; `6.62607015e-34` es notación científica (`Double`).

> **Términos explicados:** [[08 - POO III#3. Constantes conocidas en tiempo de compilación|3. Constantes conocidas en tiempo de compilación]]

### Código fuente (`Ejercicio8.3/src/Main.kt`)

```kotlin
class PhysicsConstants {
    companion object {
        // Velocidad de la luz en el vacío (c), en m/s
        const val SPEED_OF_LIGHT = 299_792_458
        // Constante de Planck (h), en J·s
        const val PLANCK_CONSTANT = 6.62607015e-34
        // Constante de gravitación universal (G), en m³/(kg·s²)
        const val GRAVITATIONAL_CONSTANT = 6.67430e-11
    }
}

fun main() {
    println("c = ${PhysicsConstants.SPEED_OF_LIGHT} m/s")
    println("h = ${PhysicsConstants.PLANCK_CONSTANT} J·s")
    println("G = ${PhysicsConstants.GRAVITATIONAL_CONSTANT} m³/(kg·s²)")
}
```

> [!tip] Salida por consola
> ```text
> c = 299792458 m/s
> h = 6.62607015E-34 J·s
> G = 6.6743E-11 m³/(kg·s²)
> ```

### Explicación paso a paso
1. Las constantes van en el _companion object_ para que la clase `PhysicsConstants` sirva de "espacio de nombres".
2. Se nombran en **UPPER_SNAKE_CASE**, la convención para constantes; el comentario indica a qué símbolo físico (`c`, `h`, `G`) corresponde cada una.
3. Las tres son `const` porque su valor es un literal de tipo primitivo (`Int` o `Double`) conocido antes de ejecutar el programa.
4. Al imprimirlas, Kotlin muestra los `Double` muy pequeños en notación científica (`6.62607015E-34`) y quita el cero final de `6.67430` (`6.6743E-11`).

## Ejercicio 8.4 · Propiedad lateinit y UninitializedPropertyAccessException

> [!question] Enunciado
> Define una clase simple llamada `AppService`. Dentro de `AppService`, define una **propiedad miembro** llamada `configName` de tipo `String` usando el modificador **`lateinit`**.
>
> Define una función pública llamada `initializeConfig(name: String)` que se encargue de asignar el valor al campo `configName`.
>
> Define una función pública llamada `runService` que imprima un mensaje usando el valor de `configName`.
>
> En la función `main`:
>
> - Crea una instancia inmutable de `AppService` llamada `service`.
> - Llama a `service.initializeConfig("Production_Env")`.
> - Llama a `service.runService()`.
> - Crea una nueva instancia inmutable de `AppService` llamada `faultyService`.
> - Utiliza un bloque `try-catch` para llamar inmediatamente a `faultyService.runService()` **sin inicializar previamente** `configName`.
> - En el bloque `catch`, captura la excepción `UninitializedPropertyAccessException` e imprime un mensaje que explique por qué falló.

### Clases y métodos introducidos
- `lateinit var`: propiedad no nullable que se inicializa **después** de construir el objeto. Debe ser `var` y no puede ser de tipo primitivo.
- `UninitializedPropertyAccessException`: excepción que se lanza si se lee una propiedad `lateinit` antes de darle valor.

> **Términos explicados:** [[08 - POO III#4. lateinit|4. lateinit]]

### Código fuente (`Ejercicio8.4/src/Main.kt`)

```kotlin
class AppService {
    // Prometemos al compilador que se inicializará antes de leerla
    lateinit var configName: String

    fun initializeConfig(name: String) {
        configName = name
    }

    fun runService() {
        println("Servicio en marcha con la configuración: $configName")
    }
}

fun main() {
    val service = AppService()
    service.initializeConfig("Production_Env")
    service.runService()

    val faultyService = AppService()
    try {
        // configName nunca se ha inicializado en este objeto
        faultyService.runService()
    } catch (e: UninitializedPropertyAccessException) {
        println("Fallo: se leyó configName antes de llamar a initializeConfig()")
        println("Mensaje de la excepción: ${e.message}")
    }
}
```

> [!tip] Salida por consola
> ```text
> Servicio en marcha con la configuración: Production_Env
> Fallo: se leyó configName antes de llamar a initializeConfig()
> Mensaje de la excepción: lateinit property configName has not been initialized
> ```

### Explicación paso a paso
1. `configName` es `lateinit var String`: no hace falta darle valor en el constructor ni volverla `String?`.
2. `initializeConfig()` cumple la "promesa" hecha al compilador asignándole un valor.
3. Con `service` todo va bien: primero se inicializa y después se usa.
4. Con `faultyService` se llama a `runService()` sin inicializar: al leer `configName` se lanza `UninitializedPropertyAccessException`, que se captura en el `catch` y se explica por pantalla.
5. "Instancia inmutable" significa declarar la referencia con `val`: el objeto puede cambiar por dentro, pero la variable siempre apunta al mismo objeto.

## Ejercicio 8.5 · Extension function reverseWords

> [!question] Enunciado
> Define una _extension function_ para la clase `String` llamada `reverseWords` que permita invertir el orden de las palabras en la cadena. Una palabra se define como una secuencia de caracteres alfanuméricos separados por espacios (ver método `split()`).
>
> Realiza una función `main` en la que se demuestre el uso de `reverseWords()`.

### Clases y métodos introducidos
- _Extension function_ `fun String.reverseWords()`: dentro, `this` (implícito) es la cadena sobre la que se llama.
- `trim()`: quita los espacios del principio y del final.
- `split(Regex("\\s+"))`: divide la cadena por uno o más espacios y devuelve una `List<String>`.
- `reversed()`: devuelve la lista en orden inverso.
- `joinToString(" ")`: une los elementos de la lista en una cadena, separados por un espacio.

> **Términos explicados:** [[08 - POO III#5. Extension functions|5. Extension functions]]

### Código fuente (`Ejercicio8.5/src/Main.kt`)

```kotlin
// Extension function: se define fuera de String, pero se llama como si fuera un método suyo
fun String.reverseWords(): String =
    trim()                      // quita espacios al principio y al final
        .split(Regex("\\s+"))   // separa por uno o más espacios
        .reversed()             // invierte el orden de la lista de palabras
        .joinToString(" ")      // vuelve a unirlas con un espacio

fun main() {
    val sentence = "Kotlin es un lenguaje   moderno"
    println("Original:  $sentence")
    println("Invertida: ${sentence.reverseWords()}")
}
```

> [!tip] Salida por consola
> ```text
> Original:  Kotlin es un lenguaje   moderno
> Invertida: moderno lenguaje un es Kotlin
> ```

### Explicación paso a paso
1. La función se declara como `String.reverseWords()`, así que se llama con un punto: `sentence.reverseWords()`.
2. No escribimos `this.trim()`: igual que en un método, el receptor se puede omitir.
3. Se usa `Regex("\\s+")` en vez de `" "` para que varios espacios seguidos no generen "palabras" vacías.
4. La lista de palabras se invierte y se vuelve a unir en una sola cadena.
5. Aunque parezca un método de `String`, la clase no se modifica: el compilador lo convierte en una función estática que recibe la cadena como primer parámetro.

## Ejercicio 8.6 · Extension property vowelCount

> [!question] Enunciado
> Define una extension property para la clase `String` llamada `vowelCount` que permita obtener el número de vocales en la cadena.

### Clases y métodos introducidos
- _Extension property_ `val String.vowelCount: Int`: propiedad calculada; como no puede tener _backing field_, su valor sale siempre del `get()`.
- `lowercase()`: pasa la cadena a minúsculas para no tener que comprobar `A` y `a` por separado.
- `c in "aeiou..."`: el operador `in` se traduce a `"aeiou...".contains(c)`.

> **Términos explicados:** [[08 - POO III#6. Extension properties|6. Extension properties]]

### Código fuente (`Ejercicio8.6/src/Main.kt`)

```kotlin
// Extension property: no tiene backing field, así que se calcula en el getter
val String.vowelCount: Int
    get() {
        var count = 0
        for (c in this.lowercase()) {
            // "in" sobre un String se traduce a contains(c)
            if (c in "aeiouáéíóúü") {
                count++
            }
        }
        return count
    }

fun main() {
    val text = "Programación Multimedia"
    println("\"$text\" tiene ${text.vowelCount} vocales")
}
```

> [!tip] Salida por consola
> ```text
> "Programación Multimedia" tiene 10 vocales
> ```

### Explicación paso a paso
1. Se declara con `val` y un `get()` personalizado; no se puede escribir `= 0` porque una _extension property_ no tiene campo donde guardar un valor.
2. El `for` recorre los caracteres de la cadena en minúsculas.
3. Cada carácter se compara con la lista de vocales (incluidas las acentuadas y la `ü`, porque el texto está en español).
4. Se usa como una propiedad normal, sin paréntesis: `text.vowelCount`.

## Ejercicio 8.7 · Sobrecarga del operador + en ComplexNumber

> [!question] Enunciado
> Define una clase llamada `ComplexNumber` para representar números complejos. Cada número complejo consta de una parte real y una parte imaginaria. Por ejemplo para la representación `a + bi`, `a` corresponde a la parte real y `b` corresponde a la parte imaginaria (`i` es una constante que debe acompañar a la parte imaginaria). Queremos sobrecargar en la clase `ComplexNumber` el operador `+` para sumar dos números complejos, cuya fórmula es: `(a+bi)+(c+di) = (a+c)+(b+d)i`.

### Clases y métodos introducidos
- `operator fun plus(other)`: al marcar `plus` con `operator`, la expresión `a + b` se traduce a `a.plus(b)`.
- `override fun toString()`: personaliza cómo se muestra el objeto en las plantillas `$a`.

> **Términos explicados:** [[08 - POO III#7. Sobrecarga de operadores|7. Sobrecarga de operadores]]

### Código fuente (`Ejercicio8.7/src/Main.kt`)

```kotlin
data class ComplexNumber(val real: Double, val imaginary: Double) {

    // (a + bi) + (c + di) = (a + c) + (b + d)i
    operator fun plus(other: ComplexNumber): ComplexNumber =
        ComplexNumber(real + other.real, imaginary + other.imaginary)

    // Formato a + bi (o a - bi si la parte imaginaria es negativa)
    override fun toString(): String =
        if (imaginary >= 0) "$real + ${imaginary}i" else "$real - ${-imaginary}i"
}

fun main() {
    val a = ComplexNumber(3.0, 2.0)
    val b = ComplexNumber(1.5, -4.0)
    val sum = a + b    // equivale a a.plus(b)
    println("($a) + ($b) = $sum")
}
```

> [!tip] Salida por consola
> ```text
> (3.0 + 2.0i) + (1.5 - 4.0i) = 4.5 - 2.0i
> ```

### Explicación paso a paso
1. `ComplexNumber` es una _data class_ inmutable con la parte real y la imaginaria.
2. `plus` aplica la fórmula: suma las partes reales por un lado y las imaginarias por otro, y devuelve un **nuevo** número complejo.
3. `toString()` se sobrescribe para mostrar el formato matemático `a + bi` (o `a - bi` si la parte imaginaria es negativa) en lugar del `ComplexNumber(real=…, imaginary=…)` que genera la _data class_.
4. En `main`, `a + b` llama a `a.plus(b)`: el operando izquierdo es el objeto sobre el que se ejecuta el método y el derecho es el argumento.

## Ejercicio 8.8 · Delegación de interfaces con by

> [!question] Enunciado
> Crea dos interfaces, `Painter` y `Writer`, que definan los métodos `paint()` y `write()`, respectivamente. Luego, implementa estas interfaces en las clases `HousePainter` y `BookWriter`. Finalmente, crea una clase `MultiTalentedPerson` que delegue la implementación de ambas interfaces a instancias de `HousePainter` y `BookWriter`, y contiene un método `introduce()` que permita a la persona presentarse y mencionar sus habilidades.
>
> Realiza la función `main` de manera que se demuestre el funcionamiento de la clase `MultiTalentedPerson` y se llame a sus métodos `introduce()`, `paint()` y `write()`.

### Clases y métodos introducidos
- `Interfaz by objeto`: el compilador genera en la clase todos los métodos de la interfaz, y cada uno simplemente llama al método del objeto delegado.
- Se pueden delegar **varias interfaces** en objetos distintos, cosa imposible con herencia (solo se hereda de una clase).

> **Términos explicados:** [[08 - POO III#8. Delegación de implementación de interfaces|8. Delegación de implementación de interfaces]]

### Código fuente (`Ejercicio8.8/src/Main.kt`)

```kotlin
interface Painter {
    fun paint()
}

interface Writer {
    fun write()
}

class HousePainter : Painter {
    override fun paint() {
        println("Pintando las paredes de la casa...")
    }
}

class BookWriter : Writer {
    override fun write() {
        println("Escribiendo un nuevo capítulo del libro...")
    }
}

// Cada interfaz se delega en un objeto distinto con "by"
class MultiTalentedPerson(
    private val name: String,
    painter: Painter = HousePainter(),
    writer: Writer = BookWriter(),
) : Painter by painter, Writer by writer {

    fun introduce() {
        println("Hola, soy $name. Sé pintar casas y escribir libros.")
    }
}

fun main() {
    val person = MultiTalentedPerson("Baldomero")
    person.introduce()
    person.paint()   // lo ejecuta el HousePainter delegado
    person.write()   // lo ejecuta el BookWriter delegado
}
```

> [!tip] Salida por consola
> ```text
> Hola, soy Baldomero. Sé pintar casas y escribir libros.
> Pintando las paredes de la casa...
> Escribiendo un nuevo capítulo del libro...
> ```

### Explicación paso a paso
1. `HousePainter` y `BookWriter` son las implementaciones "reales" de cada interfaz.
2. `MultiTalentedPerson` implementa `Painter` y `Writer`, pero no escribe `paint()` ni `write()`: con `by painter` y `by writer` los delega.
3. Los delegados llegan como parámetros del constructor con un valor por defecto, así se podría pasar otro pintor u otro escritor sin tocar la clase.
4. `introduce()` es un método propio de la clase, que convive con los métodos delegados.
5. Es **composición en lugar de herencia**: la persona _tiene_ un pintor y un escritor, en vez de _ser_ uno de ellos.

## Ejercicio 8.9 · Delegado de propiedad UpperCaseDelegate

> [!question] Enunciado
> Define la clase delegada `UpperCaseDelegate` que implemente la interfaz `ReadWriteProperty<Any?, String>`.
>
> - **`UpperCaseDelegate`**: Debe tener un constructor que acepte el valor inicial (`private var storedValue: String`).
> - **`getValue`**: Devuelve `storedValue`.
> - **`setValue`**: Convierte el `value` de entrada a **mayúsculas** antes de asignarlo a `storedValue`.
>
> Define una **función _top-level_** llamada `upperCase()` que **devuelva** una instancia de `UpperCaseDelegate<String>` inicializada con una cadena vacía (`""`).
>
> Define una clase `User` con una propiedad mutable llamada `name` de tipo `String` que **delegue su funcionalidad** a una instancia creada por la función **`upperCase()`**.
>
> En la función `main`:
>
> - Crea una instancia inmutable de `User` llamada `user`.
> - Imprime el valor inicial de `user.name`.
> - Asigna el valor `"new name in lowercase"` a `user.name`.
> - Imprime el valor de `user.name` (debería aparecer en mayúsculas).

### Clases y métodos introducidos
- `ReadWriteProperty<Any?, String>`: interfaz con `getValue()` y `setValue()` para crear delegados de propiedades `var`. El primer tipo es el del objeto propietario (`Any?` = cualquiera) y el segundo el de la propiedad.
- `KProperty<*>`: información de la propiedad delegada (por ejemplo, su nombre).
- `var name: String by upperCase()`: delega los accesos de `name` en el objeto que devuelve `upperCase()`.

> **Términos explicados:** [[08 - POO III#9. Property delegation|9. Property delegation]]

### Código fuente (`Ejercicio8.9/src/Main.kt`)

```kotlin
import kotlin.properties.ReadWriteProperty
import kotlin.reflect.KProperty

// Delegado que guarda el texto siempre en mayúsculas
class UpperCaseDelegate(private var storedValue: String) : ReadWriteProperty<Any?, String> {

    override fun getValue(thisRef: Any?, property: KProperty<*>): String = storedValue

    override fun setValue(thisRef: Any?, property: KProperty<*>, value: String) {
        storedValue = value.uppercase()
    }
}

// Función top-level que fabrica el delegado
fun upperCase(): UpperCaseDelegate = UpperCaseDelegate("")

class User {
    // Leer o escribir name llama a getValue()/setValue() del delegado
    var name: String by upperCase()
}

fun main() {
    val user = User()
    println("Valor inicial: '${user.name}'")

    user.name = "new name in lowercase"
    println("Valor actual: '${user.name}'")
}
```

> [!tip] Salida por consola
> ```text
> Valor inicial: ''
> Valor actual: 'NEW NAME IN LOWERCASE'
> ```

### Explicación paso a paso
1. `UpperCaseDelegate` guarda el valor real en `storedValue`; la propiedad `name` de `User` no tiene campo propio.
2. Leer `user.name` llama a `getValue()`, que devuelve `storedValue`.
3. Asignar `user.name = …` llama a `setValue()`, que guarda el texto ya convertido con `uppercase()`.
4. `upperCase()` es una _top-level function_ que fabrica el delegado; así la declaración de la propiedad queda muy legible.
5. El enunciado escribe `UpperCaseDelegate<String>`, pero como la clase ya implementa `ReadWriteProperty<Any?, String>` y guarda un `String`, no necesita ser genérica: se declara sin `<T>`.

## Ejercicio 8.10 · Conexión perezosa con lazy

> [!question] Enunciado
> Define una clase `Database` que represente una conexión a una base de datos. La clase debe tener una propiedad `connection` que se inicialice perezosamente. La inicialización de `connection` debe simular una conexión a la base de datos imprimiendo un mensaje en la consola.
>
> La clase también debe tener un método `executeQuery(query: String)` que imprima el la consulta recibida y después imprima el estado de la conexión.
>
> Demuestra el uso de la clase `Database` en una función `main`, ejecutando varias consultas.

### Clases y métodos introducidos
- `val x by lazy { … }`: la lambda se ejecuta **la primera vez** que se lee `x`; su último valor se guarda y se reutiliza en los siguientes accesos.
- Solo sirve con `val`.

> **Términos explicados:** [[08 - POO III#11. Inicialización perezosa con lazy|11. Inicialización perezosa con lazy]]

### Código fuente (`Ejercicio8.10/src/Main.kt`)

```kotlin
class Database {
    // La lambda solo se ejecuta la primera vez que se lee connection
    val connection: String by lazy {
        println(">> Conectando con la base de datos...")
        "Conexión activa"
    }

    fun executeQuery(query: String) {
        println("Ejecutando: $query")
        println("Estado de la conexión: $connection")
    }
}

fun main() {
    val database = Database()
    println("Objeto Database creado (todavía sin conexión)")

    database.executeQuery("SELECT * FROM users")
    database.executeQuery("SELECT * FROM products")
    database.executeQuery("DELETE FROM logs")
}
```

> [!tip] Salida por consola
> ```text
> Objeto Database creado (todavía sin conexión)
> Ejecutando: SELECT * FROM users
> >> Conectando con la base de datos...
> Estado de la conexión: Conexión activa
> Ejecutando: SELECT * FROM products
> Estado de la conexión: Conexión activa
> Ejecutando: DELETE FROM logs
> Estado de la conexión: Conexión activa
> ```

### Explicación paso a paso
1. Crear el objeto `Database` no conecta: la lambda de `lazy` todavía no se ha ejecutado.
2. En la primera consulta, `executeQuery` imprime la consulta y, al leer `connection`, se ejecuta la lambda: aparece `>> Conectando…` y se guarda `"Conexión activa"`.
3. En las siguientes consultas `connection` ya tiene valor, así que el mensaje de conexión **no vuelve a salir**.
4. La última expresión de la lambda (`"Conexión activa"`) es el valor que toma la propiedad.

## Ejercicio 8.11 · Singleton perezoso con by lazy

> [!question] Enunciado
> Crea una clase `Database` que implemente el patrón Singleton en Kotlin, donde la construcción del objeto debe realizarse de forma perezosa usando `by lazy`. El constructor de la clase recibe como argumento una cadena corresondiente a la URL de la base de datos. Además dispone del método `conectar()` que imprime un mensaje indicando que se está conectando a la base de datos utilizando la URL proporcionada, y del método `desconectar()`, que imprime un mensaje indicando que se está desconectando de la base de datos utilizando la URL proporcionada.
>
> En la función `main`, crea dos variables que correspondan a la instancia singleton de dicha clase y llama a los métodos `conectar()` y `desconectar()`. Además comprueba que ambas variables referencian el mismo objeto, usando el operador `===`.

### Clases y métodos introducidos
- **Singleton**: patrón de diseño que garantiza que de una clase solo exista **una instancia**.
- `private constructor`: impide crear objetos con `Database(...)` desde fuera de la clase.
- `===`: igualdad referencial; es `true` si las dos variables apuntan al mismo objeto en memoria.

> **Términos explicados:** [[08 - POO III#11. Inicialización perezosa con lazy|11. Inicialización perezosa con lazy]]

### Código fuente (`Ejercicio8.11/src/Main.kt`)

```kotlin
// Constructor privado: desde fuera no se puede hacer Database("...")
class Database private constructor(private val url: String) {

    fun conectar() {
        println("Conectando a la base de datos en $url")
    }

    fun desconectar() {
        println("Desconectando de la base de datos en $url")
    }

    companion object {
        private const val DEFAULT_URL = "jdbc:mysql://localhost:3306/dam"

        // Única instancia: se construye la primera vez que alguien la pide
        val instance: Database by lazy {
            println(">> Creando la única instancia de Database")
            Database(DEFAULT_URL)
        }
    }
}

fun main() {
    val db1 = Database.instance
    val db2 = Database.instance

    db1.conectar()
    db2.desconectar()

    // === compara referencias: ¿apuntan al mismo objeto en memoria?
    println("¿db1 y db2 son el mismo objeto? ${db1 === db2}")
}
```

> [!tip] Salida por consola
> ```text
> >> Creando la única instancia de Database
> Conectando a la base de datos en jdbc:mysql://localhost:3306/dam
> Desconectando de la base de datos en jdbc:mysql://localhost:3306/dam
> ¿db1 y db2 son el mismo objeto? true
> ```

### Explicación paso a paso
1. El constructor es privado: la única forma de obtener un `Database` es a través de `Database.instance`.
2. `instance` está en el _companion object_ y se inicializa con `by lazy`: el objeto se construye la primera vez que alguien lo pide, no al arrancar el programa.
3. Como `lazy` guarda el valor, `db1` y `db2` reciben **el mismo objeto**; por eso el mensaje `>> Creando…` solo sale una vez y `db1 === db2` es `true`.
4. La URL se define como constante privada del _companion object_, porque la lambda de `lazy` no puede recibir parámetros.
5. Los métodos se llaman `conectar()` y `desconectar()` porque así lo pide el enunciado.

## Ejercicio 8.12 · Delegates.notNull() con un Boolean

> [!question] Enunciado
> Define una clase llamada `GameSessionManager`. Dentro de `GameSessionManager`, define una **propiedad mutable** llamada `isMultiplayerEnabled` de tipo `Boolean` que **debe ser delegada** al constructor `Delegates.notNull()`.
>
> Define una función pública llamada `setupMode(isMultiplayer: Boolean)` que se encargue de inicializar la propiedad `isMultiplayerEnabled`.
>
> Define una función pública llamada `startGame` que imprima un mensaje indicando si el juego se inicia en modo multijugador o individual (usando el valor de la propiedad).
>
> En la función `main`, haz lo siguiente:
>
> - Crea una instancia inmutable de `GameSessionManager` llamada `manager`.
> - Llama a `manager.setupMode(true)` y luego llama a `manager.startGame()`.
> - Crea una segunda instancia inmutable de `GameSessionManager` llamada `errorManager`.
> - Utiliza un bloque **`try-catch`** para intentar llamar inmediatamente a `errorManager.startGame()` **sin inicializar** la propiedad.
> - En el bloque `catch`, captura la excepción específica que lanza `Delegates.notNull()` (`IllegalStateException`) e imprime un mensaje que incluya el nombre exacto de la excepción.

### Clases y métodos introducidos
- `Delegates.notNull()`: delegado para una `var` no nullable que se inicializa más tarde. A diferencia de `lateinit`, **funciona con tipos primitivos** (`Int`, `Boolean`…).
- `IllegalStateException`: excepción que lanza si se lee la propiedad antes de asignarle un valor.

> **Términos explicados:** [[08 - POO III#13.1 Delegates.notNull()|13.1 Delegates.notNull()]]

### Código fuente (`Ejercicio8.12/src/Main.kt`)

```kotlin
import kotlin.properties.Delegates

class GameSessionManager {
    // lateinit no admite Boolean (tipo primitivo): usamos Delegates.notNull()
    var isMultiplayerEnabled: Boolean by Delegates.notNull()

    fun setupMode(isMultiplayer: Boolean) {
        isMultiplayerEnabled = isMultiplayer
    }

    fun startGame() {
        val mode = if (isMultiplayerEnabled) "multijugador" else "individual"
        println("Iniciando partida en modo $mode")
    }
}

fun main() {
    val manager = GameSessionManager()
    manager.setupMode(true)
    manager.startGame()

    val errorManager = GameSessionManager()
    try {
        errorManager.startGame()
    } catch (e: IllegalStateException) {
        println("Capturada IllegalStateException: ${e.message}")
    }
}
```

> [!tip] Salida por consola
> ```text
> Iniciando partida en modo multijugador
> Capturada IllegalStateException: Property isMultiplayerEnabled should be initialized before get.
> ```

### Explicación paso a paso
1. `lateinit var isMultiplayerEnabled: Boolean` no compilaría, porque `Boolean` es primitivo; por eso se usa `Delegates.notNull()`.
2. `setupMode()` asigna el valor y, a partir de ahí, la propiedad se puede leer.
3. `startGame()` elige el texto con un `if` usado como expresión.
4. En `errorManager` nadie llama a `setupMode()`, así que leer la propiedad lanza `IllegalStateException`, que se captura y se muestra con su mensaje.

## Ejercicio 8.13 · Delegates.observable() para el estado de conexión

> [!question] Enunciado
> Define una clase llamada `UserManager` que simule la gestión del estado de un usuario.
>
> Dentro de `UserManager`, define una propiedad mutable llamada `isOnline` de tipo `Boolean` que **debe ser delegada** a `Delegates.observable()`. El **valor inicial** de `isOnline` debe ser `false`. La **lambda** del delegado debe:
>
> - Verificar si el `newValue` es diferente de `oldValue` (aunque `observable` solo se llama en la asignación, esto es una buena práctica).
> - Si son diferentes, imprimir un mensaje. Si el `newValue` es `true`, debe imprimir: "USER: has connected." Si es `false`, debe imprimir: "USER: has disconnected."
>
> En la función `main`:
>
> - Crea una instancia inmutable de `UserManager` llamada `manager`.
> - Imprime el estado inicial de `manager.isOnline`.
> - Simula un cambio de estado:
>     - Asigna `true` a `manager.isOnline`.
>     - Asigna `true` a `manager.isOnline` (esto no debería imprimir nada si la lambda lo comprueba).
>     - Asigna `false` a `manager.isOnline`.

### Clases y métodos introducidos
- `Delegates.observable(inicial) { prop, oldValue, newValue -> … }`: ejecuta la lambda **después** de cada asignación, con el valor anterior y el nuevo.
- `_` en los parámetros de una lambda: indica que ese parámetro no se usa (aquí, `prop`).

> **Términos explicados:** [[08 - POO III#13.2 Delegates.observable()|13.2 Delegates.observable()]]

### Código fuente (`Ejercicio8.13/src/Main.kt`)

```kotlin
import kotlin.properties.Delegates

class UserManager {
    // _ : no usamos el parámetro prop, así que no le damos nombre
    var isOnline: Boolean by Delegates.observable(false) { _, oldValue, newValue ->
        if (newValue != oldValue) {
            if (newValue) {
                println("USER: has connected.")
            } else {
                println("USER: has disconnected.")
            }
        }
    }
}

fun main() {
    val manager = UserManager()
    println("Estado inicial: ${manager.isOnline}")

    manager.isOnline = true    // false -> true: imprime
    manager.isOnline = true    // true -> true: no imprime nada
    manager.isOnline = false   // true -> false: imprime
}
```

> [!tip] Salida por consola
> ```text
> Estado inicial: false
> USER: has connected.
> USER: has disconnected.
> ```

### Explicación paso a paso
1. La propiedad empieza en `false` (primer argumento de `observable`).
2. Leer `isOnline` no ejecuta la lambda; solo las asignaciones lo hacen.
3. La primera asignación (`false → true`) imprime "has connected".
4. La segunda (`true → true`) ejecuta la lambda, pero como no hay cambio real no imprime nada.
5. La tercera (`true → false`) imprime "has disconnected".

## Ejercicio 8.14 · Delegates.vetoable() para validar temperaturas

> [!question] Enunciado
> Define una clase llamada `TemperatureMonitor`. Dentro de `TemperatureMonitor`, define una propiedad mutable llamada `currentTempCelsius` de tipo `Int` que **debe ser delegada** a `Delegates.vetoable()`. El **valor inicial** de `currentTempCelsius` debe ser `20`. La **lambda** del delegado debe:
>
> - Verificar si el `newValue` está en el rango `[10, 40]`.
> - Si está dentro del rango, la _lambda_ debe devolver `true` (Aceptar el cambio).
> - Si está fuera del rango, la _lambda_ debe devolver `false` (Rechazar el cambio). Además, debe imprimir un mensaje que diga: "ALERT: Value $newValue is out of safe range [10-40]. Retaining $oldValue."
>
> En la función `main`:
>
> - Crea una instancia inmutable de `TemperatureMonitor` llamada `sensor`.
> - Imprime el valor inicial de `sensor.currentTempCelsius`.
> - Simula los siguientes cambios y, después de cada uno, imprime el valor actual de la propiedad:
>     - Asigna `35` a `sensor.currentTempCelsius` (Cambio Válido).
>     - Asigna `5` a `sensor.currentTempCelsius` (Rechazado - Demasiado frío).
>     - Asigna `45` a `sensor.currentTempCelsius` (Rechazado - Demasiado caliente).
>     - Asigna `10` a `sensor.currentTempCelsius` (Cambio Válido).

### Clases y métodos introducidos
- `Delegates.vetoable(inicial) { prop, oldValue, newValue -> Boolean }`: ejecuta la lambda **antes** de asignar. Si devuelve `true` se acepta el valor; si devuelve `false`, la propiedad se queda como estaba (sin lanzar excepción).
- `newValue in 10..40`: comprueba si el valor está en el rango cerrado `[10, 40]`.

> **Términos explicados:** [[08 - POO III#13.3 Delegates.vetoable()|13.3 Delegates.vetoable()]]

### Código fuente (`Ejercicio8.14/src/Main.kt`)

```kotlin
import kotlin.properties.Delegates

class TemperatureMonitor {
    // La lambda decide ANTES de asignar: true acepta, false rechaza
    var currentTempCelsius: Int by Delegates.vetoable(20) { _, oldValue, newValue ->
        if (newValue in 10..40) {
            true
        } else {
            println("ALERT: Value $newValue is out of safe range [10-40]. Retaining $oldValue.")
            false
        }
    }
}

fun main() {
    val sensor = TemperatureMonitor()
    println("Temperatura inicial: ${sensor.currentTempCelsius}")

    sensor.currentTempCelsius = 35   // válido
    println("Temperatura actual: ${sensor.currentTempCelsius}")

    sensor.currentTempCelsius = 5    // rechazado: demasiado frío
    println("Temperatura actual: ${sensor.currentTempCelsius}")

    sensor.currentTempCelsius = 45   // rechazado: demasiado caliente
    println("Temperatura actual: ${sensor.currentTempCelsius}")

    sensor.currentTempCelsius = 10   // válido (límite inferior)
    println("Temperatura actual: ${sensor.currentTempCelsius}")
}
```

> [!tip] Salida por consola
> ```text
> Temperatura inicial: 20
> Temperatura actual: 35
> ALERT: Value 5 is out of safe range [10-40]. Retaining 35.
> Temperatura actual: 35
> ALERT: Value 45 is out of safe range [10-40]. Retaining 35.
> Temperatura actual: 35
> Temperatura actual: 10
> ```

### Explicación paso a paso
1. La propiedad empieza en `20`.
2. `35` está en el rango: la lambda devuelve `true` y el valor cambia.
3. `5` y `45` están fuera: la lambda imprime la alerta y devuelve `false`, así que la propiedad **conserva** `35`.
4. `10` es el límite inferior y `10..40` es un rango cerrado (incluye los extremos), así que se acepta.
5. El `if`/`else` de la lambda es una expresión: su último valor (`true` o `false`) es lo que devuelve la lambda.

## Esquema resumen de conceptos clave

| Concepto | Sintaxis | Comportamiento |
| --- | --- | --- |
| Top-level function `private` | `private fun padString(…)` | Solo visible en su fichero (8.1). |
| Top-level property | `var sessionCount = 0` | Estado compartido por las funciones del fichero (8.2). |
| `const val` | `const val SPEED_OF_LIGHT = 299_792_458` | Constante de compilación en un _companion object_ (8.3). |
| `lateinit` | `lateinit var configName: String` | Inicialización tardía; si no, `UninitializedPropertyAccessException` (8.4). |
| Extension function | `fun String.reverseWords()` | Se llama como un método de `String` (8.5). |
| Extension property | `val String.vowelCount: Int get() = …` | Propiedad calculada sin _backing field_ (8.6). |
| Sobrecarga de operador | `operator fun plus(other)` | `a + b` → `a.plus(b)` (8.7). |
| Delegación de interfaz | `: Painter by painter, Writer by writer` | Varias interfaces delegadas en objetos distintos (8.8). |
| Delegado de propiedad | `ReadWriteProperty<Any?, String>` | `getValue()`/`setValue()` controlan la propiedad (8.9). |
| `by lazy` | `val connection by lazy { … }` | Se calcula una vez, en el primer acceso (8.10, 8.11). |
| `Delegates.notNull()` | `var x: Boolean by Delegates.notNull()` | `lateinit` para primitivos; `IllegalStateException` (8.12). |
| `Delegates.observable()` | `by Delegates.observable(false) { _, old, new -> … }` | Reacciona después de asignar (8.13). |
| `Delegates.vetoable()` | `by Delegates.vetoable(20) { _, old, new -> Boolean }` | Acepta o rechaza antes de asignar (8.14). |
