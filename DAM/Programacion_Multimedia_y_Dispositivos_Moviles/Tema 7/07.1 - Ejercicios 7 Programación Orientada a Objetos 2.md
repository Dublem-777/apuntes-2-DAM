## Ejercicio 7.1 · Data class y método copy()

> [!question] Enunciado
> Define una _data class_ llamada `Product` para gestionar los datos de un producto en el almacén, y que tenga las siguientes propiedades: `id`, `name`, `price`, `quantity`.
> Crear una función `updateProduct()` que reciba un producto, y retorne un nuevo producto en el que el precio esté incrementado en el porcentaje recibido como argumento, para lo que deberá usarse el método `copy()` de la _data class_.


### Clases y métodos introducidos
- `data class`: genera `equals()`, `hashCode()`, `toString()`, `componentN()` y `copy()` usando propiedades del constructor primario.
- `copy(price = ...)`: crea una copia con precio actualizado.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Data class|`data class` y métodos generados]] · [[Programación Orientada a Objetos 2#Data class|`copy()` y parámetros con valores por defecto]] · [[Programación Orientada a Objetos 2#Data class|copia superficial (`shallow copy`)]]

#### Ejemplo simple de funcionamiento
```kotlin
data class Producto(val precio: Double)
val actualizado = Producto(10.0).copy(precio = 12.0)
```

### Código fuente (`Ejercicio7.1/src/Main.kt`)

```kotlin
data class Product(
    val id: Int,
    val name: String,
    val price: Double,
    val quantity: Int,
)

fun updateProduct(product: Product, percentage: Double): Product {
    require(percentage >= 0.0) { "Percentage must be non-negative" }
    return product.copy(price = product.price * (1 + percentage / 100.0))
}

fun main() {
    val product = Product(1, "Teclado", 50.0, 8)
    val updated = updateProduct(product, 10.0)
    println(product)
    println(updated)
}
```

### Explicación paso a paso
1. Los cuatro campos se declaran en el constructor primario y forman parte de los métodos generados.
2. `require` rechaza porcentajes negativos antes de calcular el precio.
3. `copy` mantiene `id`, `name` y `quantity`, cambiando solo `price`; 10 % de 50 es 55.
4. `product` permanece intacto porque `copy` crea otro objeto.

## Ejercicio 7.2 · Desestructuración de data class

> [!question] Enunciado
> Define una _data class_ llamada `Employee` para gestionar los empleados de una empresa. La clase debe contener las siguientes propiedades: `id`, `name`, `position` y `salary`.
> Implementa una función main que cree una instancia de `Employee` y después imprima los detalles del empleado (nombre y salario) utilizando el operador de desestructuración para extraer las propiedades de la instancia.


### Clases y métodos introducidos
- `data class`: genera funciones `componentN()` en el orden de las propiedades del constructor primario.
- Desestructuración: `val (a, b) = objeto` asigna componentes por posición.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Data class|data class]] · [[Programación Orientada a Objetos 2#Desestructuración|desestructuración posicional]]

#### Ejemplo simple de funcionamiento
```kotlin
data class Punto(val x: Int, val y: Int)
val (x, y) = Punto(3, 4)
```

### Código fuente (`Ejercicio7.2/src/Main.kt`)

```kotlin
data class Employee(
    val id: Int,
    val name: String,
    val position: String,
    val salary: Double,
)

fun main() {
    val employee = Employee(1, "Ada Lovelace", "Programadora", 4200.0)
    val (_, name, _, salary) = employee
    println("$name cobra $salary €")
}
```

### Explicación paso a paso
1. El orden de componentes sigue el orden de `id`, `name`, `position` y `salary`.
2. `_` descarta los componentes que no necesitamos.
3. `name` recibe el segundo componente y `salary`, el cuarto.

## Ejercicio 7.3 · Pair, Triple y desestructuración

> [!question] Enunciado
> Define una función privada llamada `calculateAndReport` que acepte un único parámetro `numbers` de tipo `List<Double>`. La función debe devolver un `Triple` con la siguiente estructura y significado: `Triple<Double, Double, String>` (suma, promedio, estado).
> Dentro de la función, haz lo siguiente:
> - Si la lista `numbers` está vacía, devuelve un `Triple` con `0.0`, `0.0`, y el estado `"EMPTY"`.
> - Si la lista no está vacía, calcula la suma y el promedio.
> - Determina el estado: si el promedio es mayor que `10.0`, el estado es `"HIGH"`, de lo contrario es `"LOW"`.
> - Devuelve los tres valores en un `Triple` (usa su constructor normal).
> En la función `main`:
> - Llama a `calculateAndReport` con una lista de ejemplo: `listOf(12.5, 8.0, 15.0)`.
> - Utiliza la **desestructuración** para asignar el resultado del _Triple_ directamente a tres variables inmutables con nombres significativos (`totalSum`, `avg`, `status`).
> - Imprime un mensaje formateado usando estas tres variables.


### Clases y métodos introducidos
- `Triple<A, B, C>`: agrupa tres valores; `toList()` no es necesario aquí.
- `sum()`, `average()` y desestructuración de `Triple`.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Pair y Triple|`Triple` y sus componentes]]

#### Ejemplo simple de funcionamiento
```kotlin
val (suma, media, estado) = Triple(35.5, 11.8, "HIGH")
```

### Código fuente (`Ejercicio7.3/src/Main.kt`)

```kotlin
private fun calculateAndReport(numbers: List<Double>): Triple<Double, Double, String> {
    if (numbers.isEmpty()) return Triple(0.0, 0.0, "EMPTY")

    val sum = numbers.sum()
    val average = numbers.average()
    val status = if (average > 10.0) "HIGH" else "LOW"
    return Triple(sum, average, status)
}

fun main() {
    val (totalSum, avg, status) = calculateAndReport(listOf(12.5, 8.0, 15.0))
    println("Suma: $totalSum, promedio: $avg, estado: $status")
}
```

### Explicación paso a paso
1. La lista vacía se gestiona antes de calcular; así no se obtiene un promedio inválido.
2. `sum()` y `average()` calculan total y media de los valores.
3. La condición compara la media con `10.0` y asigna `HIGH` o `LOW`.
4. El `Triple` se desestructura en suma, promedio y estado.

## Ejercicio 7.4 · Clases abstractas

> [!question] Enunciado
> Define una clase abstracta llamada `Animal` para representar diferentes tipos de animales en un zoológico. La clase debe contener las siguientes propiedades y métodos:
> - Propiedad `name` (`String`): Nombre del animal.
> - Propiedad `age` (`Int`): Edad del animal.
> - Método abstracto `makeSound()`: Debe ser implementado por las subclases para definir el sonido que hace el animal.
> - Método `info()`: Debe imprimir el nombre y la edad del animal.
> Luego, define dos subclases concretas llamadas `Lion` y `Elephant` que hereden de `Animal` y proporcionen implementaciones para el método `makeSound()`.
> Implementa una función main que cree una instancia de `Lion` y otra de `Elephant`. Llame al método `info()` y `makeSound()` para cada instancia.


### Clases y métodos introducidos
- `abstract class`: no se puede instanciar directamente; define comportamiento común y miembros abstractos.
- `override`: implementa un método abstracto en cada subclase.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Clases abstractas|clases abstractas y miembros abstractos]] · [[Programación Orientada a Objetos 1#11. Herencia|herencia]]

#### Ejemplo simple de funcionamiento
```kotlin
abstract class Figura { abstract fun dibujar() }
class Circulo : Figura() { override fun dibujar() = println("○") }
```

### Código fuente (`Ejercicio7.4/src/Main.kt`)

```kotlin
abstract class Animal(val name: String, val age: Int) {
    abstract fun makeSound()

    fun info() {
        println("$name tiene $age años")
    }
}

class Lion(name: String, age: Int) : Animal(name, age) {
    override fun makeSound() = println("Roar")
}

class Elephant(name: String, age: Int) : Animal(name, age) {
    override fun makeSound() = println("Trumpet")
}

fun main() {
    val lion = Lion("Simba", 5)
    val elephant = Elephant("Dumbo", 12)

    lion.info()
    lion.makeSound()
    elephant.info()
    elephant.makeSound()
}
```

### Explicación paso a paso
1. `Animal` almacena nombre y edad y declara `makeSound()` sin implementación.
2. `Lion` y `Elephant` heredan las propiedades y deben sobrescribir `makeSound()`.
3. `info()` es concreto y se hereda sin sobrescritura.

## Ejercicio 7.5 · Enumeraciones con propiedades

> [!question] Enunciado
> Define una enumeración llamada `OrderStatus` para gestionar los diferentes estados de un pedido en una tienda. La enumeración debe contener los siguientes estados y sus propiedades asociadas:
> - `PENDING` con la propiedad `description` como "Order has been received".
> - `PROCESSING` con la propiedad `description` como "Order is being processed".
> - `SHIPPED` con la propiedad `description` como "Order has been shipped".
> - `DELIVERED` con la propiedad `description` como "Order has been delivered".
> - `CANCELLED` con la propiedad `description` como "Order has been cancelled".
> Cada estado debe tener un método `printStatus()` que imprima el nombre del estado y su descripción.
> Implementa una clase llamada `Order` para representar un pedido, que contenga las siguientes propiedades: `id` y `status` (de tipo `OrderStatus`).
> Implementa una función main que cree una instancia de Order con un estado inicial, imprima el estado inicial del pedido, actualice el estado del pedido a otro estado y vuelva a imprimirlo.


### Clases y métodos introducidos
- `enum class`: define un conjunto finito de objetos constantes.
- Constructor de enum: cada constante aporta argumentos para sus propiedades.
- Propiedad `var status`: permite actualizar estado del pedido.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Enumeraciones|enumeraciones con propiedades y métodos]] · [[Programación Orientada a Objetos 1#5. Propiedades|propiedades mutables]]

#### Ejemplo simple de funcionamiento
```kotlin
enum class Estado(val descripcion: String) { ABIERTO("En curso") }
```

### Código fuente (`Ejercicio7.5/src/Main.kt`)

```kotlin
enum class OrderStatus(val description: String) {
    PENDING("Order has been received"),
    PROCESSING("Order is being processed"),
    SHIPPED("Order has been shipped"),
    DELIVERED("Order has been delivered"),
    CANCELLED("Order has been cancelled");

    fun printStatus() {
        println("$name: $description")
    }
}

class Order(val id: Int, var status: OrderStatus)

fun main() {
    val order = Order(42, OrderStatus.PENDING)
    order.status.printStatus()

    order.status = OrderStatus.SHIPPED
    order.status.printStatus()
}
```

### Explicación paso a paso
1. Cada constante de `OrderStatus` recibe su descripción en el constructor.
2. El punto y coma separa las constantes de los miembros de la enumeración.
3. `name` es una propiedad heredada que contiene el identificador de la constante.
4. `status` es `var`, por lo que `main` puede actualizar el estado del pedido.

## Ejercicio 7.6 · Interfaces y herencia de interfaces

> [!question] Enunciado
> Define una interfaz llamada `Device` para representar dispositivos electrónicos. La interfaz debe contener las siguientes propiedades y métodos:
> - Propiedad `brand` (`String`): Marca del dispositivo.
> - Método `turnOn()` con código por defecto que imprima "Turning on the device".
> - Método `turnOff()` sin implementación.
> Luego, define otra interfaz llamada `SmartDevice` que herede de `Device` y agregue las siguientes propiedades y métodos:
> - Propiedad `os` (`String`): Sistema operativo del dispositivo.
> - Método `connectToWiFi()` con código por defecto que imprima "Connecting to WiFi".
> Implementa una clase llamada `Smartphone` que implemente la interfaz `SmartDevice` y proporcione una implementación para los métodos requeridos y sobrescriba alguno de los métodos con implementación por defecto.
> Implementa una función main que cree una instancia de `Smartphone` y llame a todos los métodos disponibles para la instancia.


### Clases y métodos introducidos
- Las interfaces declaran propiedades y operaciones que una clase debe implementar.
- Los métodos con cuerpo tienen implementación por defecto.
- Una interfaz puede heredar de otra interfaz.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Interfaces|interfaces, propiedades y métodos por defecto]]

#### Ejemplo simple de funcionamiento
```kotlin
interface Activable { fun encender() = println("Encendido") }
```

### Código fuente (`Ejercicio7.6/src/Main.kt`)

```kotlin
interface Device {
    val brand: String
    fun turnOn() = println("Turning on the device")
    fun turnOff()
}

interface SmartDevice : Device {
    val os: String
    fun connectToWiFi() = println("Connecting to WiFi")
}

class Smartphone(
    override val brand: String,
    override val os: String,
) : SmartDevice {
    override fun turnOff() = println("Turning off $brand")
    override fun turnOn() = println("Starting $brand on $os")
}

fun main() {
    val phone = Smartphone("Example", "Android")
    phone.turnOn()
    phone.connectToWiFi()
    phone.turnOff()
}
```

### Explicación paso a paso
1. `SmartDevice` hereda `brand`, `turnOn()` y `turnOff()` de `Device`.
2. `Smartphone` implementa las dos propiedades y el único método abstracto restante, `turnOff()`.
3. También sobrescribe `turnOn()`; `connectToWiFi()` usa la implementación por defecto.

## Ejercicio 7.7 · Object expressions y gestión de eventos

> [!question] Enunciado
> Define una interfaz llamada `EventListener` para manejar eventos en una aplicación. La interfaz debe contener el método `onEventOccurred(event: String)`, para manejar la ocurrencia de un evento, que recibe una cadena con la descripción del evento.
> Luego, define una clase llamada `EventManager` que maneje la gestión de eventos. La clase debe contener los siguientes métodos:
> - `registerListener(listener: EventListener)`: Método para registrar un `EventListener`.
> - `triggerEvent(event: String)`: Método para desencadenar un evento, notificando a todos los `EventListener` registrados.
> Implementa una función main que cree una instancia de `EventManager`, utilice una _object expression_ para crear un `EventListener` anónimo que imprima los eventos recibidos, y utilice otra _object expression_ para crear una subclase anónima de `EventManager` que agregue una funcionalidad adicional al método `triggerEvent()`. Además, se deberá registrar el `EventListener` en la instancia de `EventManager` y desencadenar un evento llamando al método `triggerEvent()`.


### Clases y métodos introducidos
- _Object expression_: crea una instancia anónima de una interfaz o subclase.
- Lista mutable de listeners para registrar varias suscripciones.
- `open` permite crear una subclase anónima de `EventManager`.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Anonymous object expression|expresiones de objeto anónimo]] · [[Programación Orientada a Objetos 1#11. Herencia|herencia y `open`]]

#### Ejemplo simple de funcionamiento
```kotlin
val listener = object : Runnable { override fun run() = println("Evento") }
```

### Código fuente (`Ejercicio7.7/src/Main.kt`)

```kotlin
interface EventListener {
    fun onEventOccurred(event: String)
}

open class EventManager {
    private val listeners = mutableListOf<EventListener>()

    fun registerListener(listener: EventListener) {
        listeners.add(listener)
    }

    open fun triggerEvent(event: String) {
        for (listener in listeners) listener.onEventOccurred(event)
    }
}

fun main() {
    val listener = object : EventListener {
        override fun onEventOccurred(event: String) {
            println("Evento recibido: $event")
        }
    }

    val manager = object : EventManager() {
        override fun triggerEvent(event: String) {
            println("Preparando evento")
            super.triggerEvent(event)
        }
    }

    manager.registerListener(listener)
    manager.triggerEvent("Inicio de sesión")
}
```

### Explicación paso a paso
1. `EventListener` define el contrato de notificación.
2. `EventManager` conserva listeners y les reenvía cada evento.
3. La primera expresión `object` implementa el listener sin declarar una clase con nombre.
4. La segunda crea una subclase anónima que añade una acción antes de llamar a `super.triggerEvent()`.

## Ejercicio 7.8 · Sealed class para formas de pago

> [!question] Enunciado
> Define una _sealed class_ llamada `Payment` para representar diferentes formas de pago en una aplicación. Debe tener las siguientes subclases:
> - `CreditCardPayment`, con las propiedades `cardNumber`, `cardHolder` y `amount`.
> - `PaypalPayment`, con las propiedades `email` y `amount`.
> - `CashPayment`, con la propiedad `amount`.
> Luego, define una función `processPayment(payment: Payment)`, que reciba un objeto de tipo `Payment` y procese el pago de acuerdo con su tipo. La función debe usar una estructura when para manejar los diferentes tipos de pagos y debe imprimir un mensaje específico para cada tipo.
> Además, implementa una función `main` que cree una instancia de cada tipo de pago (`CreditCardPayment`, `PaypalPayment`, y `CashPayment`), y llame a la función processPayment para cada instancia de pago.


### Clases y métodos introducidos
- `sealed class`: restringe las subclases directas y permite un `when` exhaustivo.
- `data class`: representa cada forma de pago con sus datos.
- `when`: selecciona el procesamiento según subtipo.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Sealed classes|jerarquías selladas y `when`]] · [[Programación Orientada a Objetos 2#Data class|data classes]]

#### Ejemplo simple de funcionamiento
```kotlin
sealed class Resultado

data class Exito(val texto: String) : Resultado()
```

### Código fuente (`Ejercicio7.8/src/Main.kt`)

```kotlin
sealed class Payment {
    data class CreditCardPayment(
        val cardNumber: String,
        val cardHolder: String,
        val amount: Double,
    ) : Payment()

    data class PaypalPayment(val email: String, val amount: Double) : Payment()
    data class CashPayment(val amount: Double) : Payment()
}

fun processPayment(payment: Payment) {
    when (payment) {
        is Payment.CreditCardPayment ->
            println("Tarjeta de ${payment.cardHolder}: ${payment.amount} €")
        is Payment.PaypalPayment ->
            println("PayPal ${payment.email}: ${payment.amount} €")
        is Payment.CashPayment ->
            println("Efectivo: ${payment.amount} €")
    }
}

fun main() {
    processPayment(Payment.CreditCardPayment("1234", "Ada", 25.0))
    processPayment(Payment.PaypalPayment("ada@example.com", 15.0))
    processPayment(Payment.CashPayment(10.0))
}
```

### Explicación paso a paso
1. Las tres formas de pago son subclases directas y conocidas de `Payment`.
2. `when` contempla todos los subtipos, por lo que no necesita rama `else`.
3. En cada rama se aplica smart cast y quedan disponibles las propiedades específicas.

## Ejercicio 7.9 · Jerarquía sellada y when exhaustivo

> [!question] Enunciado
> Define una `enum class` llamada `Priority` con los siguientes **tres** posibles valores y ninguna propiedad adicional: `LOW`, `MEDIUM`, y `HIGH`.
> Define una `sealed class` llamada `UserAlert`. Dentro del mismo archivo, define las siguientes subclases directas de `UserAlert`:
> - Una `data class` llamada `EmailAlert` con una propiedad `sender` (`String`) y una propiedad `priority` (`Priority`).
> - Una `data class` llamada `SmsAlert` con una propiedad `phoneNumber` (`String`) y una propiedad `priority` (`Priority`).
> - Un `object` llamado `SystemMaintenance`.
> Define una función _top-level_ llamada `processAlert` que acepte un parámetro `alert` de tipo `UserAlert` y **utilice una expresión `when` exhaustiva** para imprimir un mensaje:
> - Si es `EmailAlert`, imprime el remitente y su prioridad.
> - Si es `SmsAlert`, imprime el número y su prioridad.
> - Si es `SystemMaintenance`, imprime "Scheduled downtime starting now."
> - **No debe haber rama `else`**.
> En la función `main`, crea una instancia de cada subclase de `UserAlert` y pásala a `processAlert`.


### Clases y métodos introducidos
- `enum class`: prioridad finita compartida por distintos tipos de alerta.
- `sealed class`: jerarquía restringida de alertas.
- `when` exhaustivo: comprueba los subtipos sin rama `else`.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Enumeraciones|enumeraciones]] · [[Programación Orientada a Objetos 2#Sealed classes|clases selladas y `when` exhaustivo]]

#### Ejemplo simple de funcionamiento
```kotlin
sealed interface Estado

data object Cargando : Estado
```

### Código fuente (`Ejercicio7.9/src/Main.kt`)

```kotlin
enum class Priority { LOW, MEDIUM, HIGH }

sealed class UserAlert {
    data class EmailAlert(val sender: String, val priority: Priority) : UserAlert()
    data class SmsAlert(val phoneNumber: String, val priority: Priority) : UserAlert()
    data object SystemMaintenance : UserAlert()
}

fun processAlert(alert: UserAlert) {
    when (alert) {
        is UserAlert.EmailAlert -> println("Email de ${alert.sender}: ${alert.priority}")
        is UserAlert.SmsAlert -> println("SMS a ${alert.phoneNumber}: ${alert.priority}")
        UserAlert.SystemMaintenance -> println("Scheduled downtime starting now.")
    }
}

fun main() {
    processAlert(UserAlert.EmailAlert("admin@example.com", Priority.HIGH))
    processAlert(UserAlert.SmsAlert("555123456", Priority.MEDIUM))
    processAlert(UserAlert.SystemMaintenance)
}
```

### Explicación paso a paso
1. `Priority` solo admite `LOW`, `MEDIUM` y `HIGH`.
2. `UserAlert` permite exactamente los tres tipos declarados.
3. `when` cubre cada subtipo y no necesita `else`; el compilador avisa si jerarquía cambia.

## Ejercicio 7.10 · Sealed interface para respuestas de API

> [!question] Enunciado
> Define una _sealed interface_ llamada `ApiResponse` para representar diferentes tipos de respuestas de una API. La interfaz debe tener las siguientes implementaciones:
> - Clase `SuccessResponse`, con la propiedad `data`, que contiene el texto de la respuesta.
> - Clase `ErrorResponse`, con las propiedades `errorCode`, para el código de error, y `errorMessage` para el mensaje de error.
> - Object `Loading`, para representar el estado de que se está obteniendo la respuesta.
> Luego, define una función `handleResponse(response: ApiResponse)` que tome un objeto de tipo `ApiResponse` y maneje la respuesta de acuerdo con su tipo. La función debe usar una estructura `when` para manejar los diferentes tipos de respuestas y debe imprimir un mensaje específico para cada tipo.
> Implementa una función main que cree una instancia de cada tipo de respuesta (`SuccessResponse`, `ErrorResponse`, y `Loading`), y llame a la función handleResponse para cada instancia de respuesta.


### Clases y métodos introducidos
- `sealed interface`: restringe las implementaciones directas y permite `when` exhaustivo.
- `data class`: almacena datos de éxito o error.
- `object`: representa el estado único de carga.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Sealed interfaces|interfaces selladas]] · [[Programación Orientada a Objetos 2#Data class|data classes]] · [[Programación Orientada a Objetos 2#Sealed classes|`when` exhaustivo]]

#### Ejemplo simple de funcionamiento
```kotlin
sealed interface Respuesta
```

### Código fuente (`Ejercicio7.10/src/Main.kt`)

```kotlin
sealed interface ApiResponse {
    data class SuccessResponse(val data: String) : ApiResponse
    data class ErrorResponse(val errorCode: Int, val errorMessage: String) : ApiResponse
    data object Loading : ApiResponse
}

fun handleResponse(response: ApiResponse) {
    when (response) {
        is ApiResponse.SuccessResponse -> println("Respuesta: ${response.data}")
        is ApiResponse.ErrorResponse ->
            println("Error ${response.errorCode}: ${response.errorMessage}")
        ApiResponse.Loading -> println("Cargando respuesta…")
    }
}

fun main() {
    handleResponse(ApiResponse.SuccessResponse("Datos recibidos"))
    handleResponse(ApiResponse.ErrorResponse(404, "No encontrado"))
    handleResponse(ApiResponse.Loading)
}
```

### Explicación paso a paso
1. `ApiResponse` define tres estados posibles: éxito, error y carga.
2. Las respuestas con datos se modelan con `data class`; `Loading` es un objeto único.
3. `when` distingue exhaustivamente los tres tipos y accede a sus campos específicos.

## Ejercicio 7.11 · Inline value class para teléfono

> [!question] Enunciado
> Define una _inline value class_ llamada `PhoneNumber` que encapsule un número de teléfono como un String. La clase debe validar que el número de teléfono tenga exactamente 9 dígitos. Si el número no es válido, debe lanzar una excepción en el momento de la creación del objeto.
> Luego, define una función `printPhoneNumber()` que reciba un objeto de tipo `PhoneNumber` y muestre el número en la consola.
> Implementa una función `main` que intente crear una instancia de `PhoneNumber` con un número válido y otra instancia con un número inválido y maneje la excepción. Finalmente deberá llamar a la función `printPhoneNumber()` con la instancia válida creada.


### Clases y métodos introducidos
- `@JvmInline value class`: envuelve un valor con un tipo distinto y una única propiedad del constructor primario.
- `init` y `require`: validan el valor al crear la instancia.
- Expresión regular `\d{9}`: exige exactamente nueve dígitos.

> **Términos explicados:** [[Programación Orientada a Objetos 2#Inline value classes|value classes y restricciones]] · [[Programación Orientada a Objetos 2#Clases abstractas|validación con `require`]]

#### Ejemplo simple de funcionamiento
```kotlin
@JvmInline
value class Codigo(val valor: String) {
    init { require(valor.isNotBlank()) }
}
```

### Código fuente (`Ejercicio7.11/src/Main.kt`)

```kotlin
@JvmInline
value class PhoneNumber(val value: String) {
    init {
        require(Regex("\\d{9}").matches(value)) {
            "Phone number must contain exactly 9 digits"
        }
    }
}

fun printPhoneNumber(phoneNumber: PhoneNumber) {
    println(phoneNumber.value)
}

fun main() {
    val validNumber = PhoneNumber("612345678")
    printPhoneNumber(validNumber)

    try {
        PhoneNumber("12345")
    } catch (e: IllegalArgumentException) {
        println("Número inválido: ${e.message}")
    }
}
```

### Explicación paso a paso
1. Una value class debe tener exactamente una propiedad en el constructor primario.
2. `Regex("\\d{9}")` comprueba nueve dígitos y rechaza cualquier longitud o carácter distinto.
3. `require` lanza `IllegalArgumentException` durante la creación si el número no cumple el formato.
4. El número válido se imprime; la excepción del inválido se captura en `main`.
