## Ejercicio 11.1 · Creación de colecciones

> [!question] Enunciado
> Define un `listOf` llamado `productNames` que contenga al menos cinco nombres de productos (`String`).
>
> Define un `setOf` llamado `uniqueCategories` que contenga al menos tres categorías (`String`). Asegúrate de repetir una categoría para verificar que el `Set` elimina duplicados.
>
> Define un `mapOf` llamado `priceMap` donde las claves sean los nombres de los productos (de `productNames`) y los valores sean sus precios (`Double`).
>
> Crea un `mutableListOf` llamado `shoppingList` a partir de los dos primeros elementos de `productNames`. Crea un `mutableMapOf` llamado `stockLevels` inicializado con los siguientes pares: `("ProductA" to 10)`, `("ProductB" to 5)`. Utiliza la función `List()` con una _lambda_ para crear una `List<Int>` de tamaño 5 llamada `inventoryIds`. La _lambda_ debe asignar a cada elemento su índice más 100 (e.g., 100, 101, 102, …).
>
> En la función `main`:
>
> - Imprime el tamaño de `uniqueCategories` para confirmar que los duplicados fueron eliminados.
> - Añade un nuevo producto (`"ProductC"`) a `shoppingList`.
> - Actualiza el stock de `"ProductA"` en `stockLevels` a 15.
> - Imprime `inventoryIds` y `stockLevels` después de las modificaciones.

### Clases y métodos introducidos
- `listOf()`, `setOf()`, `mapOf()`: crean colecciones de **solo lectura**.
- `mutableListOf()`, `mutableMapOf()`: crean colecciones **mutables** (se pueden añadir, quitar o cambiar elementos).
- `"clave" to valor`: crea un `Pair`, que es lo que recibe `mapOf`.
- `List(5) { it + 100 }`: crea una lista de 5 elementos; la lambda recibe el índice (`it`) y devuelve el valor.

> **Términos explicados:** [[11 - Colecciones#3. Creación de colecciones|3. Creación de colecciones]]

### Código fuente (`Ejercicio11.1/src/Main.kt`)

```kotlin
// Colecciones de solo lectura
val productNames = listOf("ProductA", "ProductB", "ProductC", "ProductD", "ProductE")
val uniqueCategories = setOf("Electrónica", "Hogar", "Electrónica", "Deporte")   // "Electrónica" repetida
val priceMap = mapOf(
    "ProductA" to 19.99,
    "ProductB" to 5.50,
    "ProductC" to 120.0,
    "ProductD" to 45.25,
    "ProductE" to 8.75,
)

// Colecciones mutables
val shoppingList = mutableListOf(productNames[0], productNames[1])
val stockLevels = mutableMapOf("ProductA" to 10, "ProductB" to 5)

// List(tamaño) { índice -> valor }
val inventoryIds = List(5) { it + 100 }

fun main() {
    // El Set descarta el duplicado: 3 categorías, no 4
    println("uniqueCategories: $uniqueCategories (tamaño ${uniqueCategories.size})")

    shoppingList.add("ProductC")
    stockLevels["ProductA"] = 15

    println("shoppingList: $shoppingList")
    println("priceMap: $priceMap")
    println("inventoryIds: $inventoryIds")
    println("stockLevels: $stockLevels")
}
```

> [!tip] Salida por consola
> ```text
> uniqueCategories: [Electrónica, Hogar, Deporte] (tamaño 3)
> shoppingList: [ProductA, ProductB, ProductC]
> priceMap: {ProductA=19.99, ProductB=5.5, ProductC=120.0, ProductD=45.25, ProductE=8.75}
> inventoryIds: [100, 101, 102, 103, 104]
> stockLevels: {ProductA=15, ProductB=5}
> ```

### Explicación paso a paso
1. Los productos se llaman `ProductA`…`ProductE` para que coincidan con las claves de `stockLevels` y con el `"ProductC"` que pide añadir el enunciado.
2. `uniqueCategories` tiene `"Electrónica"` dos veces, pero el `Set` solo la guarda una: su tamaño es 3.
3. `shoppingList` se crea con los dos primeros productos, accediendo por índice (`productNames[0]`, `productNames[1]`).
4. Las colecciones se declaran con `val`, pero `shoppingList` y `stockLevels` se pueden modificar: `val` impide **reasignar la variable**, no cambiar el contenido de una colección mutable.
5. `stockLevels["ProductA"] = 15` sustituye el valor de una clave que ya existe (`put`).
6. `mapOf` y `setOf` conservan el orden de inserción al imprimir (en la JVM son `LinkedHashMap` y `LinkedHashSet`).

## Ejercicio 11.2 · Conversión entre colecciones con toSet y toMutableList

> [!question] Enunciado
> Define un `listOf` llamado `rawNames` que contenga los siguientes nombres (incluyendo duplicados y variaciones de mayúsculas): `"Alice"`, `"bob"`, `"Alice"`, `"charlie"`, `"Bob"`.
>
> Aplica la función `map` a `rawNames` para convertir todos los nombres a minúsculas.
>
> Aplica la función **`toSet()`** al resultado del mapeo para obtener un conjunto de nombres únicos y en minúsculas. Almacena el resultado en una variable inmutable llamada `normalizedNames`. Imprime `normalizedNames`.
>
> Aplica la función **`toMutableList()`** al conjunto `normalizedNames` para obtener una lista que se pueda modificar. Almacena el resultado en una variable mutable llamada `editableList`.
>
> Añade un nuevo nombre (`"david"`) a `editableList`.
>
> Imprime `editableList`.

### Clases y métodos introducidos
- `map { it.lowercase() }`: crea una lista nueva con cada nombre en minúsculas.
- `toSet()`: crea un `Set` nuevo, sin duplicados.
- `toMutableList()`: crea una `MutableList` nueva con los mismos elementos.

> **Términos explicados:** [[11 - Colecciones#4. Obtener una colección a partir de otra|4. Obtener una colección a partir de otra]]

### Código fuente (`Ejercicio11.2/src/Main.kt`)

```kotlin
fun main() {
    val rawNames = listOf("Alice", "bob", "Alice", "charlie", "Bob")

    // map crea una lista en minúsculas; toSet elimina los repetidos
    val normalizedNames = rawNames.map { it.lowercase() }.toSet()
    println("normalizedNames: $normalizedNames")

    // toMutableList crea una lista NUEVA que sí se puede modificar
    val editableList = normalizedNames.toMutableList()
    editableList.add("david")
    println("editableList: $editableList")
}
```

> [!tip] Salida por consola
> ```text
> normalizedNames: [alice, bob, charlie]
> editableList: [alice, bob, charlie, david]
> ```

### Explicación paso a paso
1. Primero hay que normalizar: `"Bob"` y `"bob"` son distintos hasta que se pasan a minúsculas.
2. `toSet()` elimina los repetidos y quedan tres nombres. El orden se conserva porque en la JVM `toSet()` devuelve un `LinkedHashSet`.
3. `normalizedNames` es un `Set` de solo lectura: no tiene `add()`. Por eso se convierte con `toMutableList()`.
4. El enunciado pide una "variable mutable", pero lo que tiene que ser mutable es la **lista**, no la variable. `val editableList` basta para hacer `add()`: nunca se reasigna.

## Ejercicio 11.3 · Operador corchete y operadores + y - en colecciones

> [!question] Enunciado
> Define las siguientes estructuras:
>
> - Una lista mutable llamada `inventory` inicializada con: `"Laptop"`, `"Monitor"`, `"Mouse"`.
> - Un mapa mutable llamado `prices` inicializado con: `"Laptop" to 1200.0`, `"Monitor" to 300.0`.
> - Una variable (`var`) que contenga una lista inmutable llamada `ordersToday` inicializada con: `"Laptop"`, `"Monitor"`.
>
> Realiza las siguientes acciones usando el operador corchete:
>
> - **Lectura**: Imprime el precio del `"Laptop"` desde el mapa `prices`.
> - **Escritura**: Cambia el elemento en el índice 2 de `inventory` de `"Mouse"` a `"Keyboard"`.
> - **Adición de Clave/Valor**: Añade un nuevo producto al mapa `prices`: `"Keyboard"` con un precio de `50.0`.
>
> Realiza las siguientes acciones:
>
> - **Creación Inmutable (`+`)**: Crea una nueva lista llamada `newOrder` que sea el resultado de añadir `"Keyboard"` a la lista `ordersToday`. Imprime `newOrder`.
> - **Reasignación Mutable (`+=`)**: Usa el operador `+=` para añadir `"Charger"` a la variable `ordersToday`.
> - **Substracción y Reasignación (`-=`)**: Usa el operador `-=` para eliminar `"Monitor"` de la variable `ordersToday`.
> - Imprime el estado final de `ordersToday` y `inventory`.

### Clases y métodos introducidos
- `lista[i]` / `lista[i] = x`: se traducen a `get(i)` / `set(i, x)`.
- `mapa[clave]` / `mapa[clave] = x`: se traducen a `get(clave)` / `put(clave, x)`. Si la clave no existe, `put` la añade.
- `lista + x` / `lista - x`: devuelven una lista **nueva**; la original no cambia.
- Con una `var` de tipo `List`, `lista += x` equivale a `lista = lista + x`.

> **Términos explicados:** [[11 - Colecciones#5. Operadores sobrecargados en colecciones|5. Operadores sobrecargados en colecciones]]

### Código fuente (`Ejercicio11.3/src/Main.kt`)

```kotlin
fun main() {
    val inventory = mutableListOf("Laptop", "Monitor", "Mouse")
    val prices = mutableMapOf("Laptop" to 1200.0, "Monitor" to 300.0)
    var ordersToday = listOf("Laptop", "Monitor")     // var + lista de solo lectura

    // Operador corchete
    println("Precio del Laptop: ${prices["Laptop"]}")  // lectura: prices.get("Laptop")
    inventory[2] = "Keyboard"                          // escritura: inventory.set(2, "Keyboard")
    prices["Keyboard"] = 50.0                          // nueva clave: prices.put("Keyboard", 50.0)

    // Operadores + y -
    val newOrder = ordersToday + "Keyboard"            // lista nueva; ordersToday no cambia
    println("newOrder: $newOrder")

    ordersToday += "Charger"                           // ordersToday = ordersToday + "Charger"
    ordersToday -= "Monitor"                           // ordersToday = ordersToday - "Monitor"

    println("ordersToday: $ordersToday")
    println("inventory: $inventory")
    println("prices: $prices")
}
```

> [!tip] Salida por consola
> ```text
> Precio del Laptop: 1200.0
> newOrder: [Laptop, Monitor, Keyboard]
> ordersToday: [Laptop, Charger]
> inventory: [Laptop, Monitor, Keyboard]
> prices: {Laptop=1200.0, Monitor=300.0, Keyboard=50.0}
> ```

### Explicación paso a paso
1. `prices["Laptop"]` devuelve un `Double?`, porque la clave podría no existir. En la plantilla se imprime directamente.
2. `inventory[2] = "Keyboard"` cambia el elemento en la posición 2 (la tercera), que era `"Mouse"`.
3. `prices["Keyboard"] = 50.0` **añade** una entrada, porque la clave no existía.
4. `ordersToday + "Keyboard"` crea `newOrder` sin tocar `ordersToday`, que sigue siendo `[Laptop, Monitor]`.
5. `ordersToday` es una `List` de solo lectura dentro de una `var`: `+=` y `-=` no modifican la lista, sino que crean una nueva y la **reasignan** a la variable. Por eso hace falta `var`.

## Ejercicio 11.4 · Métodos y propiedades de listas con testScores

> [!question] Enunciado
> - Define un `listOf<Int>` llamado `testScores` con al menos seis puntuaciones (por ejemplo, `85, 92, 78, 95, 88, 70`).
> - Imprime el número total de puntuaciones.
> - Imprime el índice de la última puntuación.
> - Encuentra la posición del puntaje 95 e imprímela.
> - Intenta obtener el elemento en el índice 10. Imprime el resultado.
> - Obtén el elemento en el índice 10. Si el índice no existe, la _lambda_ debe retornar el valor `50` (la puntuación de "suspenso"). Imprime este resultado.
> - Verificar si la puntuación `78` está en la lista e imprime el booleano resultante.
> - Obtén una nueva lista de solo tres puntuaciones barajadas al azar. Imprime la lista resultante.
> - Crea una lista de todas las puntuaciones excepto la última.
> - Obtén una cadena con los valores de la lista en formato [85 | 92 | ...]. Imprime la cadena formateada.

### Clases y métodos introducidos
- `size` / `lastIndex`: número de elementos / índice del último (`size - 1`).
- `indexOf(x)`: posición de `x`, o `-1` si no está.
- `getOrNull(i)` / `getOrElse(i) { … }`: acceso seguro; devuelven `null` o el valor de la lambda si el índice no existe.
- `x in lista`: se traduce a `lista.contains(x)`.
- `shuffled()` + `take(3)`: baraja y se queda con los tres primeros.
- `dropLast(1)`: todos menos el último.
- `joinToString(separator, prefix, postfix)`: convierte la lista en texto.

> **Términos explicados:** [[11 - Colecciones#6. Métodos y propiedades de listas|6. Métodos y propiedades de listas]]

### Código fuente (`Ejercicio11.4/src/Main.kt`)

```kotlin
fun main() {
    val testScores = listOf(85, 92, 78, 95, 88, 70)

    println("Número de puntuaciones: ${testScores.size}")
    println("Índice de la última: ${testScores.lastIndex}")
    println("Posición del 95: ${testScores.indexOf(95)}")

    // get(10) lanzaría IndexOutOfBoundsException; getOrNull devuelve null
    println("Elemento en el índice 10: ${testScores.getOrNull(10)}")
    // getOrElse ejecuta la lambda si el índice no existe
    println("Índice 10 o suspenso: ${testScores.getOrElse(10) { 50 }}")

    println("¿Está el 78? ${78 in testScores}")                    // contains(78)
    println("Tres al azar: ${testScores.shuffled().take(3)}")       // cambia en cada ejecución

    val allButLast = testScores.dropLast(1)
    println("Todas menos la última: $allButLast")

    println(testScores.joinToString(separator = " | ", prefix = "[", postfix = "]"))
}
```

> [!tip] Salida por consola
> ```text
> Número de puntuaciones: 6
> Índice de la última: 5
> Posición del 95: 3
> Elemento en el índice 10: null
> Índice 10 o suspenso: 50
> ¿Está el 78? true
> Tres al azar: [85, 70, 95]
> Todas menos la última: [85, 92, 78, 95, 88]
> [85 | 92 | 78 | 95 | 88 | 70]
> ```

### Explicación paso a paso
1. "Intenta obtener el elemento en el índice 10": con `testScores[10]` el programa terminaría con `IndexOutOfBoundsException`. `getOrNull(10)` devuelve `null` sin fallar.
2. `getOrElse(10) { 50 }` ejecuta la lambda solo si el índice no existe; la lambda recibe el índice, aunque aquí no se usa.
3. `shuffled()` devuelve una lista **nueva** barajada (la original no cambia), y `take(3)` se queda con tres. Esa línea de la salida **cambia en cada ejecución**.
4. Se usan argumentos con nombre en `joinToString` (`separator = " | "`…) para que se vea qué es cada cadena.

## Ejercicio 11.5 · Procesamiento funcional de empleados

> [!question] Enunciado
> Define la siguiente `data class`:
>
> ```kotlin
> data class Employee(val name: String, val department: String, val salary: Double)
> ```
>
> Define una `listOf` llamada `employees` con al menos seis instancias que cubran dos o tres departamentos diferentes. Asegúrate de que haya salarios variados.
>
> En la función `main`, resuelve las siguientes tareas en orden, usando una cadena de llamadas (_chaining_) cuando sea posible:
>
> - Filtra la lista para incluir solo a los empleados del departamento `"IT"`.
> - Transforma la lista filtrada a una lista de _solo sus nombres_.
> - Almacena y muestra la lista de nombres de IT.
> - Verifica si _todos_ los empleados tienen un salario superior a `60000.0`. Muestra el resultado.
> - Cuenta cuántos empleados están en el departamento `"HR"`. Muestra el resultado.
> - Ordena la lista completa de empleados por salario, del más alto al más bajo.
> - Obtén solo los dos empleados mejor pagados. Imprime el nombre y salario de estos.
> - Encuentra el primer empleado cuyo nombre comience con la letra 'A'. Muestra el nombre del empleado encontrado o un mensaje si es `null`.

### Clases y métodos introducidos
- `filter { … }` + `map { … }`: seleccionar y transformar.
- `all { … }` / `count { … }`: ¿lo cumplen todos? / ¿cuántos lo cumplen?
- `sortedByDescending { it.salary }`: lista nueva ordenada de mayor a menor salario.
- `find { … }`: primer elemento que cumple la condición, o `null`.

> **Términos explicados:** [[11 - Colecciones#7. Procesamiento funcional de listas|7. Procesamiento funcional de listas]]

### Código fuente (`Ejercicio11.5/src/Main.kt`)

```kotlin
data class Employee(val name: String, val department: String, val salary: Double)

val employees = listOf(
    Employee("Ana", "IT", 72000.0),
    Employee("Bruno", "HR", 48000.0),
    Employee("Carla", "IT", 85000.0),
    Employee("David", "Sales", 61000.0),
    Employee("Alberto", "HR", 53000.0),
    Employee("Elena", "IT", 67000.0),
)

fun main() {
    // filter + map encadenados
    val itNames = employees
        .filter { it.department == "IT" }
        .map { it.name }
    println("Empleados de IT: $itNames")

    val allAbove60k = employees.all { it.salary > 60000.0 }
    println("¿Todos cobran más de 60000? $allAbove60k")

    val hrCount = employees.count { it.department == "HR" }
    println("Empleados de HR: $hrCount")

    // Ordenar de mayor a menor salario y quedarse con los dos primeros
    println("Los dos mejor pagados:")
    employees
        .sortedByDescending { it.salary }
        .take(2)
        .forEach { println("  ${it.name}: ${it.salary}") }

    // find devuelve el primero que cumple, o null
    val firstWithA = employees.find { it.name.startsWith("A") }
    println("Primer empleado que empieza por A: ${firstWithA?.name ?: "ninguno"}")
}
```

> [!tip] Salida por consola
> ```text
> Empleados de IT: [Ana, Carla, Elena]
> ¿Todos cobran más de 60000? false
> Empleados de HR: 2
> Los dos mejor pagados:
>   Carla: 85000.0
>   Ana: 72000.0
> Primer empleado que empieza por A: Ana
> ```

### Explicación paso a paso
1. Cada operación devuelve una colección nueva, así que se pueden **encadenar** (`filter` → `map`, `sortedByDescending` → `take` → `forEach`). Escribir una por línea ayuda a leer la cadena.
2. `all` devuelve `false` en cuanto encuentra a alguien que no cumple (Bruno cobra 48000).
3. `count` con lambda cuenta solo los que cumplen; sin lambda contaría todos.
4. `employees` no cambia nunca: `sortedByDescending` devuelve una lista nueva ordenada.
5. `find` devuelve `Employee?`. Con `?.name ?: "ninguno"` se muestra el nombre o un mensaje si es `null`. Ana es la primera de la lista que empieza por "A", por delante de Alberto.

## Ejercicio 11.6 · Secuencia infinita de usuarios premium

> [!question] Enunciado
> Define la siguiente constante para simular la ID de usuario que buscamos:
>
> ```kotlin
> const val TARGET_ID = 500
> ```
>
> Define una **función _top-level_ `isPremium(id: Int)`** que reciba la ID de un usuario y devuelva un `Boolean`. Esta función debe **imprimir** un mensaje para simular la verificación costosa en una base de datos: `"Checking premium status for ID: $id"`. Debe devolver `true` si la `id` es un número par y `false` en caso contrario.
>
> Crear una secuencia infinita de IDs de usuario, comenzando en `1` e incrementando en `1` en cada paso. Filtra esta secuencia infinita, ya que solo queremos usuarios _premium_. Limitar la búsqueda ya que solo necesitamos el primer usuario con ID 500 que sea premium. Obtén el nombre de dicho usuario (`"User-${it}"`). Finalmente, busca el nombre `"User-500"`.
>
> Almacena el resultado de toda la cadena de operaciones en una variable `foundUser`. Imprime el valor de `foundUser`.
>
> Observa y comenta cuántas veces se ejecutó el mensaje "Checking premium status for ID: ..."
>
> - Si se hubiera usado una `List` y operaciones _eager_, se habrían verificado los IDs hasta el 500 (500 llamadas a `isPremium`).
> - Con la `Sequence`, solo se verifica la cantidad de IDs necesarios hasta encontrar el par 500. (Solo se verifica el 500, ya que es el elemento 500 en la secuencia infinita, y el filtro se aplica antes del `find`).

> [!warning] La conclusión del enunciado es incorrecta
> Con la secuencia **no** se comprueba solo el ID 500. Como cada elemento recorre la cadena entero antes de pasar al siguiente, `filter` llama a `isPremium` con el 1, el 2, el 3… hasta llegar al 500, que es el que `find` acepta. Por eso son **500 llamadas**: el programa lleva un contador y lo imprime. Lo que ahorra la secuencia es todo lo que viene **después** del 500: se para ahí. Con una lista ansiosa, por ejemplo `(1..1000).toList()`, `filter` habría comprobado **los 1000 IDs** antes de que `find` empezara a buscar (comprobado: 1000 llamadas). Y sobre una fuente infinita, una lista ni siquiera podría crearse.

### Clases y métodos introducidos
- `generateSequence(1) { it + 1 }`: secuencia infinita 1, 2, 3…; cada elemento se calcula a partir del anterior.
- `takeWhile { it <= TARGET_ID }`: operación **intermedia** que corta la secuencia en cuanto la condición deja de cumplirse.
- `find { … }`: operación **terminal**: dispara la evaluación y se detiene en el primer elemento que cumple.

> **Términos explicados:** [[11 - Colecciones#8. Secuencias|8. Secuencias]]

### Código fuente (`Ejercicio11.6/src/Main.kt`)

```kotlin
const val TARGET_ID = 500

var premiumChecks = 0    // contador para comprobar cuántas veces se llama a isPremium

// Simula una consulta costosa a la base de datos
fun isPremium(id: Int): Boolean {
    premiumChecks++
    println("Checking premium status for ID: $id")
    return id % 2 == 0
}

fun main() {
    val foundUser = generateSequence(1) { it + 1 }   // 1, 2, 3, ... (infinita)
        .takeWhile { it <= TARGET_ID }               // limita la búsqueda hasta el ID 500
        .filter { isPremium(it) }                    // solo usuarios premium (ID par)
        .map { "User-$it" }                          // ID -> nombre
        .find { it == "User-$TARGET_ID" }            // terminal: aquí empieza a trabajar todo

    println("foundUser = $foundUser")
    println("isPremium se ejecutó $premiumChecks veces")
}
```

> [!tip] Salida por consola
> ```text
> Checking premium status for ID: 1
> Checking premium status for ID: 2
> Checking premium status for ID: 3
> ... (495 líneas más, una por cada ID del 4 al 498) ...
> Checking premium status for ID: 499
> Checking premium status for ID: 500
> foundUser = User-500
> isPremium se ejecutó 500 veces
> ```

### Explicación paso a paso
1. Hasta `find`, ninguna línea hace nada: `generateSequence`, `takeWhile`, `filter` y `map` solo **describen** los pasos (operaciones intermedias).
2. `find` pide elementos uno a uno: el 1 pasa por `takeWhile` y `filter` (`isPremium(1)` → `false`, se descarta); el 2 pasa `filter`, `map` lo convierte en `"User-2"` y `find` lo rechaza… y así sucesivamente.
3. Al llegar al 500, `map` da `"User-500"`, `find` lo acepta y **la secuencia se detiene**: el 501 nunca se genera.
4. `takeWhile` es el "límite" que pide el enunciado: aunque el usuario buscado no existiera, la búsqueda acabaría en el 500 y `find` devolvería `null`, en lugar de quedarse en un bucle infinito.
5. La salida real tiene 500 líneas de "Checking…"; aquí se muestran las primeras y las últimas.

## Esquema resumen de conceptos clave

| Concepto | Sintaxis | Comportamiento |
| --- | --- | --- |
| Creación | `listOf` · `setOf` · `mapOf` · `mutableListOf` · `mutableMapOf` · `List(5) { … }` | Solo lectura o mutables; el `Set` elimina duplicados (11.1). |
| `val` con colección mutable | `val shoppingList = mutableListOf(…)` | No se reasigna la variable, pero sí se modifica el contenido (11.1, 11.2). |
| Conversión | `map { … }.toSet()` · `toMutableList()` | Crea colecciones nuevas (11.2). |
| Operador `[]` | `prices["Laptop"]` · `inventory[2] = …` | `get`/`set`/`put` (11.3). |
| `+`, `-`, `+=`, `-=` | `ordersToday += "Charger"` | Lista nueva; con `var` se reasigna (11.3). |
| Acceso seguro | `getOrNull(10)` · `getOrElse(10) { 50 }` | Sin `IndexOutOfBoundsException` (11.4). |
| Encadenamiento | `filter { … }.map { … }` · `sortedByDescending { … }.take(2)` | Cada paso devuelve una colección nueva (11.5). |
| Predicados | `all` · `count` · `find` | Preguntar por los elementos (11.5). |
| Secuencia perezosa | `generateSequence(1) { it + 1 }.takeWhile { … }.filter { … }.find { … }` | Elemento a elemento; se detiene al encontrar el resultado (11.6). |
