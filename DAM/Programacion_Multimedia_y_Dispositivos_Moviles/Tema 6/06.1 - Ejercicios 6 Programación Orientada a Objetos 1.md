## Ejercicio 6.1 · Validar salario en `init`

> [!question] Enunciado
> Define `Employee` con propiedades `firstName: String`, `lastName: String` y `salary: Double`, declaradas en el constructor primario. Usa un bloque `init` para impedir salarios negativos; si `salary < 0`, lanza `IllegalArgumentException` con el mensaje `Salary must be non-negative`.

### Clases y métodos introducidos
- Constructor primario con propiedades `val`.
- Bloque `init`: valida los argumentos durante la construcción.
- `require(condicion) { mensaje }`: lanza `IllegalArgumentException` si la condición es falsa.

> **Términos explicados:** [[Programación Orientada a Objetos 1#2. Constructor primario y bloques de inicialización|constructor primario e `init`]] · [[04 - Estructuras básicas#8. Excepciones|`require` y excepciones]] · [[Programación Orientada a Objetos 1#5. Propiedades|propiedades `val`]]

#### Ejemplo simple de funcionamiento
```kotlin
class Edad(val valor: Int) {
    init {
        require(valor >= 0) { "La edad no puede ser negativa" }
    }
}
```

### Código fuente (`Ejercicio6.1/src/Main.kt`)

```kotlin
class Employee(
    val firstName: String,
    val lastName: String,
    val salary: Double,
) {
    init {
        require(salary >= 0.0) { "Salary must be non-negative" }
    }
}

fun main() {
    val employee = Employee("Ada", "Lovelace", 4200.0)
    println("${employee.firstName} ${employee.lastName}: ${employee.salary}")

    try {
        Employee("Grace", "Hopper", -1.0)
    } catch (e: IllegalArgumentException) {
        println(e.message)
    }
}
```

### Explicación paso a paso
1. `val` crea tres propiedades de solo lectura accesibles desde fuera de la clase.
2. Kotlin asigna los argumentos del constructor y ejecuta el bloque `init` durante la construcción.
3. Si el salario es negativo, `require` lanza la excepción con el mensaje indicado y no se crea el objeto.
4. El `try-catch` muestra el error sin detener el resto de `main`.

## Ejercicio 6.2 · Constructor secundario desde una cadena

> [!question] Enunciado
> Añade a `Employee` un constructor secundario que reciba una cadena con formato `firstName-lastName-salary` y cree el empleado con esos datos. La validación del salario del ejercicio anterior debe seguir aplicándose.

### Clases y métodos introducidos
- Constructor secundario: se declara con `constructor` dentro del cuerpo de la clase.
- Delegación con `this(...)`: todo constructor secundario debe delegar directa o indirectamente al constructor primario.
- `split` y `toDouble`: separan y convierten los datos de entrada.

> **Términos explicados:** [[Programación Orientada a Objetos 1#4. Constructores secundarios|constructor secundario y delegación con `this(...)`]] · [[01 - Introduccion a Kotlin#6.1 readln() y compañía|conversiones `toDouble()`]] · [[01 - Introduccion a Kotlin#6.3 Varios valores en una línea: split()|`split()`]] · [[Programación Orientada a Objetos 1#2. Constructor primario y bloques de inicialización|constructor primario e `init`]]

#### Ejemplo simple de funcionamiento
```kotlin
class Punto(val x: Int, val y: Int) {
    constructor(texto: String) : this(
        texto.split(",")[0].toInt(),
        texto.split(",")[1].toInt(),
    )
}
```

### Código fuente (`Ejercicio6.2/src/Main.kt`)

```kotlin
class Employee(
    val firstName: String,
    val lastName: String,
    val salary: Double,
) {
    init {
        require(salary >= 0.0) { "Salary must be non-negative" }
    }

    constructor(text: String) : this(
        text.split("-")[0],
        text.split("-")[1],
        text.split("-")[2].toDouble(),
    )
}

fun main() {
    val employee = Employee("Ada-Lovelace-4200.0")
    println("${employee.firstName} ${employee.lastName}: ${employee.salary}")
}
```

### Explicación paso a paso
1. `split("-")` separa la cadena en tres partes; los índices `0`, `1` y `2` seleccionan nombre, apellido y salario.
2. `toDouble()` convierte la tercera parte a `Double`; si el texto no tiene el formato esperado o el salario no es numérico, la conversión falla.
3. El constructor secundario delega directamente al constructor primario mediante `this(...)`.
4. El constructor primario ejecuta `init`, así que también rechaza los salarios negativos. Para mantener la solución sencilla, se presupone el formato indicado y que los nombres no contienen guiones.

## Ejercicio 6.3 · Propiedades en el constructor primario

> [!question] Enunciado
> Define `InventoryItem` con una propiedad inmutable `sku: String` y una propiedad mutable `stockQuantity: Int`, ambas declaradas directamente en el constructor primario. En `main`, crea `product` con SKU `KOT-001` y stock `10`, imprime el SKU, reduce el stock en 3 y muestra el nuevo valor.

### Clases y métodos introducidos
- `val` en el constructor: crea una propiedad de solo lectura.
- `var` en el constructor: crea una propiedad que se puede reasignar.
- Una referencia declarada con `val` puede apuntar a un objeto cuyas propiedades `var` sí cambian.

> **Términos explicados:** [[Programación Orientada a Objetos 1#5. Propiedades|propiedades `val` y `var`]] · [[Programación Orientada a Objetos 1#2. Constructor primario y bloques de inicialización|propiedades en el constructor primario]]

#### Ejemplo simple de funcionamiento
```kotlin
class Producto(val codigo: String, var cantidad: Int)

val producto = Producto("A-1", 5)
producto.cantidad -= 1
```

### Código fuente (`Ejercicio6.3/src/Main.kt`)

```kotlin
class InventoryItem(
    val sku: String,
    var stockQuantity: Int,
)

fun main() {
    val product = InventoryItem("KOT-001", 10)
    println("SKU: ${product.sku}")

    product.stockQuantity -= 3
    println("Stock restante: ${product.stockQuantity}")
}
```

### Explicación paso a paso
1. `sku` no puede reasignarse después de construir el objeto.
2. `stockQuantity` tiene un setter público porque se declaró con `var`.
3. `product` puede ser `val`: no se cambia la referencia a `InventoryItem`, sino una propiedad mutable del objeto.
4. El stock final es `7`.

## Ejercicio 6.4 · Setter y getter personalizados

> [!question] Enunciado
> Define `Employee` con el parámetro `initialExperienceMonths`. Crea en el cuerpo una propiedad mutable `experienceMonths` que rechace valores negativos mediante un setter personalizado. Crea también la propiedad calculada `experienceLevel`: `Junior` para menos de 12 meses, `Intermediate` entre 12 y 60 inclusive, y `Senior` por encima de 60. En `main`, prueba el nivel inicial con 18 meses, cámbialo a 72 y comprueba que asignar -5 lanza una excepción que se captura.

### Clases y métodos introducidos
- Setter personalizado con `set(value)` y `field`.
- Getter calculado con `get()`.
- El setter no se ejecuta al inicializar el campo; valida también el valor inicial en `init`.

> **Términos explicados:** [[Programación Orientada a Objetos 1#6. Getters y setters personalizados|getter, setter y `field`]] · [[Programación Orientada a Objetos 1#7. Propiedades calculadas|propiedad calculada]] · [[Programación Orientada a Objetos 1#2. Constructor primario y bloques de inicialización|`init`]]

#### Ejemplo simple de funcionamiento
```kotlin
var cantidad = 1
    set(value) {
        require(value >= 0)
        field = value
    }
```

### Código fuente (`Ejercicio6.4/src/Main.kt`)

```kotlin
class Employee(initialExperienceMonths: Int) {
    var experienceMonths: Int = initialExperienceMonths
        set(value) {
            require(value >= 0) { "Experience months must be non-negative" }
            field = value
        }

    val experienceLevel: String
        get() = when {
            experienceMonths < 12 -> "Junior"
            experienceMonths <= 60 -> "Intermediate"
            else -> "Senior"
        }

    init {
        require(initialExperienceMonths >= 0) {
            "Experience months must be non-negative"
        }
    }
}

fun main() {
    val dev = Employee(18)
    println(dev.experienceLevel)

    dev.experienceMonths = 72
    println(dev.experienceLevel)

    try {
        dev.experienceMonths = -5
    } catch (e: IllegalArgumentException) {
        println("Error: ${e.message}")
    }
}
```

### Explicación paso a paso
1. La inicialización de `experienceMonths` asigna directamente el valor al campo; no invoca el setter personalizado.
2. `init` valida el argumento inicial para impedir que se construya un empleado inválido.
3. Las asignaciones posteriores pasan por el setter, que valida `value` y solo después actualiza `field`.
4. `experienceLevel` no almacena un valor: calcula el nivel cada vez que se consulta.
5. El nivel cambia de `Intermediate` a `Senior`; el valor negativo genera `IllegalArgumentException`.

## Ejercicio 6.5 · Propiedades calculadas de salud

> [!question] Enunciado
> Define `PlayerStats` con `health` y `maxHealth` mutables en el constructor. Añade `isHurt`, que indique si la salud está por debajo del máximo, y `healthPercentage`, propiedad mutable calculada que convierta entre porcentaje y puntos de salud, limitando el porcentaje al intervalo de 0 a 100. Prueba un jugador con 80 de 100 puntos y asígnale un porcentaje de 50.

> [!warning] Corrección del enunciado
> `field` solo da acceso al campo de respaldo de la propiedad cuyo accesor se está implementando. El setter de `healthPercentage` debe asignar a la propiedad `health`; no puede usar `field` para modificar el campo de respaldo de otra propiedad.

### Clases y métodos introducidos
- Propiedad calculada de solo lectura con un getter.
- Propiedad calculada mutable con getter y setter.
- Las condiciones `if` limitan el porcentaje al intervalo; se usa aritmética básica para convertirlo.

> **Términos explicados:** [[Programación Orientada a Objetos 1#7. Propiedades calculadas|propiedades calculadas y getter/setter]] · [[Programación Orientada a Objetos 1#8. Campo de respaldo|campo de respaldo `field`]] · [[04 - Estructuras básicas#1. La estructura if|condiciones `if`]]

#### Ejemplo simple de funcionamiento
```kotlin
val doble: Int
    get() = base * 2
```

### Código fuente (`Ejercicio6.5/src/Main.kt`)

```kotlin
class PlayerStats(health: Int, maxHealth: Int) {
    var health: Int = health
        set(value) {
            require(value in 0..maxHealth) { "health must be between 0 and maxHealth" }
            field = value
        }

    var maxHealth: Int = maxHealth
        set(value) {
            require(value > 0 && health <= value) {
                "maxHealth must be positive and at least health"
            }
            field = value
        }

    init {
        require(maxHealth > 0) { "maxHealth must be positive" }
        require(health in 0..maxHealth) { "health must be between 0 and maxHealth" }
    }

    val isHurt: Boolean
        get() = health < maxHealth

    var healthPercentage: Double
        get() = health * 100.0 / maxHealth
        set(value) {
            val limitedPercentage = if (value < 0.0) {
                0.0
            } else if (value > 100.0) {
                100.0
            } else {
                value
            }
            health = (limitedPercentage * maxHealth / 100.0).toInt()
        }
}

fun main() {
    val player = PlayerStats(80, 100)
    println("¿Herido?: ${player.isHurt}")
    println("Salud: ${player.healthPercentage}%")

    player.healthPercentage = 50.0
    println("Puntos de salud: ${player.health}")
}
```

### Explicación paso a paso
1. `init` exige un máximo positivo y una salud inicial dentro del intervalo válido; así se evita división por cero.
2. `isHurt` compara el valor actual de `health` con `maxHealth` cada vez que se consulta.
3. El getter calcula el porcentaje y el setter convierte el porcentaje a puntos de salud.
4. Las condiciones `if` limitan el porcentaje a 0–100; `toInt()` trunca la parte decimal del resultado.
5. Con 80/100, el porcentaje inicial es 80.0; al asignar 50.0, `health` pasa a 50.

## Ejercicio 6.6 · Setter y temperatura calculada

> [!question] Enunciado
> Define `TemperatureSensor` con una temperatura Celsius inicial, un setter que rechace temperaturas inferiores al cero absoluto y una propiedad calculada Fahrenheit con la fórmula `F = C * 1.8 + 32`. Prueba 20 °C, cambia a 30 °C y captura el error al intentar asignar -300 °C.

> [!warning] Corrección del enunciado
> El cero absoluto es **-273,15 °C**, no +273,15 °C. Se usa el umbral correcto en la validación.

### Clases y métodos introducidos
- Setter personalizado para validar asignaciones posteriores.
- Validación de argumento inicial en `init`.
- Propiedad calculada para conversión de unidades.

> **Términos explicados:** [[Programación Orientada a Objetos 1#6. Getters y setters personalizados|setter personalizado y validación inicial]] · [[Programación Orientada a Objetos 1#7. Propiedades calculadas|propiedad calculada]] · [[04 - Estructuras básicas#8. Excepciones|`require` y captura con `try-catch`]]

#### Ejemplo simple de funcionamiento
```kotlin
val fahrenheit: Double
    get() = celsius * 1.8 + 32
```

### Código fuente (`Ejercicio6.6/src/Main.kt`)

```kotlin
class TemperatureSensor(initialTemperatureCelsius: Double) {
    var temperatureCelsius: Double = initialTemperatureCelsius
        set(value) {
            require(value >= -273.15) {
                "Temperature cannot be below absolute zero"
            }
            field = value
        }

    val temperatureFahrenheit: Double
        get() = temperatureCelsius * 1.8 + 32.0

    init {
        require(initialTemperatureCelsius >= -273.15) {
            "Temperature cannot be below absolute zero"
        }
    }
}

fun main() {
    val sensor = TemperatureSensor(20.0)
    println("${sensor.temperatureFahrenheit} °F")

    sensor.temperatureCelsius = 30.0
    println("${sensor.temperatureFahrenheit} °F")

    try {
        sensor.temperatureCelsius = -300.0
    } catch (e: IllegalArgumentException) {
        println("Error: ${e.message}")
    }
}
```

### Explicación paso a paso
1. La propiedad se inicializa directamente desde el parámetro; por eso `init` también valida el valor inicial.
2. Las modificaciones posteriores ejecutan el setter, que rechaza temperaturas inferiores a -273,15 °C.
3. `temperatureFahrenheit` calcula la conversión al consultarse; no guarda un valor redundante.
4. La asignación de -300.0 lanza `IllegalArgumentException` y el `catch` muestra su mensaje.

## Ejercicio 6.7 · Cuenta bancaria y propiedad de respaldo

> [!question] Enunciado
> Implementa `BankAccount` con titular, saldo no negativo e historial de transacciones. El saldo debe validarse al construir la cuenta y al reasignarse. Expón el historial como texto de solo lectura y permite que solo la clase lo modifique. Añade `deposit` y `withdraw`: ambos deben rechazar cantidades no positivas y la retirada debe comprobar que existe saldo suficiente.

### Clases y métodos introducidos
- Propiedad de respaldo: propiedad privada mutable más una propiedad pública de lectura.
- Setter personalizado y validación tanto inicial como posterior.
- El historial se expone como `String` de solo lectura para evitar introducir colecciones mutables aún no explicadas en los temas anteriores.

> **Términos explicados:** [[Programación Orientada a Objetos 1#10. Propiedades de respaldo|propiedad de respaldo]] · [[Programación Orientada a Objetos 1#6. Getters y setters personalizados|setter personalizado y `field`]] · [[Programación Orientada a Objetos 1#5. Propiedades|propiedades mutables y de solo lectura]] · [[04 - Estructuras básicas#8. Excepciones|validación con `require`]]

#### Ejemplo simple de funcionamiento
```kotlin
private var elementosInternos = ""
val elementos: String
    get() = elementosInternos
```

### Código fuente (`Ejercicio6.7/src/Main.kt`)

```kotlin
class BankAccount(
    val accountHolder: String,
    initialBalance: Double = 0.0,
) {
    var balance: Double = initialBalance
        set(value) {
            require(value >= 0.0) {
                "Balance must be non-negative"
            }
            field = value
        }

    private var historyText: String = ""
    val transactionHistory: String
        get() = historyText

    init {
        require(accountHolder != "") { "Account holder cannot be blank" }
        require(initialBalance >= 0.0) {
            "Balance must be non-negative"
        }
    }

    fun deposit(amount: Double) {
        require(amount > 0.0) {
            "Deposit amount must be positive"
        }
        balance += amount
        historyText += "Deposit: +$amount\n"
    }

    fun withdraw(amount: Double) {
        require(amount > 0.0) {
            "Withdrawal amount must be positive"
        }
        require(amount <= balance) { "Insufficient funds" }
        balance -= amount
        historyText += "Withdrawal: -$amount\n"
    }
}

fun main() {
    val account = BankAccount("Ada Lovelace", 100.0)
    account.deposit(50.0)
    account.withdraw(30.0)

    println("Saldo: ${account.balance}")
    println("Movimientos: ${account.transactionHistory}")
}
```

### Explicación paso a paso
1. `historyText` es privada y mutable; `transactionHistory` permite consultarla sin exponer su setter.
2. El setter de `balance` protege las asignaciones posteriores. `init` repite la validación porque la inicialización directa no invoca el setter.
3. `deposit` valida la cantidad, actualiza el saldo y añade una línea al historial.
4. `withdraw` valida cantidad y fondos antes de modificar saldo o historial.
5. El saldo final es 120.0. El historial público no permite reasignar el texto.

## Ejercicio 6.8 · Herencia básica

> [!question] Enunciado
> Define `Person` con una propiedad `name` y un método `introduce()` que imprima `Hello, my name is [name]`. Define `Employee` como subclase, con parámetros `employeeName` y `employeeID`, y pasa el nombre al constructor de `Person`. Crea `Employee("Alex", 101)` y llama a `introduce()`.

### Clases y métodos introducidos
- `open class`: clase que permite herencia.
- `: Person(employeeName)`: invoca el constructor de la superclase.
- Una clase es final por defecto; para heredar de ella hay que marcarla `open` o declararla `abstract`.

> **Términos explicados:** [[Programación Orientada a Objetos 1#11. Herencia|herencia y `open`]] · [[Programación Orientada a Objetos 1#2. Constructor primario y bloques de inicialización|constructores primarios]]

#### Ejemplo simple de funcionamiento
```kotlin
open class Animal(val nombre: String)
class Perro(nombre: String) : Animal(nombre)
```

### Código fuente (`Ejercicio6.8/src/Main.kt`)

```kotlin
open class Person(val name: String) {
    fun introduce() {
        println("Hello, my name is $name")
    }
}

class Employee(
    employeeName: String,
    val employeeID: Int,
) : Person(employeeName)

fun main() {
    val dev = Employee("Alex", 101)
    dev.introduce()
    println("ID: ${dev.employeeID}")
}
```

### Explicación paso a paso
1. `Person` es `open`, así que otras clases pueden heredar de ella.
2. `Employee` pasa `employeeName` al constructor de `Person` al declarar la superclase.
3. `employeeID` se declara como propiedad de `Employee` con `val`.
4. `dev` hereda `introduce()` y lo ejecuta con el nombre almacenado por `Person`.

## Ejercicio 6.9 · Jerarquía y sobrescritura

> [!question] Enunciado
> Diseña una jerarquía para empleados con un método `getDetails()`. Debe incluir `Employee`, `Manager` con departamento y `Developer` con una cantidad variable de lenguajes de programación. Sobrescribe `getDetails()` para incorporar los datos de cada subtipo. El enunciado pide al menos tres niveles, aunque solo detalla dos; la solución añade `Person` como superclase de `Employee` para cumplir ese requisito.

### Clases y métodos introducidos
- `open` permite heredar de una clase o sobrescribir un miembro.
- `override` sobrescribe un método abierto y es obligatorio en Kotlin.
- `vararg` recibe una cantidad variable de argumentos.

> **Términos explicados:** [[Programación Orientada a Objetos 1#11. Herencia|herencia]] · [[Programación Orientada a Objetos 1#12. Sobrescribir métodos y propiedades|`override`, `super` y despacho dinámico]] · [[03 - Funciones#9. varargs|`vararg`]] · [[04 - Estructuras básicas#6. Bucles for y repeat|bucles y recorrido]]

#### Ejemplo simple de funcionamiento
```kotlin
open class Base {
    open fun descripcion() = "Base"
}
class Derivada : Base() {
    override fun descripcion() = "Derivada"
}
```

### Código fuente (`Ejercicio6.9/src/Main.kt`)

```kotlin
open class Person(val name: String)

open class Employee(name: String, val id: Int) : Person(name) {
    open fun getDetails(): String = "Empleado: $name (ID: $id)"
}

class Manager(
    name: String,
    id: Int,
    val department: String,
) : Employee(name, id) {
    override fun getDetails(): String =
        "${super.getDetails()}, departamento: $department"
}

class Developer(
    name: String,
    id: Int,
    vararg programmingLanguages: String,
) : Employee(name, id) {
    private var languageText = ""

    init {
        for (language in programmingLanguages) {
            if (languageText != "") {
                languageText += ", "
            }
            languageText += language
        }
    }

    override fun getDetails(): String =
        "${super.getDetails()}, lenguajes: $languageText"
}

fun main() {
    val employees: List<Employee> = listOf(
        Manager("Ada", 1, "Investigación"),
        Developer("Grace", 2, "Kotlin", "Java"),
    )

    employees.forEach { println(it.getDetails()) }
}
```

### Explicación paso a paso
1. La cadena de herencia tiene tres niveles: `Person` → `Employee` → `Manager` o `Developer`.
2. `Employee` es `open`, y `getDetails()` también; ambas condiciones permiten crear subclases y sobrescribir el método.
3. Cada subtipo añade su dato específico y combina su resultado con `super.getDetails()`.
4. `vararg` permite llamar a `Developer` con cero o más lenguajes; el bucle `for` construye el texto sin usar operaciones de colecciones aún no estudiadas.
5. El tipo estático de la lista es `Employee`, pero se ejecuta la sobrescritura del tipo concreto de cada objeto (despacho dinámico).

## Ejercicio 6.10 · Clase anidada sin instancia externa

> [!question] Enunciado
> Define `SystemConfig` con `versionNumber` y `getConfigDetails()`. Dentro, declara la clase anidada `Setting` (sin `inner`) con `keyName` y `printKey()`. En `main`, crea una instancia de cada clase. Explica en un comentario por qué `Setting` no puede acceder a `versionNumber` sin una instancia de `SystemConfig`.

### Clases y métodos introducidos
- Una clase anidada en Kotlin no está asociada a una instancia de la clase externa por defecto; no se declara con la palabra clave `static`.
- Se instancia como `SystemConfig.Setting(...)`.

> **Términos explicados:** [[Programación Orientada a Objetos 1#13. Clases anidadas|clases anidadas]] · [[Programación Orientada a Objetos 1#2. Constructor primario y bloques de inicialización|clases y propiedades]]

#### Ejemplo simple de funcionamiento
```kotlin
class Exterior {
    class Anidada(val dato: String)
}
val objeto = Exterior.Anidada("Kotlin")
```

### Código fuente (`Ejercicio6.10/src/Main.kt`)

```kotlin
class SystemConfig(val versionNumber: String) {
    fun getConfigDetails() {
        println("Versión: $versionNumber")
    }

    class Setting(val keyName: String) {
        fun printKey() {
            println(keyName)
        }
    }
}

fun main() {
    val mainConfig = SystemConfig("1.0.0")
    mainConfig.getConfigDetails()

    val logSetting = SystemConfig.Setting("LogLevel")
    logSetting.printKey()

    // Setting no tiene referencia a una instancia de SystemConfig.
}
```

### Explicación paso a paso
1. `Setting` está anidada, pero no lleva `inner`; por eso no guarda una referencia a `SystemConfig`.
2. Se puede construir directamente con `SystemConfig.Setting(...)`, sin usar `mainConfig`.
3. `versionNumber` pertenece a cada objeto `SystemConfig`, y `Setting` no tiene una instancia concreta desde la que leerla.

## Ejercicio 6.11 · Clases anidadas e internas

> [!question] Enunciado
> Crea `Hotel` con nombre, número de habitaciones e información del hotel. Añade la clase anidada `Reservation` con datos y detalles de reserva, y la clase `Employee` marcada como `inner`, con datos del empleado y un método que obtenga el total de habitaciones del hotel asociado. Prueba los métodos desde `main`.

### Clases y métodos introducidos
- Clase anidada normal: no conserva una instancia externa.
- `inner class`: conserva la instancia externa y accede a ella mediante `this@Hotel`.

> **Términos explicados:** [[Programación Orientada a Objetos 1#13. Clases anidadas|clase anidada]] · [[Programación Orientada a Objetos 1#14. Clases internas|clase `inner` y `this@Hotel`]]
- Una reserva estática no necesita un hotel concreto; un empleado interno sí.

#### Ejemplo simple de funcionamiento
```kotlin
class Exterior(val valor: Int) {
    inner class Interior {
        fun leerValor() = this@Exterior.valor
    }
}
```

### Código fuente (`Ejercicio6.11/src/Main.kt`)

```kotlin
class Hotel(val name: String, val roomCount: Int) {
    init {
        require(roomCount >= 0) { "roomCount cannot be negative" }
    }

    fun getHotelInfo(): String = "$name: $roomCount habitaciones"

    class Reservation(val guestName: String, val roomNumber: Int) {
        fun getReservationDetails(): String =
            "Reserva de $guestName, habitación $roomNumber"
    }

    inner class Employee(val employeeName: String, val position: String) {
        fun getEmployeeDetails(): String = "$employeeName: $position"
        fun getEmployeeTotalRooms(): Int = this@Hotel.roomCount
    }
}

fun main() {
    val hotel = Hotel("Costa Azul", 80)
    val reservation = Hotel.Reservation("Ada", 12)
    val employee = hotel.Employee("Grace", "Recepcionista")

    println(hotel.getHotelInfo())
    println(reservation.getReservationDetails())
    println(employee.getEmployeeDetails())
    println("Habitaciones del hotel del empleado: ${employee.getEmployeeTotalRooms()}")
}
```

### Explicación paso a paso
1. `Hotel.Reservation(...)` se construye desde el nombre de la clase externa porque no requiere una instancia de hotel.
2. `Employee` lleva `inner`; por eso se construye mediante `hotel.Employee(...)` y conserva esa instancia.
3. `this@Hotel.roomCount` desambigua y accede a la propiedad de la instancia externa.
4. `getEmployeeTotalRooms()` devuelve `80`, correspondiente al hotel usado para crear el empleado.

## Ejercicio 6.12 · Modificadores de visibilidad

> [!question] Enunciado
> Define `BaseComponent` como `open`, con una propiedad pública `id`, otra protegida `settings` y un método `internal logAccess()`. Crea `DerivedComponent` para acceder a `settings`, y `ExternalApp.interact()` para mostrar `id`. Explica cuál de las propiedades no puede leer `ExternalApp`.

### Clases y métodos introducidos
- `public`: acceso desde cualquier código que pueda ver el tipo.
- `protected`: acceso desde la clase que declara el miembro y sus subclases.
- `internal`: acceso dentro del mismo módulo de compilación.
- `private`: acceso restringido al ámbito de declaración correspondiente.

> **Términos explicados:** [[Programación Orientada a Objetos 1#15. Modificadores de visibilidad|`public`, `private`, `protected` e `internal`]]

#### Ejemplo simple de funcionamiento
```kotlin
open class Base {
    protected val dato = "solo la clase y sus subclases"
}
class Derivada : Base() {
    fun mostrar() = println(dato)
}
```

### Código fuente (`Ejercicio6.12/src/Main.kt`)

```kotlin
open class BaseComponent(
    val id: String,
    protected val settings: String,
) {
    internal fun logAccess() {
        println("Access logged by internal function")
    }
}

class DerivedComponent(id: String, settings: String) : BaseComponent(id, settings) {
    fun displaySettings() {
        println(settings)
    }
}

class ExternalApp {
    fun interact(component: DerivedComponent) {
        println(component.id)
        // println(component.settings) // Error: settings es protected.
    }
}

fun main() {
    val component = DerivedComponent("main", "dark-mode")
    component.logAccess() // Válido: main está en el mismo módulo.
    component.displaySettings()
    ExternalApp().interact(component)
}
```

### Explicación paso a paso
1. `DerivedComponent` hereda de `BaseComponent`; por eso puede leer la propiedad protegida `settings`.
2. `ExternalApp` no es una subclase, así que no puede acceder a `settings`, aunque esté en el mismo paquete.
3. `id` es pública y se puede leer desde `ExternalApp`.
4. `logAccess()` es `internal`: `main` puede llamarla porque se compila en el mismo módulo. `internal` no significa “mismo paquete”.

## Ejercicio 6.13 · Singleton con `object`

> [!question] Enunciado
> Implementa `ConfigurationManager` como singleton. Debe usar un mapa privado `MutableMap<String, String>` y permitir almacenar un par clave-valor, obtener un valor por clave y representar todas las configuraciones mediante una cadena.

### Clases y métodos introducidos
- `object`: declaración de un singleton, con una única instancia.
- `mutableMapOf<K, V>()`: crea un mapa mutable.
- La propiedad de mapa se consulta directamente para obtener su representación en texto.

> **Términos explicados:** [[Programación Orientada a Objetos 1#16. Declaraciones de objetos|declaración `object` y singleton]] · [[05.1 - Ejercicios 5 Operaciones con tipos nullables#Ejercicio 5.3 · Acceso seguro a un mapa|mapas y acceso por clave]] · [[Programación Orientada a Objetos 1#15. Modificadores de visibilidad|propiedad `private`]]

#### Ejemplo simple de funcionamiento
```kotlin
object Contador {
    var valor = 0
}
Contador.valor++
```

### Código fuente (`Ejercicio6.13/src/Main.kt`)

```kotlin
object ConfigurationManager {
    private val settings = mutableMapOf<String, String>()

    fun set(key: String, value: String) {
        settings[key] = value
    }

    fun get(key: String): String? = settings[key]

    fun describe(): String = settings.toString()
}

fun main() {
    ConfigurationManager.set("theme", "dark")
    ConfigurationManager.set("language", "es")

    println(ConfigurationManager.get("theme"))
    println(ConfigurationManager.describe())
}
```

### Explicación paso a paso
1. `object` crea y expone una única instancia; no se instancia con paréntesis.
2. `settings` es privado: solo las operaciones de `ConfigurationManager` pueden modificar el mapa.
3. `set` inserta o reemplaza el valor asociado a la clave.
4. `get` devuelve `null` si la clave no existe.
5. `describe` devuelve la representación en texto del mapa mediante `toString()`.

## Ejercicio 6.14 · Identificadores con `companion object`

> [!question] Enunciado
> Define `User` de forma que la primera instancia reciba `id = 1`, la segunda `id = 2`, y así sucesivamente, sin que el código que crea usuarios calcule el identificador.

### Clases y métodos introducidos
- `companion object`: contiene miembros asociados a la clase, no a una instancia concreta.
- Una propiedad del `companion object` conserva el siguiente identificador entre instancias.

> **Términos explicados:** [[Programación Orientada a Objetos 1#17. Objetos compañeros|`companion object`]] · [[Programación Orientada a Objetos 1#5. Propiedades|propiedades de instancia]]

#### Ejemplo simple de funcionamiento
```kotlin
class Ejemplo {
    companion object {
        var contador = 0
    }
}
```

### Código fuente (`Ejercicio6.14/src/Main.kt`)

```kotlin
class User {
    val id: Int = nextId()

    companion object {
        private var nextIdValue = 1

        private fun nextId(): Int = nextIdValue++
    }
}

fun main() {
    val first = User()
    val second = User()
    val third = User()

    println(first.id)  // 1
    println(second.id) // 2
    println(third.id)  // 3
}
```

### Explicación paso a paso
1. Cada nueva instancia inicializa `id` llamando a `nextId()`.
2. `nextIdValue` pertenece al `companion object`, por lo que su valor se comparte entre todas las instancias.
3. La función devuelve el identificador actual e incrementa el contador para el siguiente objeto.
4. El contador simple sirve para este ejemplo secuencial; una aplicación multihilo necesitaría sincronización o un contador atómico.
