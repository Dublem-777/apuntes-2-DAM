## Ejercicio 10.1 · Función de orden superior testBoth con lambdas

> [!question] Enunciado
> Define una función de orden superior llamada `testBoth`, que reciba dos enteros y una función de condición como parámetros. La función `testBoth` debe retornar un valor booleano que indique si ambos números cumplen con la condición especificada.
>
> Prueba la función llamándola dos veces desde el `main` con dos condiciones distintas pasadas como lambdas.

### Clases y métodos introducidos
- **Función de orden superior**: función que recibe otra función como parámetro (o la devuelve).
- `(Int) -> Boolean`: tipo función que recibe un `Int` y devuelve un `Boolean` (un "predicado").
- `condition(first)`: se invoca el parámetro de tipo función igual que una función normal (equivale a `condition.invoke(first)`).

> **Términos explicados:** [[10 - Programación funcional#1. Tipos función|1. Tipos función]]

### Código fuente (`Ejercicio10.1/src/Main.kt`)

```kotlin
// Función de orden superior: recibe una función (Int) -> Boolean como parámetro
fun testBoth(first: Int, second: Int, condition: (Int) -> Boolean): Boolean =
    condition(first) && condition(second)

fun main() {
    // Condición 1: ¿son pares? (lambda con it y trailing lambda)
    val bothEven = testBoth(4, 10) { it % 2 == 0 }
    println("¿4 y 10 son pares? $bothEven")

    // Condición 2: ¿son positivos? (lambda con nombre de parámetro)
    val bothPositive = testBoth(3, -5) { number -> number > 0 }
    println("¿3 y -5 son positivos? $bothPositive")
}
```

> [!tip] Salida por consola
> ```text
> ¿4 y 10 son pares? true
> ¿3 y -5 son positivos? false
> ```

### Explicación paso a paso
1. `testBoth` declara su tercer parámetro como `(Int) -> Boolean`: cualquier función que reciba un entero y devuelva un booleano vale.
2. El cuerpo aplica la condición a los dos números y los une con `&&`.
3. Como el parámetro de tipo función es el **último**, la lambda se escribe fuera de los paréntesis (_trailing lambda_).
4. En la primera llamada se usa `it` porque la lambda tiene un único parámetro; en la segunda se le da nombre (`number ->`) para que se lea mejor.
5. `-5` no es positivo, así que la segunda llamada devuelve `false`.

## Ejercicio 10.2 · Varianza en tipos función con Message, Email y SMS

> [!question] Enunciado
> Define una jerarquía de clases simple:
>
> - Clase `Message` (base).
> - Clase `Email` que hereda de `Message`.
> - Clase `SMS` que hereda de `Message`.
>
> Define una función _top-level_ llamada `sendNotification(process: (Email) -> Message)` que acepte una función con la siguiente firma estricta: recibe un `Email` y devuelve un `Message`. Dentro, llama a `process(Email("Test"))` y devuelve el resultado.
>
> Crea tres funciones independientes que intenten cumplir el contrato, aprovechando la varianza:
>
> - `logEmail(e: Message): Message`: **Contravarianza en el Parámetro**. Debe recibir el supertipo (`Message`) y devolver el tipo esperado (`Message`). Simplemente imprime el contenido y devuelve el mismo objeto.
> - `createReply(e: Email): SMS`: **Covarianza en el Retorno**. Debe recibir el tipo esperado (`Email`) y devolver un subtipo de `Message` (`SMS`). Simplemente crea y devuelve un `SMS`.
> - `handleAll(m: Message): SMS`: **Ambas Varianzas**. Recibe el supertipo (`Message`) y devuelve el subtipo (`SMS`).
>
> En la función `main`, llama a `sendNotification` pasando las funciones `logEmail`, `createReply`, y `handleAll` como argumentos. Imprime el tipo de objeto devuelto por `sendNotification` en cada caso para confirmar que el compilador aceptó las conversiones.

### Clases y métodos introducidos
- En un tipo función `(Email) -> Message`, el parámetro es **contravariante** (`in`) y el retorno **covariante** (`out`).
- `::logEmail`: referencia a una función _top-level_ para pasarla como argumento (se ve en [[10 - Programación funcional#10. Referencias a función|Referencias a función]]).
- `objeto::class.simpleName`: nombre de la clase real del objeto en tiempo de ejecución.

> **Términos explicados:** [[10 - Programación funcional#2. Varianza en los tipos función|2. Varianza en los tipos función]]

### Código fuente (`Ejercicio10.2/src/Main.kt`)

```kotlin
open class Message(val content: String)
class Email(content: String) : Message(content)
class SMS(content: String) : Message(content)

// Contrato estricto: recibe un Email y devuelve un Message
fun sendNotification(process: (Email) -> Message): Message = process(Email("Test"))

// Contravarianza en el parámetro: acepta un supertipo (Message) de lo que se le pasará (Email)
fun logEmail(e: Message): Message {
    println("Log: ${e.content}")
    return e
}

// Covarianza en el retorno: devuelve un subtipo (SMS) de lo esperado (Message)
fun createReply(e: Email): SMS = SMS("Re: ${e.content}")

// Ambas: parámetro más general y retorno más concreto
fun handleAll(m: Message): SMS = SMS("Handled: ${m.content}")

fun main() {
    val result1 = sendNotification(::logEmail)
    println("logEmail    -> ${result1::class.simpleName}")

    val result2 = sendNotification(::createReply)
    println("createReply -> ${result2::class.simpleName}")

    val result3 = sendNotification(::handleAll)
    println("handleAll   -> ${result3::class.simpleName}")
}
```

> [!tip] Salida por consola
> ```text
> Log: Test
> logEmail    -> Email
> createReply -> SMS
> handleAll   -> SMS
> ```

### Explicación paso a paso
1. `sendNotification` solo exige "algo que acepte un `Email` y devuelva un `Message`".
2. `logEmail` acepta cualquier `Message`. Si sabe tratar cualquier mensaje, también sabe tratar un `Email`: el parámetro puede ser **más general** (contravarianza).
3. `createReply` devuelve un `SMS`, que **es** un `Message`: el retorno puede ser **más concreto** (covarianza).
4. `handleAll` combina las dos cosas y el compilador también la acepta.
5. La salida muestra el tipo real devuelto: `logEmail` devuelve el mismo `Email` que recibió, y las otras dos devuelven `SMS`.

## Ejercicio 10.3 · typealias MathOperation y función que devuelve función

> [!question] Enunciado
> Define un alias de tipo _top-level_ llamado `MathOperation` para el tipo de función que recibe dos `Double` y devuelve un `Double`.
>
> Define una función _top-level_ llamada `applyCalculation(a: Double, b: Double, op: MathOperation): Double` que simplemente llama a `op(a, b)` y devuelve el resultado.
>
> Define una función _top-level_ llamada `createFormatter(prefix: String, suffix: String): (Double) -> String` que devuelve una función.
>
> La función devuelta debe recibir un `Double` (el resultado del cálculo) y devolver una `String` que contenga el `prefix`, el número redondeado a dos decimales y el `suffix`.
>
> En la función `main`:
>
> - Define una variable de tipo función (usando el alias `MathOperation`) llamada `powerFunction` que tome dos números y devuelva el primer número elevado a la potencia del segundo (usa `Math.pow`).
> - Llama a `applyCalculation` usando `powerFunction` con los valores `2.0` y `10.0`. Guarda el resultado en `result`.
> - Llama a `createFormatter` con `prefix` como `"FINAL -> "` y `suffix` como `" €"` para obtener la función de formato. Almacénala en una variable `formatter`.
> - Aplica `formatter` al `result` y muestra la cadena final.

### Clases y métodos introducidos
- `typealias MathOperation = (Double, Double) -> Double`: otro nombre para el mismo tipo; no crea un tipo nuevo.
- Función que **devuelve** una función: su tipo de retorno es un tipo función, `(Double) -> String`.
- `"%.2f".format(value)`: formatea un `Double` con dos decimales (usa el separador decimal del sistema, en español la coma).

> **Términos explicados:** [[10 - Programación funcional#3. typealias|3. typealias]]

### Código fuente (`Ejercicio10.3/src/Main.kt`)

```kotlin
// Nombre alternativo para el tipo función (Double, Double) -> Double
typealias MathOperation = (Double, Double) -> Double

fun applyCalculation(a: Double, b: Double, op: MathOperation): Double = op(a, b)

// Devuelve una función (Double) -> String que "recuerda" prefix y suffix
fun createFormatter(prefix: String, suffix: String): (Double) -> String =
    { value -> prefix + "%.2f".format(value) + suffix }

fun main() {
    val powerFunction: MathOperation = { base, exponent -> Math.pow(base, exponent) }

    val result = applyCalculation(2.0, 10.0, powerFunction)

    val formatter = createFormatter("FINAL -> ", " €")
    println(formatter(result))
}
```

> [!tip] Salida por consola
> ```text
> FINAL -> 1024,00 €
> ```

### Explicación paso a paso
1. `MathOperation` hace más legible la firma de `applyCalculation`; para el compilador es exactamente `(Double, Double) -> Double`.
2. `createFormatter` devuelve una lambda que usa `prefix` y `suffix` aunque `createFormatter` ya haya terminado (es un _closure_).
3. `powerFunction` se declara con el alias, así el compilador sabe que `base` y `exponent` son `Double` sin indicarlo.
4. `2^10 = 1024.0`; el `formatter` lo convierte en `FINAL -> 1024,00 €` (coma decimal por el idioma del sistema).

## Ejercicio 10.4 · Lambdas con it, trailing lambda y desestructuración

> [!question] Enunciado
> Define una `data class` llamada `OrderLine` con dos propiedades inmutables: `productName` (`String`) y `price` (`Double`).
>
> Define una lista inmutable de `OrderLine` llamada `shoppingCart` con al menos tres elementos.
>
> En la función `main`, utiliza la lista `shoppingCart` y las funciones de colección de Kotlin (`forEach`, `filter`, `map`) para realizar las siguientes tareas, aplicando la sintaxis más concisa posible:
>
> - **Impresión Simple (`forEach`)**:
>     - Usa `forEach` para imprimir el `productName` de cada artículo.
>     - **Debe usar `it`** y la sintaxis de _trailing lambda_.
> - **Filtrado y Mapeo (Desestructuración)**:
>     - Usa la función `filter` para quedarte solo con los artículos cuyo precio sea mayor o igual a `50.0`.
>     - Usa el resultado anterior para aplicar la función `map` para crear una lista de `String` que contenga solo el `productName`.
>     - **La lambda de `filter` debe usar la desestructuración** del parámetro para acceder al precio directamente (e ignorar el nombre).
>     - **La lambda de `map` debe usar `it`**.
> - **Cálculo (Uso de `it` y _trailing lambda_)**:
>     - Usa la función `sumOf` para calcular la suma total de todos los precios en el `shoppingCart`.
>     - **Debe usar `it`** y la sintaxis de _trailing lambda_.
>
> Finalmente, imprime los resultados del punto 2 y 3 con mensajes claros.

### Clases y métodos introducidos
- `forEach { … }`: ejecuta la lambda con cada elemento.
- `filter { … }`: devuelve una lista nueva con los elementos para los que la lambda devuelve `true`.
- `map { … }`: devuelve una lista nueva con el resultado de aplicar la lambda a cada elemento.
- `sumOf { … }`: suma los valores que devuelve la lambda para cada elemento.
- `{ (_, price) -> … }`: desestructuración del parámetro (`component1()`/`component2()` de la _data class_), ignorando el primero con `_`.

> **Términos explicados:** [[10 - Programación funcional#5. Expresiones lambda|5. Expresiones lambda]]

### Código fuente (`Ejercicio10.4/src/Main.kt`)

```kotlin
data class OrderLine(val productName: String, val price: Double)

val shoppingCart = listOf(
    OrderLine("Teclado", 45.99),
    OrderLine("Monitor", 189.90),
    OrderLine("Ratón", 19.95),
    OrderLine("Auriculares", 59.00),
)

fun main() {
    // 1. forEach con it y trailing lambda
    println("Productos del carrito:")
    shoppingCart.forEach { println("- ${it.productName}") }

    // 2. filter con desestructuración (ignorando el nombre) y map con it
    val expensiveProducts = shoppingCart
        .filter { (_, price) -> price >= 50.0 }
        .map { it.productName }

    // 3. sumOf con it y trailing lambda
    val total = shoppingCart.sumOf { it.price }

    println("Productos de 50 € o más: $expensiveProducts")
    println("Total del carrito: ${"%.2f".format(total)} €")
}
```

> [!tip] Salida por consola
> ```text
> Productos del carrito:
> - Teclado
> - Monitor
> - Ratón
> - Auriculares
> Productos de 50 € o más: [Monitor, Auriculares]
> Total del carrito: 314,84 €
> ```

### Explicación paso a paso
1. Todas las llamadas usan _trailing lambda_ y, como la lambda es el único argumento, sin paréntesis.
2. En `filter`, `(_, price)` desestructura cada `OrderLine`: `_` descarta el nombre y `price` recibe el precio.
3. `filter` y `map` se encadenan: primero se quedan los productos de 50 € o más, y luego se transforman en sus nombres.
4. `sumOf { it.price }` suma los precios. El total se formatea con dos decimales, porque al sumar `Double` pueden salir decimales "raros" (como `314.84000000000003`).

## Ejercicio 10.5 · Conversión SAM con fun interface DelayedTask

> [!question] Enunciado
> Define una **`fun interface`** llamada `DelayedTask` con un único método abstracto: `execute(delayMs: Long): Unit`.
>
> Define una clase llamada `TaskScheduler` con una función _top-level_ llamada `schedule(task: DelayedTask)` que:
>
> - Imprima el mensaje: "Scheduling task..."
> - Llama a `task.execute(1000L)` (simulando una ejecución con 1000 ms de retraso).
>
> En la función `main`, haz lo siguiente:
>
> - Crea una instancia inmutable de `TaskScheduler` llamada `scheduler`.
> - Llama a `scheduler.schedule` y, como argumento, pasa una **expresión lambda** compatible que reciba el parámetro `delayMs` y simplemente imprima: "Executing task after $delayMs ms."
> - En un comentario, explica qué cambio sintáctico (si lo hubiera) se necesitaría en la `DelayedTask` si se quisiera usar esta sintaxis lambda en Java.

### Clases y métodos introducidos
- **SAM** (_Single Abstract Method_): interfaz con un único método abstracto.
- **Conversión SAM**: el compilador convierte una lambda en un objeto que implementa la interfaz.
- `fun interface`: hace falta para que Kotlin aplique la conversión SAM a una interfaz escrita en Kotlin.

> **Términos explicados:** [[10 - Programación funcional#6. Conversión SAM|6. Conversión SAM]]

### Código fuente (`Ejercicio10.5/src/Main.kt`)

```kotlin
// fun interface: permite pasar una lambda donde se espera un DelayedTask (conversión SAM)
fun interface DelayedTask {
    fun execute(delayMs: Long)
}

class TaskScheduler {
    fun schedule(task: DelayedTask) {
        println("Scheduling task...")
        task.execute(1000L)
    }
}

fun main() {
    val scheduler = TaskScheduler()

    // La lambda se convierte automáticamente en un DelayedTask
    scheduler.schedule { delayMs ->
        println("Executing task after $delayMs ms.")
    }

    // ¿Qué cambiaría para usar esta sintaxis lambda desde Java?
    // Nada: Java considera funcional a CUALQUIER interfaz con un único método abstracto,
    // así que desde Java se podría escribir scheduler.schedule(delayMs -> ...) igualmente.
    // La palabra "fun" solo hace falta para que KOTLIN aplique la conversión SAM;
    // sin ella, desde Kotlin habría que usar object : DelayedTask { ... }.
}
```

> [!tip] Salida por consola
> ```text
> Scheduling task...
> Executing task after 1000 ms.
> ```

### Explicación paso a paso
1. El enunciado habla de una "función _top-level_" dentro de una clase, lo que es contradictorio: si está dentro de `TaskScheduler` es un **método**. Se define como método, porque luego se llama con `scheduler.schedule`.
2. Gracias a `fun interface`, la lambda `{ delayMs -> … }` se convierte en un `DelayedTask`; el compilador deduce que `delayMs` es `Long`.
3. Si se quita `fun`, `kotlinc` da error (`actual type is '(???) -> ???', but 'DelayedTask' was expected`), y habría que escribir `object : DelayedTask { override fun execute(delayMs: Long) { … } }`.
4. **Respuesta a la pregunta del comentario:** desde Java no habría que cambiar nada. Java trata como funcional cualquier interfaz con un único método abstracto, lleve o no `fun`.

## Ejercicio 10.6 · fun interface DataValidator

> [!question] Enunciado
> Define una **`fun interface`** llamada `DataValidator`. El método abstracto de `DataValidator` debe llamarse `isValid(input: String): Boolean`.
>
> Define una clase llamada `ValidationService` con una función llamada `check(value: String, validator: DataValidator): Boolean` que:
>
> - Imprima el mensaje: "Checking value: '$value'"
> - Llama a `validator.isValid(value)` y devuelve el resultado.
>
> En la función `main`, haz lo siguiente:
>
> - Crea una instancia inmutable de `ValidationService` llamada `service`.
> - Llama a `service.check` para verificar si la cadena `"kotlin"` **es más larga que 5 caracteres**. Pasa la expresión lambda necesaria para la validación (recibe un `String` y devuelve `Boolean`).
> - Llama a `service.check` para verificar si la cadena `"java"` **contiene la letra 'a'**. Pasa la segunda expresión lambda para esta validación.
>
> Finalmente, imprime los resultados de las dos llamadas.

### Clases y métodos introducidos
- `fun interface DataValidator`: interfaz funcional con nombre propio, que además se puede usar desde Java.
- `'a' in it`: el operador `in` sobre un `String` se traduce a `it.contains('a')`.

> **Términos explicados:** [[10 - Programación funcional#7. Interfaz fun interface|7. Interfaz fun interface]]

### Código fuente (`Ejercicio10.6/src/Main.kt`)

```kotlin
fun interface DataValidator {
    fun isValid(input: String): Boolean
}

class ValidationService {
    fun check(value: String, validator: DataValidator): Boolean {
        println("Checking value: '$value'")
        return validator.isValid(value)
    }
}

fun main() {
    val service = ValidationService()

    // Cada lambda (String) -> Boolean se convierte en un DataValidator
    val isLongEnough = service.check("kotlin") { it.length > 5 }
    val containsA = service.check("java") { 'a' in it }

    println("¿\"kotlin\" tiene más de 5 caracteres? $isLongEnough")
    println("¿\"java\" contiene la letra 'a'? $containsA")
}
```

> [!tip] Salida por consola
> ```text
> Checking value: 'kotlin'
> Checking value: 'java'
> ¿"kotlin" tiene más de 5 caracteres? true
> ¿"java" contiene la letra 'a'? true
> ```

### Explicación paso a paso
1. `DataValidator` da nombre y significado al contrato "recibe un `String` y devuelve un `Boolean`".
2. `check` es un método normal que delega la decisión en el validador recibido.
3. Como `validator` es el último parámetro, cada lambda va como _trailing lambda_ y se convierte en un `DataValidator` (conversión SAM).
4. `"kotlin"` tiene 6 caracteres (> 5) y `"java"` contiene `'a'`, así que las dos validaciones devuelven `true`.

## Ejercicio 10.7 · testBoth con funciones anónimas

> [!question] Enunciado
> Define una función de orden superior llamada `testBoth`, que reciba dos enteros y una función de condición como parámetros. La función `testBoth` debe retornar un valor booleano que indique si ambos números cumplen con la condición especificada.
>
> Prueba la función llamándola dos veces desde el `main` con dos condiciones distintas pasadas como funciones anónimas.

### Clases y métodos introducidos
- **Función anónima**: `fun(number: Int): Boolean { … }`, una función sin nombre que se usa como valor.
- A diferencia de una lambda, permite indicar el tipo de retorno y su `return` sale solo de la función anónima.

> **Términos explicados:** [[10 - Programación funcional#8. Funciones anónimas|8. Funciones anónimas]]

### Código fuente (`Ejercicio10.7/src/Main.kt`)

```kotlin
fun testBoth(first: Int, second: Int, condition: (Int) -> Boolean): Boolean =
    condition(first) && condition(second)

fun main() {
    // Función anónima con cuerpo de bloque: el return solo sale de ella
    val bothEven = testBoth(4, 10, fun(number: Int): Boolean {
        return number % 2 == 0
    })
    println("¿4 y 10 son pares? $bothEven")

    // Función anónima de expresión única
    val bothInRange = testBoth(15, 30, fun(number: Int) = number in 1..20)
    println("¿15 y 30 están entre 1 y 20? $bothInRange")
}
```

> [!tip] Salida por consola
> ```text
> ¿4 y 10 son pares? true
> ¿15 y 30 están entre 1 y 20? false
> ```

### Explicación paso a paso
1. `testBoth` es la misma función que en el [[#Ejercicio 10.1 · Función de orden superior testBoth con lambdas|ejercicio 10.1]]; solo cambia cómo se le pasa la condición.
2. La primera función anónima tiene cuerpo de bloque y usa `return`, que **solo** sale de ella, no de `main`.
3. La segunda es de expresión única (`= number in 1..20`), y su tipo de retorno se infiere.
4. Las funciones anónimas no se pueden escribir como _trailing lambda_: tienen que ir dentro de los paréntesis.
5. `30` no está entre 1 y 20, así que la segunda llamada devuelve `false`.

## Ejercicio 10.8 · Closure sequenceGenerator

> [!question] Enunciado
> Define una función llamada sequenceGenerator que reciba un entero inicial y una función que determine cómo calcular el siguiente número en la secuencia. La función sequenceGenerator debe devolver otra función (un closure) que, cada vez que sea llamada, devuelva el siguiente número en la secuencia basado en el último número generado.
>
> Por ejemplo, si el número inicial es 5 y la función de cálculo suma 2 al número anterior, la secuencia sería 5, 7, 9, 11, etc. La función sequenceGenerator debe recordar el último número generado y continuar la secuencia cada vez que se llame al closure.
>
> Demuestra el uso de sequenceGenerator creando dos secuencias diferentes y mostrando algunos de los valores generados por cada una.

### Clases y métodos introducidos
- **_Closure_**: lambda que captura variables del ámbito donde se creó y las conserva entre llamadas.
- `() -> Int`: tipo de la función devuelta (no recibe nada y devuelve el siguiente número).

> **Términos explicados:** [[10 - Programación funcional#9. Closures|9. Closures]]

### Código fuente (`Ejercicio10.8/src/Main.kt`)

```kotlin
// Devuelve un closure: una función que recuerda nextValue entre llamadas
fun sequenceGenerator(start: Int, next: (Int) -> Int): () -> Int {
    var nextValue = start           // variable capturada por la lambda
    return {
        val result = nextValue
        nextValue = next(nextValue) // se modifica la variable capturada
        result
    }
}

fun main() {
    val plusTwo = sequenceGenerator(5) { it + 2 }
    val timesThree = sequenceGenerator(1) { it * 3 }

    print("Secuencia +2: ")
    for (i in 1..5) print("${plusTwo()} ")
    println()

    print("Secuencia x3: ")
    for (i in 1..5) print("${timesThree()} ")
    println()

    // Cada generador tiene su propio estado: plusTwo sigue por donde iba
    println("Siguiente de +2: ${plusTwo()}")
}
```

> [!tip] Salida por consola
> ```text
> Secuencia +2: 5 7 9 11 13 
> Secuencia x3: 1 3 9 27 81 
> Siguiente de +2: 15
> ```

### Explicación paso a paso
1. `nextValue` es una variable **local** de `sequenceGenerator`, pero la lambda devuelta la captura, así que sigue "viva" después de que la función termine.
2. Cada llamada a la lambda guarda el valor actual, calcula el siguiente con `next` y devuelve el guardado. Así, la primera llamada devuelve el número inicial.
3. Cada llamada a `sequenceGenerator` crea su **propia** variable `nextValue`, por eso `plusTwo` y `timesThree` no se mezclan.
4. Al llamar otra vez a `plusTwo()` al final, continúa donde se había quedado (`15`).
5. En Java esto no se podría hacer directamente, porque las variables capturadas por una lambda tienen que ser _effectively final_. En Kotlin, una `var` capturada sí se puede modificar.

## Ejercicio 10.9 · Referencias a función con applyOperation

> [!question] Enunciado
> Define una función genérica llamada `applyOperation` que reciba dos parámetros de tipo `Double` y una función que realice una operación matemática binaria sobre esos dos valores (por ejemplo, suma, resta, multiplicación, etc.). La función `applyOperation` debe devolver el resultado de aplicar la operación a los dos parámetros.
>
> Posteriormente, define varias funciones que implementen operaciones matemáticas básicas (suma, resta, multiplicación, división) y usa la función applyOperation pasándole estas funciones a través de referencias a método.
>
> Después, define varias funciones similares dentro del _companion object_ de un clase `Operations`, y llama a la función `applyOperation` usando dichas funciones.
>
> Después define varias funciones similares dentro de una clase `MyOperations`, instancia un objeto de dicha clase y llama a la función `applyOperation` usando las funciones de dicha instancia.

### Clases y métodos introducidos
- `::add`: referencia a una función _top-level_.
- `Operations::power`: referencia a una función del _companion object_ (se escribe con el nombre de la clase).
- `myOperations::scaledSum`: referencia **ligada** a una instancia (_bound reference_); el receptor ya va incluido.

> **Términos explicados:** [[10 - Programación funcional#10. Referencias a función|10. Referencias a función]]

### Código fuente (`Ejercicio10.9/src/Main.kt`)

```kotlin
// Recibe cualquier operación binaria sobre Double
fun applyOperation(a: Double, b: Double, operation: (Double, Double) -> Double): Double =
    operation(a, b)

// 1. Funciones top-level
fun add(a: Double, b: Double): Double = a + b
fun subtract(a: Double, b: Double): Double = a - b
fun multiply(a: Double, b: Double): Double = a * b
fun divide(a: Double, b: Double): Double = a / b

// 2. Funciones en el companion object
class Operations {
    companion object {
        fun power(a: Double, b: Double): Double = Math.pow(a, b)
        fun average(a: Double, b: Double): Double = (a + b) / 2
    }
}

// 3. Métodos de instancia
class MyOperations(private val factor: Double) {
    fun scaledSum(a: Double, b: Double): Double = (a + b) * factor
    fun maximum(a: Double, b: Double): Double = if (a > b) a else b
}

fun main() {
    println("Top-level:")
    println("  8 + 2 = ${applyOperation(8.0, 2.0, ::add)}")
    println("  8 - 2 = ${applyOperation(8.0, 2.0, ::subtract)}")
    println("  8 * 2 = ${applyOperation(8.0, 2.0, ::multiply)}")
    println("  8 / 2 = ${applyOperation(8.0, 2.0, ::divide)}")

    println("Companion object:")
    println("  8 ^ 2 = ${applyOperation(8.0, 2.0, Operations::power)}")
    println("  media(8, 2) = ${applyOperation(8.0, 2.0, Operations::average)}")

    println("Instancia de MyOperations:")
    val myOperations = MyOperations(10.0)
    println("  (8 + 2) * 10 = ${applyOperation(8.0, 2.0, myOperations::scaledSum)}")
    println("  max(8, 2) = ${applyOperation(8.0, 2.0, myOperations::maximum)}")
}
```

> [!tip] Salida por consola
> ```text
> Top-level:
>   8 + 2 = 10.0
>   8 - 2 = 6.0
>   8 * 2 = 16.0
>   8 / 2 = 4.0
> Companion object:
>   8 ^ 2 = 64.0
>   media(8, 2) = 5.0
> Instancia de MyOperations:
>   (8 + 2) * 10 = 100.0
>   max(8, 2) = 8.0
> ```

### Explicación paso a paso
1. El enunciado dice "función genérica", pero los parámetros son `Double`: se entiende "general" (sirve para cualquier operación). No necesita `<T>`.
2. Las cuatro funciones _top-level_ tienen la firma `(Double, Double) -> Double`, así que `::add`, `::subtract`… encajan en el parámetro `operation`.
3. Las del _companion object_ se referencian con `Operations::power`, igual que un método estático de Java (`Integer::sum`).
4. Para los métodos de instancia se crea `myOperations` y se usa `myOperations::scaledSum`. Como la referencia está ligada al objeto, su tipo sigue siendo `(Double, Double) -> Double` y además usa el `factor` de esa instancia.

## Ejercicio 10.10 · Inline function y non-local return

> [!question] Enunciado
> Define una **función _top-level_ `inline`** llamada `executeWithTimer` que reciba una _lambda_ `action: () -> Unit` como único parámetro. Dentro, debe imprimir "Starting timer...", ejecutar la `action()`, e imprimir "Timer finished."
>
> En la función `main`, haz lo siguiente:
>
> - Llama a `executeWithTimer` usando una _lambda_ donde:
>     - Se imprima "Inside Action 1"
>     - Se ejecute un **`return` simple** (Non-local return).
>     - Se imprima "This should not be printed."
> - Inmediatamente después de esta llamada, imprime: **"Main continues here."** (Observa si se ejecuta o no).
> - Llama a `executeWithTimer` por segunda vez, pero esta vez:
>     - Utiliza una **etiqueta de retorno** (`return@executeWithTimer`) para forzar un **retorno local** (simulando un `break` en una función normal).
>     - Imprime: "Inside Action 2"
> - Inmediatamente después de esta llamada, imprime: **"Main finished properly."**

> [!note] Por qué no está todo en `main`
> Si las dos llamadas estuvieran directamente en `main`, el `return` de la primera lambda **terminaría `main`** y la segunda llamada nunca se ejecutaría. Para poder ver los dos comportamientos, cada caso va en su propia función y `main` las llama una detrás de otra. Lo que en el enunciado se imprime "en `main`" pasa a imprimirse en esas funciones.

### Clases y métodos introducidos
- `inline fun`: el compilador copia el cuerpo de la función, y el de la lambda, en el lugar de la llamada.
- **_Non-local return_**: un `return` sin etiqueta dentro de la lambda sale de la función que la **escribe** (aquí `nonLocalReturnDemo`).
- `return@executeWithTimer`: retorno **local**, que solo termina la lambda.

> **Términos explicados:** [[10 - Programación funcional#11. Inline functions|11. Inline functions]]

### Código fuente (`Ejercicio10.10/src/Main.kt`)

```kotlin
inline fun executeWithTimer(action: () -> Unit) {
    println("Starting timer...")
    action()
    println("Timer finished.")
}

fun nonLocalReturnDemo() {
    executeWithTimer {
        println("Inside Action 1")
        return                                   // non-local return: sale de nonLocalReturnDemo()
        println("This should not be printed.")
    }
    println("Main continues here.")              // no se ejecuta
}

fun localReturnDemo() {
    executeWithTimer {
        println("Inside Action 2")
        return@executeWithTimer                  // retorno local: solo sale de la lambda
        println("This should not be printed either.")
    }
    println("Main finished properly.")           // sí se ejecuta
}

fun main() {
    nonLocalReturnDemo()
    println("-----")
    localReturnDemo()
}
```

> [!tip] Salida por consola
> ```text
> Starting timer...
> Inside Action 1
> -----
> Starting timer...
> Inside Action 2
> Timer finished.
> Main finished properly.
> ```

### Explicación paso a paso
1. En `nonLocalReturnDemo`, el `return` sale de toda la función: no se imprimen ni "This should not be printed." ni "Timer finished." (porque el resto de `executeWithTimer` también está "copiado" ahí), ni "Main continues here.".
2. Esto solo es posible porque `executeWithTimer` es `inline`. Con una función normal, un `return` sin etiqueta dentro de la lambda no compilaría.
3. En `localReturnDemo`, `return@executeWithTimer` termina solo la lambda: `executeWithTimer` sigue y escribe "Timer finished.", y después se imprime "Main finished properly.".
4. El IDE marca como _unreachable code_ los `println` que hay justo después de cada `return`: es un aviso, no un error, y se dejan porque el enunciado los pide.

## Ejercicio 10.11 · Funciones hacerCon con receptor

> [!question] Enunciado
> Realiza las siguientes funciones y pruébalas llamándolas proporcionando una lambda que retorne una cadena inversa a la "recibida":
>
> 1. Una función `hacerCon1` que no retorna nada, y recibe dos parámetros: una cadena y un parámetro de tipo función que no retorna nada y que recibe como argumento una cadena correspondiente a la cadena suministrada como parámetro anterior.
> 2. Una función `hacerCon2`, similar a la anterior, pero que después de ejecutar la lambda recibida, retorna la cadena recibida como argumento.
> 3. Una función `hacerCon3` similar a la anterior, pero que retorna una cadena, correspondiente a lo que retorne el literal de función pasado como argumento del parámetro de tipo función.
> 4. Una función `hacerCon4`, similar a `hacerCon2`, pero que corresponda a una _extension function_ sobre `String`, y que por tanto no la reciba como argumento, sino que se ejecute "sobre ella".
> 5. Una función `hacerCon5`, similar a `hacerCon3`, pero que corresponda a una _extension function_ sobre `String`, y que por tanto no la reciba como argumento, sino que se ejecute "sobre ella".
> 6. Una función `hacerCon6`, similar a `hacerCon4`, pero que funcione con cualquier tipo T en vez de solo con String.
> 7. Una función `hacerCon7`, similar a `hacerCon5`, pero que funcione con cualquier tipo T en vez de solo con String. El tipo de retorno también debe generalizarse a un tipo R.
> 8. Una función `hacerCon8`, similar a `hacerCon6`, pero en el que el parámetro sea tipo función con receptor.
> 9. Una función `hacerCon9`, similar a `hacerCon7`, pero en el que el parámetro sea tipo función con receptor.

### Clases y métodos introducidos
- `(String) -> Unit` frente a `String.() -> Unit`: en el primero la cadena llega como parámetro (`it`); en el segundo es el **receptor** (`this`, que se puede omitir).
- `fun <T> T.hacerCon6(…)`: _extension function_ genérica, que vale para un receptor de cualquier tipo.
- `reversed()`: devuelve la cadena al revés.

> **Términos explicados:** [[10 - Programación funcional#12. Literales de función con receptor (lambda with receiver)|12. Literales de función con receptor (lambda with receiver)]]

### Código fuente (`Ejercicio10.11/src/Main.kt`)

```kotlin
// 1. Recibe la cadena y una función que la usa sin devolver nada
fun hacerCon1(text: String, action: (String) -> Unit) {
    action(text)
}

// 2. Igual, pero devuelve la cadena recibida
fun hacerCon2(text: String, action: (String) -> Unit): String {
    action(text)
    return text
}

// 3. Devuelve lo que devuelva la función
fun hacerCon3(text: String, action: (String) -> String): String = action(text)

// 4. Como hacerCon2, pero como extension function de String
fun String.hacerCon4(action: (String) -> Unit): String {
    action(this)
    return this
}

// 5. Como hacerCon3, pero como extension function de String
fun String.hacerCon5(action: (String) -> String): String = action(this)

// 6. Como hacerCon4, pero para cualquier tipo T          (equivale a also)
fun <T> T.hacerCon6(action: (T) -> Unit): T {
    action(this)
    return this
}

// 7. Como hacerCon5, pero con T y un retorno genérico R   (equivale a let)
fun <T, R> T.hacerCon7(action: (T) -> R): R = action(this)

// 8. Como hacerCon6, pero con tipo función con receptor   (equivale a apply)
fun <T> T.hacerCon8(action: T.() -> Unit): T {
    action()          // se ejecuta sobre this: dentro de la lambda, this es el receptor
    return this
}

// 9. Como hacerCon7, pero con tipo función con receptor   (equivale a run)
fun <T, R> T.hacerCon9(action: T.() -> R): R = action()

fun main() {
    val word = "Kotlin"

    hacerCon1(word) { println("hacerCon1: ${it.reversed()}") }
    println("hacerCon2 devuelve: ${hacerCon2(word) { println("hacerCon2: ${it.reversed()}") }}")
    println("hacerCon3 devuelve: ${hacerCon3(word) { it.reversed() }}")
    println("hacerCon4 devuelve: ${word.hacerCon4 { println("hacerCon4: ${it.reversed()}") }}")
    println("hacerCon5 devuelve: ${word.hacerCon5 { it.reversed() }}")
    println("hacerCon6 devuelve: ${word.hacerCon6 { println("hacerCon6: ${it.reversed()}") }}")
    println("hacerCon7 devuelve: ${word.hacerCon7 { it.reversed() }}")
    println("hacerCon8 devuelve: ${word.hacerCon8 { println("hacerCon8: ${reversed()}") }}")
    println("hacerCon9 devuelve: ${word.hacerCon9 { reversed() }}")

    // Las versiones genéricas funcionan con cualquier tipo: aquí T = Int y R = String
    println("hacerCon7 con un Int: ${12345.hacerCon7 { it.toString().reversed() }}")
    println("hacerCon9 con un Int: ${12345.hacerCon9 { toString().reversed() }}")
}
```

> [!tip] Salida por consola
> ```text
> hacerCon1: niltoK
> hacerCon2: niltoK
> hacerCon2 devuelve: Kotlin
> hacerCon3 devuelve: niltoK
> hacerCon4: niltoK
> hacerCon4 devuelve: Kotlin
> hacerCon5 devuelve: niltoK
> hacerCon6: niltoK
> hacerCon6 devuelve: Kotlin
> hacerCon7 devuelve: niltoK
> hacerCon8: niltoK
> hacerCon8 devuelve: Kotlin
> hacerCon9 devuelve: niltoK
> hacerCon7 con un Int: 54321
> hacerCon9 con un Int: 54321
> ```

### Explicación paso a paso
1. Del 1 al 3, la cadena es un parámetro normal y cambia lo que se devuelve: nada, la cadena original o el resultado de la lambda.
2. El 4 y el 5 son lo mismo, pero como _extension function_ de `String`: se llaman con `word.hacerCon4 { … }` y dentro se usa `this`.
3. El 6 y el 7 generalizan a cualquier `T`; el 7 también generaliza el retorno a `R`. Por eso al final se prueban con un `Int` que devuelve un `String`.
4. El 8 y el 9 cambian `(T) -> …` por `T.() -> …`: en la lambda ya no se usa `it`, sino directamente `reversed()` sobre `this`.
5. Las cuatro últimas son exactamente las _scoping functions_ de la librería estándar (las que llevan un `≈` en la tabla de abajo).
6. Los nombres `hacerConN` están en español porque así los pide el enunciado.

| Función | Parámetro | Devuelve | Equivale a |
| --- | --- | --- | --- |
| `hacerCon1` | `(String) -> Unit` | nada | — |
| `hacerCon2` | `(String) -> Unit` | la cadena | — |
| `hacerCon3` | `(String) -> String` | resultado de la lambda | — |
| `String.hacerCon4` | `(String) -> Unit` | la cadena | — |
| `String.hacerCon5` | `(String) -> String` | resultado de la lambda | — |
| `T.hacerCon6` | `(T) -> Unit` | el receptor `T` | ≈ `also` |
| `T.hacerCon7` | `(T) -> R` | `R` | ≈ `let` |
| `T.hacerCon8` | `T.() -> Unit` | el receptor `T` | ≈ `apply` |
| `T.hacerCon9` | `T.() -> R` | `R` | ≈ `run` |

## Ejercicio 10.12 · Scoping functions sobre Order

> [!question] Enunciado
> Define la siguiente `data class`:
>
> ```kotlin
> data class Order(
>     val id: Int,
>     var status: String = "PENDING",
>     var processingTimeMs: Long = 0
> )
> ```
>
> En la función `main`, sigue el siguiente flujo de trabajo:
>
> - Crea un objeto `Order` con `id = 42`.
> - Utiliza `apply` para establecer su `status` inicial en `"CREATED"` y guardarlo en una variable inmutable `baseOrder`.
> - Ejecuta `baseOrder.also` y usa la _lambda_ para imprimir un mensaje de log: "LOG: Order $it.id created with status $it.status."
> - Crea una variable `nullableOrder` que sea `null`.
> - Utiliza el operador `?.let` sobre `nullableOrder` para intentar imprimir un mensaje. Si es nulo, el bloque `let` debe devolver la cadena `"No order processed."` (Usa el Elvis operator `?:`). Imprime el resultado.
> - Usa `with` sobre `baseOrder` y dentro de la _lambda_:
>     - Establece `processingTimeMs` a `250`.
>     - Retorna el nuevo estado de la orden (p. ej., la cadena `"PROCESSING"`).
> - Almacena el valor de retorno en una variable `newStatus`.
> - Imprime `baseOrder` y `newStatus`.
> - Llama a `baseOrder.run` y úsalo para calcular y devolver una `String` final que resuma el estado y el tiempo de procesamiento.
> - La cadena debe ser: "SUMMARY: Order $this.id is $this.status and took $this.processingTimeMs ms."
> - Imprime el resultado de `run`.

> [!warning] Ojo con las plantillas del enunciado
> En una plantilla, `$it.id` **no** accede a `id`: `$it` se sustituye por el objeto entero y `.id` se queda como texto. Comprobado con `kotlinc`, imprime `LOG: Order Order(id=42, status=PENDING).id created…`. Para acceder a una propiedad hay que usar llaves: `${it.id}`. Lo mismo pasa con `$this.id`; dentro de `run` basta con `$id`, porque `this` está implícito.

### Clases y métodos introducidos
- `apply` (`this`, devuelve el objeto) · `also` (`it`, devuelve el objeto) · `let` (`it`, devuelve el resultado) · `with` y `run` (`this`, devuelven el resultado).
- `?.let { … } ?: valor`: si el objeto es `null`, la lambda no se ejecuta y se usa el valor de la derecha del Elvis.

> **Términos explicados:** [[10 - Programación funcional#13. Scoping functions (with, run, apply, let, also)|13. Scoping functions (with, run, apply, let, also)]]

### Código fuente (`Ejercicio10.12/src/Main.kt`)

```kotlin
data class Order(
    val id: Int,
    var status: String = "PENDING",
    var processingTimeMs: Long = 0,
)

fun main() {
    // apply: configura el objeto (this) y devuelve el propio objeto
    val baseOrder = Order(id = 42).apply {
        status = "CREATED"
    }

    // also: efecto secundario (log) con it; devuelve el objeto sin cambiarlo
    baseOrder.also {
        println("LOG: Order ${it.id} created with status ${it.status}.")
    }

    // ?.let + Elvis: si es null, la lambda no se ejecuta y se usa el valor de la derecha
    val nullableOrder: Order? = null
    val letResult = nullableOrder?.let { "Processing order ${it.id}." } ?: "No order processed."
    println(letResult)

    // with: trabaja sobre el objeto (this) y devuelve el resultado de la lambda
    val newStatus = with(baseOrder) {
        processingTimeMs = 250
        status = "PROCESSING"
        status                       // último valor = lo que devuelve with
    }
    println(baseOrder)
    println("newStatus = $newStatus")

    // run: igual que with, pero como extension function
    val summary = baseOrder.run {
        "SUMMARY: Order $id is $status and took $processingTimeMs ms."
    }
    println(summary)
}
```

> [!tip] Salida por consola
> ```text
> LOG: Order 42 created with status CREATED.
> No order processed.
> Order(id=42, status=PROCESSING, processingTimeMs=250)
> newStatus = PROCESSING
> SUMMARY: Order 42 is PROCESSING and took 250 ms.
> ```

### Explicación paso a paso
1. `Order(id = 42).apply { status = "CREATED" }` crea el pedido, lo configura y lo devuelve, así que se puede guardar directamente en `baseOrder`.
2. `also` se usa para un efecto secundario (el log): devuelve el mismo objeto sin tocarlo.
3. `nullableOrder?.let { … }` no ejecuta la lambda porque el pedido es `null`; la expresión vale `null` y el Elvis da `"No order processed."`.
4. Dentro de `with(baseOrder)`, `processingTimeMs` y `status` se refieren a las propiedades de `baseOrder`. El enunciado dice "retorna el nuevo estado", así que se asigna `"PROCESSING"` y se devuelve: el último valor de la lambda es lo que devuelve `with`.
5. `run` hace lo mismo que `with`, pero se llama sobre el objeto (`baseOrder.run { … }`); se usa para construir el resumen.

## Esquema resumen de conceptos clave

| Concepto | Sintaxis | Comportamiento |
| --- | --- | --- |
| Función de orden superior | `fun testBoth(a: Int, b: Int, condition: (Int) -> Boolean)` | Recibe una función como parámetro (10.1, 10.7). |
| Varianza de tipos función | `(Email) -> Message` acepta `(Message) -> SMS` | Parámetro más general y retorno más concreto (10.2). |
| `typealias` y función que devuelve función | `typealias MathOperation = …` · `: (Double) -> String` | Alias legible; la función devuelta captura sus parámetros (10.3). |
| Lambdas concisas | `forEach { it… }` · `filter { (_, price) -> … }` | _Trailing lambda_, `it` y desestructuración (10.4). |
| Conversión SAM | `fun interface DelayedTask` | Una lambda se convierte en la interfaz (10.5, 10.6). |
| Función anónima | `fun(number: Int): Boolean { return … }` | `return` local; va dentro de los paréntesis (10.7). |
| _Closure_ | `var nextValue = start; return { … }` | Conserva estado entre llamadas (10.8). |
| Referencias | `::add` · `Operations::power` · `obj::scaledSum` | Funciones existentes como argumentos (10.9). |
| `inline` y _non-local return_ | `return` · `return@executeWithTimer` | Salir de la función exterior o solo de la lambda (10.10). |
| Función con receptor | `T.() -> R` | `this` dentro de la lambda; base de `apply` y `run` (10.11). |
| _Scoping functions_ | `apply` · `also` · `let` · `with` · `run` | Elegir por `this`/`it` y por lo que devuelven (10.12). |
